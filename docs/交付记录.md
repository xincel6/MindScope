## 2026-10-14 · 数据层、启动引导与类型共享

> 提交：`20409fa`（数据层）｜ 范围：`harmony/`（从零建立数据层）+ `docs/`

### 目标

- 在 Ability 生命周期最开始取数并启动存储，**不含任何 UI**。
- 共享类型可同时被 TS / ArkTS 使用；类型收拢到统一目录；基础类以 `base...` 命名。
- 产出《鸿蒙端数据获取使用指南》，让后续写 UI 的人只读 `AppStore`。

### 交付

- `types/`（enums / dto / model / constant / mapper / storeState / Index）、`network/`、`persistence/`（RDB + preferences）、`store/`（含 `AppStore` 门面）、`common/AppBootstrap`。
- 启动时序：`StorageManager.init → ApiConfig.load → 冷启动预热 → AuthStore.restore → 并发拉取 → 离线 / 未登录兜底`。
- 14 条接口清单落地；`AppStore` 字段 / 方法全表与 4 个页面示例。

### 验证

- `assembleHap` → **BUILD SUCCESSFUL**，0 error / 0 warning；HAP 514 KB。
- 未做真机 / 模拟器测试（本轮明确不要求）；RDB 只过编译、未跑真库。

### 决策 / 缺陷

- `.ts` 放纯类型 / 纯常量（可被 Web import），`.ets` 放 ArkTS 专有内容；`dto.ts` 是唯一允许 `snake_case` 的文件。
- 修掉 64 个编译期问题（静态字段与方法同名、惰性单例类型收窄、`Record` 存 null、装饰器约束等）。

### 遗留

- `POST /api/analyze`（空壳）与 `/api/analyze/face` 未封装。
- RDB 的 DDL / 分页 / batchInsert 需真机联调确认。
