4. **不改服务端类型**（`dashboard/backend/schemas.py` 保持原样）。
5. 代码风格**严格驼峰**；类中**对外暴露的接口尽量集中**，便于阅读。

## 三、已确认的决策（用户已拍板，不要再问）

### 3.1 数据持久化：**方案 A · 混合**

| 层 | 技术 | 存什么 |
|---|---|---|
| 配置/令牌层 | `preferences`（`@kit.ArkData`） | JWT 令牌、服务端 host/port、轻量偏好 |
| 业务数据层 | `relationalStore`（客户端 RDB / SQLite） | `media_asset`、`diagnosis_report` 两张**镜像表**，与服务端 SQLite 同构 |
| UI 数据源 | 内存 `@ObservedV2 + @Trace` store | UI **唯一**读数的来源；落盘只做冷启动预热与离线兜底 |

**选它的理由（已向用户说明并获同意）**：
- 服务端本身就是 SQLite 关系库，客户端用 RDB 是**同构镜像**，schema 一一对应、最不易漂移；
- 服务端 `/api/reports` 自带 `severity` / `media_type` / `page` / `limit` 过滤分页，RDB 能 1:1 承接，`preferences`/JSON 文件只能整包替换；
- 离线（答辩现场网络抖动）时仍可查询、翻页；
- 代价：代码量最大（建表 + DAO + 版本迁移约 300 行），且本轮只能编译校验、无法真机跑 SQL。

### 4.3 必须写进代码的坑

1. **`MediaItemOut.id` 是字符串，`ReportListItem.media_id` 是数字** —— 混用会让列表选中/删除静默失效。要在 `mapper` 层统一归一化。
2. **`/api/upload/image` 响应不完整**（缺 `thumbnail_url` / `duration` / `created_at`），客户端要自己补，`created_at` 按 `%Y-%m-%d` 拼，**不要用 `toISOString()`**（带时区偏移）。
3. **`/api/analyze` 是空壳**，别指望它触发分析。
4. **不存在登出接口**，登出 = 客户端删 token。也没有改密码 / 删报告 / 媒体分页。
5. **JWT HS256，有效期 7 天，无 refresh** → 401 必须全局处理成"踢回登录页"。
6. **WS 的 token 只能放 query**；无效 token 服务端 `close(1008)`。
7. **WS 帧消息没有 `type` 字段**，分流判据是 `msg.type === undefined`。
8. **`done` 之后服务端主动 close**，必须用 `analysisFinished` 标志区分"正常收尾"与"真断线"，否则误触发重连。
9. **注册/登录成功响应里没有用户信息**，必须再调 `/api/auth/me`。
10. **422 时 `detail` 是数组**，不是字符串，ArkTS 里必须显式判断，不能直接 `as {detail:string}`。

### 4.4 错误码表

| HTTP | detail | 触发 |
|---|---|---|
| 400 | 用户名需 3–32 位，仅支持字母、数字、下划线或中文 | 不匹配 `^[a-zA-Z0-9_\u4e00-\u9fa5]{3,32}$` |
| 400 | 密码至少 6 位 | 注册密码 < 6 |
| 400 | 用户名已存在 | 重名 |
| 400 | 邮箱已被注册 | 邮箱重复 |
| 401 | 用户名或密码错误 | 登录失败（不区分用户不存在/密码错） |
| 403 | 账号已禁用 | `is_active=false` |
| 422 | `detail` 是**数组** | Pydantic 校验失败 |

## 五、命名与类型规范（用户硬性要求，必须执行）

### 5.1 驼峰 vs 服务端 snake_case —— 用**两层类型**化解

用户要求「严格驼峰」，用户又要求「不改服务端类型」。二者靠**分层**同时满足：

```
types/dto.ts     wire DTO —— 字段名保持 snake_case，与服务端 1:1，零漂移
                     ↓  mapper.ts 显式转换（每个字段手写，不用对象展开）
types/model.ts   领域模型 —— 字段名全部 camelCase，UI 层只认这一层
```

- **只有 `dto.ts` 允许出现 snake_case**，且**仅限字段名**；类型名、函数名、变量名一律驼峰。
- 这样服务端将来改字段，只需改 `dto.ts` + `mapper.ts`，UI 层完全不动。

### 5.2 `.ts` / `.ets` 划分规则

| 后缀 | 判定标准 | 本轮放什么 |
|---|---|---|
| `.ts` | 纯类型 + 纯常量；**同时是合法 TS 与合法 ArkTS**，可被 Web 端直接 import | `dto.ts` / `model.ts` / `enums.ts` / `constant.ts` / `mapper.ts` |
| `.ets` | 用了 ArkTS 专有能力（装饰器 `@ObservedV2`/`@Trace`、ArkUI 类型） | `types/storeState.ets`（响应式状态类型） |

> 依据：官方约束 `arkts-no-ts-deps` —— `.ets` 可以 import `.ts`，**反向不行**。
> 所以共享类型**必须**是 `.ts`。

### 5.3 `base...` 基础类

- `store/BaseStore.ets` —— 抽象基础类：`loading` / `errorMsg` / `lastSyncAt` / `refresh()` / `clear()`。
- `persistence/BaseDao.ets` —— 抽象基础类：`insertOrReplace` / `queryAll` / `deleteAll` / `count`。
- 子类命名 `XxxStore` / `XxxDao`（`AuthStore` / `MediaDao` ...）。

### 5.4 暴露接口集中原则

每个类**顶部集中声明 public 成员**，private 实现全部下压；`types/Index.ts` 作为**唯一对外出口**做统一 re-export（用显式具名导出，不用 `export *`，避免 ArkTS 歧义）。

### 启动时序（本轮核心）

```
EntryAbility.onCreate
  └─ AppBootstrap.start(context)            ← 不 await 阻塞 UI 线程，内部自管
       ① StorageManager.init(context)       preferences + RDB 建表
       ② ApiConfig.load(context)            读回 host/port/token
       ③ 冷启动预热：从 RDB 把上次快照灌进内存 store（UI 立刻有数据）
       ④ 若 token 非空 → AuthApi.me() 校验
       ⑤ 校验通过 → 并发拉取 media / reports / stats，写内存 store + 回写 RDB
       ⑥ 失败/无 token → store 标记未登录或离线，UI 照常渲染（不崩、不白屏）
```

`onCreate` 里**不能 await 长任务**（会拖慢首帧），所以 `AppBootstrap.start()` 返回 `void`，内部用 `Promise` 自跑，并暴露 `AppBootstrap.ready: Promise<void>` 供 UI 侧按需等待。
