# 鸿蒙端网络层 & ArkTS/TS 类型共享方案

> 结论先行：
> 1. **要写一个 WebSocket 封装类，但它的定位不是"存储数据"** —— 它是"一条短命的长连接管理器"（建连/心跳/重连/消息分发）。视频/图片**不走 WebSocket**，先 HTTP 上传拿 `media_id`，再用 WS 触发服务端分析并接收回推的分数/人脸/热力图。
> 2. **ArkTS 与 TS 的类型可以做到"物理上同一份文件、零漂移"** —— 因为 ArkTS 是 TS 的子集，把共享类型写成 **ArkTS 安全子集的 `.ts` 文件**，Vue 和 HarmonyOS 两边直接 `import` 同一份即可。关键是扩展名必须是 `.ts`（ArkTS 规则 `arkts-no-ts-deps`：`.ets` 可以 import `.ts`，反向不行）。
>
> 所有协议细节均以本仓库 `backend/` 源码为准，行号可查。

## 一、WebSocket 类：要写，但先纠正三个认知

### 1.1 认知纠正

| 你可能的直觉 | 代码事实 | 证据 |
|---|---|---|
| WebSocket 用来"存储数据" | WS 只做**传输通道**；数据存储是 ArkTS 侧的 store（`@ObservedV2 + @Trace` / `AppStorage`） | — |
| 客户端把视频帧/二进制推给服务器 | **不存在任何二进制/帧上传通道**。WS 只接收 3 种**文本**消息：`{"id":"<media_id>"}`、`{"type":"cancel"}`、`{"type":"ping"}` | `routers/ws.py:60-62,128-134` |
| "25fps 实时流式推理" | 服务端 `await process_media(...)` **把整个文件先算完**，之后才进入取帧循环 → 客户端看到的是**突发批量**回推 | `routers/ws.py:97-113`；`services/frame_processor.py:124-141` |
| 连接是常驻的 | 一次分析 = 一条**短命连接**。服务端发完 `done` 后**主动 close** | `routers/ws.py:169-173` |

论文/技术文档里"前端以 25fps 捕获并转 Blob 投递后端"的表述，与代码不符。**照论文实现会做出后端接不上的客户端。**

### 1.2 真实交互时序（HarmonyOS 端要实现的就是这个）

```
① HTTP  POST /api/upload/image       multipart，字段名必须是 file
   → { id, name, type, url }                     ← 拿到 media_id（服务端返回字符串）

② WS    ws://<host>:8000/ws/analysis?token=<JWT>
        ★ token 只能放 query 参数，不能放 header（服务端 ws.query_params.get("token")）

   ⏱ 服务端 accept 后只等 15 秒：15s 内没收到 {"id":...} 就 error + close
   → 客户端必须在 on('open') 里立刻发 {"id":"<media_id>"}

③ ◀ {"type":"status","message":"analysis_started","task_id":"<id>"}

④ ◀ AnalysisFrame × N   ★★ 帧消息里【没有 type 字段】
   { frame_id, timestamp, bdi_score, aligned_face, heatmap_data[16][16],
     inference_time_ms, progress }
   （Vue 端 useWebSocket.ts 把这堆统一交给 onMessage(data:any)，所以 Web 端没暴露这个问题；
     ArkTS 去掉 any 之后，你必须靠"type === undefined"来判定它是帧）

⑤ ◀ {"type":"vlm_analysis","content":"【…】…"}   可能没有（VLM 失败静默跳过）
⑥ ◀ {"type":"done","final_score":18.42}
⑦ 服务端 close（正常收尾）
```

错误消息：`{"type":"error","message":"..."}`（未收到 media_id / 素材不存在 / 文件不存在 / 推理异常）。

### 1.3 五个必须写进代码的边界条件

1. **帧无 `type` 字段** → 分流判据是 `msg.type === undefined`，不是 `msg.type === 'frame'`。
2. **`done` 之后服务端主动 close** → `on('close')` 在"正常完成"和"真断线"两种场景都会触发。必须用 `analysisFinished` 标志区分，否则会误报"连接已断开"并触发无谓重连。
3. **ping 不回复** → 服务端在帧循环里用 `asyncio.wait_for(..., timeout=0.01)` 消费消息，只识别 `cancel`，其余丢弃。**不能靠"等 pong"判活**，判活只能用 `close`/`error` 事件 + `GET_NETWORK_INFO`。
4. **`cancel` 对视频基本无效** → 处理早在 15s 前就 `await` 完了；取消只在帧循环期间有意义。UI 上不要承诺"可中断"。
5. **断线重连 ≠ 断点续传** → 重连后重发 `{"id"}` 会让服务端**从头再跑一遍完整分析**（`process_media` 重新执行）。所以：空闲态断线才自动重连；分析中重连必须提示用户"将重新分析"。

另外两条环境坑（详见总报告 8.4）：
- ~~后端默认 `127.0.0.1:8000`（`serve_all.py`），必须改成局域网 IP 才能被手机访问~~ → **已解决**：服务端已部署并监听 `0.0.0.0:8000`（systemd 用户服务 `mindscope.service`）。鸿蒙端默认地址已在 `ApiConfig.ets` 中烧成服务器地址（Tailscale `100.122.178.113:8000`，局域网备选 `192.168.0.123:8000`）。
- `http://` / `ws://` 都是明文，HarmonyOS 默认拦截 → **已配好**：`module.json5` 的 `metadata` 已挂 `resources/base/profile/network_config.json`（`cleartextTrafficPermitted: true`）。**这一步没做对，表现是"所有请求静默失败"。**

### 1.4 `AnalysisSocket.ets` 骨架（可直接落盘改）

> 说明：下面的写法已按 ArkTS 约束调整过——没有 `any`、没有对象展开、回调不用"带方法的对象字面量"、定时器句柄是 `number`（不是 `ReturnType<typeof setInterval>`）。API 签名以本机 SDK 的 `@ohos.net.webSocket.d.ts` 为准。

```ts
// entry/src/main/ets/network/AnalysisSocket.ets
import { webSocket } from '@kit.NetworkKit';
import { BusinessError } from '@kit.BasicServicesKit';
import { AnalysisFrame, WsInbound } from '../model/WsModel';   // ← 共享 .ts
import { ApiConfig } from '../common/ApiConfig';
import { Logger } from '../common/Logger';

export enum SocketState { IDLE, CONNECTING, OPEN, CLOSING, CLOSED }   // 不用字符串字面量联合

/** 回调用抽象类：ArkTS 不允许用对象字面量初始化"带方法的接口" */
export abstract class AnalysisListener {
  onFrame(frame: AnalysisFrame): void {}
  onStatus(taskId: string): void {}
  onVlm(text: string): void {}
  onDone(score: number): void {}
  onError(msg: string): void {}
  onStateChanged(state: SocketState): void {}
}

/** 出站消息用带参构造的 class（对象字面量不能初始化带参构造的类） */
class StartMsg {
  public id: string;
  constructor(id: string) { this.id = id; }
}
class TypeMsg {
  public type: string;
  constructor(type: string) { this.type = type; }
}

export class AnalysisSocket {
  private ws: webSocket.WebSocket | null = null;
  private state: SocketState = SocketState.IDLE;
  private listener: AnalysisListener;
  private mediaId: string = '';
  private hbTimer: number = -1;
  private reconnectTimer: number = -1;
  private reconnectCount: number = 0;
  private readonly maxReconnect: number = 5;
  private manualClosed: boolean = false;
  private analysisFinished: boolean = false;

  constructor(listener: AnalysisListener) { this.listener = listener; }

  /** 每次分析开一条新连接 */
  start(mediaId: string): void {
    this.mediaId = mediaId;
    this.manualClosed = false;
    this.analysisFinished = false;
    this.reconnectCount = 0;
    this.openSocket();
  }

  private openSocket(): void {
    this.teardown();
    this.setState(SocketState.CONNECTING);
    const ws = webSocket.createWebSocket();
    this.ws = ws;

    ws.on('open', () => {
      this.setState(SocketState.OPEN);
      this.reconnectCount = 0;
      this.sendRaw(JSON.stringify(new StartMsg(this.mediaId)));  // ★ 15 秒内必须发出
      this.startHeartbeat();
    });

    ws.on('message', (err: BusinessError, value: string | ArrayBuffer) => {
      if (typeof value !== 'string') { return; }   // 服务端全部是文本消息
      this.dispatch(value);
    });

    ws.on('close', (err: BusinessError, value: webSocket.CloseResult) => {
      this.stopHeartbeat();
      this.setState(SocketState.CLOSED);
      if (this.manualClosed || this.analysisFinished) { return; }  // ★ 正常收尾，不重连
      this.scheduleReconnect();
    });

    ws.on('error', (err: BusinessError) => {
      Logger.e('ws error: ' + JSON.stringify(err));
      this.stopHeartbeat();
      this.setState(SocketState.CLOSED);
      if (!this.manualClosed && !this.analysisFinished) { this.scheduleReconnect(); }
    });

    ws.connect(ApiConfig.wsUrl(ApiConfig.token)).catch((e: BusinessError) => {
      Logger.e('ws connect fail: ' + JSON.stringify(e));
      this.setState(SocketState.CLOSED);
      if (!this.manualClosed) { this.scheduleReconnect(); }
    });
  }

  /** 唯一的分流入口 */
  private dispatch(text: string): void {
    let msg: WsInbound;
    try {
      msg = JSON.parse(text) as WsInbound;      // ★ 只能 as 成 interface，不能 as 成 class
    } catch (e) {
      return;
    }
    const type: string | undefined = msg.type;
    if (type === undefined || type === '') {
      this.listener.onFrame(this.toFrame(msg));  // ★ 帧消息没有 type
      return;
    }
    if (type === 'status')       { this.listener.onStatus(msg.task_id ?? ''); return; }
    if (type === 'vlm_analysis') { this.listener.onVlm(msg.content ?? '');    return; }
    if (type === 'done') {
      this.analysisFinished = true;              // 服务端随后会 close
      this.listener.onDone(msg.final_score ?? 0);
      return;
    }
    if (type === 'error') {
      this.analysisFinished = true;
      this.listener.onError(msg.message ?? 'unknown error');
      return;
    }
    // 未知类型忽略（服务端不推 pong）
  }

  /** ArkTS 没有对象展开，逐字段显式拷贝（有明确类型标注的字面量是合法的） */
  private toFrame(m: WsInbound): AnalysisFrame {
    const frame: AnalysisFrame = {
      frame_id: m.frame_id ?? 0,
      timestamp: m.timestamp ?? 0,
      bdi_score: m.bdi_score ?? 0,
      aligned_face: m.aligned_face ?? '',
      heatmap_data: m.heatmap_data ?? [],
      inference_time_ms: m.inference_time_ms ?? 0,
      progress: m.progress ?? 0
    };
    return frame;
  }

  /** 仅心跳用途；服务端不回复，不可作为判活依据 */
  private startHeartbeat(): void {
    this.stopHeartbeat();
    this.hbTimer = setInterval(() => {
      this.sendRaw(JSON.stringify(new TypeMsg('ping')));
    }, 30000);
  }

  private stopHeartbeat(): void {
    if (this.hbTimer !== -1) { clearInterval(this.hbTimer); this.hbTimer = -1; }
  }

  /** 分析中重连 = 服务端重新跑一遍完整分析，UI 必须提示 */
  private scheduleReconnect(): void {
    if (this.reconnectCount >= this.maxReconnect) {
      this.listener.onError('重连失败，请检查服务端地址与网络');
      return;
    }
    const delay: number = Math.min(1000 * Math.pow(2, this.reconnectCount), 16000);
    this.reconnectCount++;
    this.reconnectTimer = setTimeout(() => { this.openSocket(); }, delay);
  }

  /** 只在服务端帧循环期间有效；视频场景基本无效 */
  cancel(): void { this.sendRaw(JSON.stringify(new TypeMsg('cancel'))); }

  stop(): void {
    this.manualClosed = true;
    this.stopHeartbeat();
    if (this.reconnectTimer !== -1) { clearTimeout(this.reconnectTimer); this.reconnectTimer = -1; }
    this.teardown();
    this.setState(SocketState.CLOSED);
  }

  private teardown(): void {
    const ws = this.ws;
    if (ws === null) { return; }
    ws.off('open'); ws.off('message'); ws.off('close'); ws.off('error');
    ws.close().catch((e: BusinessError) => {});
    this.ws = null;
  }

  private sendRaw(text: string): void {
    const ws = this.ws;
    if (ws === null || this.state !== SocketState.OPEN) { return; }
    ws.send(text).catch((e: BusinessError) => { Logger.e('ws send fail: ' + JSON.stringify(e)); });
  }

  private setState(s: SocketState): void {
    this.state = s;
    this.listener.onStateChanged(s);
  }
}
```

### 1.5 数据"存储"放哪里

Socket 类**不要**持有业务状态。ArkTS 的响应式只认装饰器，普通 class 的字段变化**不会**刷新 UI：

```ts
// store/DashboardStore.ets
@ObservedV2
export class DashboardStore {
  @Trace analyzing: boolean = false;
  @Trace bdiScore: number = 0;
  @Trace progress: number = 0;
  @Trace wsState: SocketState = SocketState.IDLE;
  @Trace faces: FaceFrameSnapshot[] = [];
  @Trace heatmap: number[][] = [];

  private static inst: DashboardStore | null = null;
  static get(): DashboardStore {
    if (DashboardStore.inst === null) { DashboardStore.inst = new DashboardStore(); }
    return DashboardStore.inst;
  }
}

// 页面里：listener.onFrame 里只写 store，UI 自动刷新
// 注意：批量到达的帧不要"每帧刷一次图表"，攒批重绘（见 10.4 节：progress 会从 0 直接跳到 1）
```

生命周期：页面 `aboutToDisappear()` / `onPageHide()` 里调 `socket.stop()`，避免连接泄漏。

## 二、ArkTS 类型 ↔ TS 类型一致

### 2.1 机制：一份 `.ts`，两边 import（这是唯一"零漂移"的做法）

官方约束原文（`arkts-no-ts-deps`）：

> `.ets` 文件可以 `import` `.ets`/`.ts`/`.js` 文件源码，但是 `.ts`/`.js` 文件不允许 `import` `.ets` 文件源码。

推论出两条硬规则：

1. **共享文件必须是 `.ts`，不能是 `.ets`**（否则 Vue 侧 import 不了，且 `.ets` 不能被 `.ts` import）。
2. 共享文件只放**纯类型 + 纯常量**（`interface` / `enum` / `const`），没有运行时代码 → 两边编译都无成本。

并且官方明确说明：

> 按本文约束进行代码重构后，代码仍为合法有效的 TS 代码。

→ 只要共享文件用"ArkTS 安全子集"的写法，**它同时是合法 TS 与合法 ArkTS**。不需要 codegen、不需要手工同步。

### 2.2 目录落地

```
大挑项目/
├── shared/                                  ← 唯一真源（ArkTS 子集写法的 .ts）
│   ├── enums.ts          ← SeverityLevel / MediaType
│   ├── model.ts          ← MediaItem / AnalysisFrame / ReportListItem / StatsData / WsInbound
│   └── constants.ts      ← 阈值 13/19/28、中文标签、颜色、干预建议
├── 系统代码/src/api/index.ts                 ← 改成 re-export：export * from '../../../shared/model'
└── DepressionHarmonyOS/entry/src/main/ets/model/   ← 同一份文件
```

Windows 下把 `shared/` 挂进 DevEco 工程，二选一：
- **目录联接（开发期最省事）**：`mklink /J "…\ets\model" "E:\大挑项目\shared"`
- **脚本同步（交付/换机器最稳）**：`sync-shared.bat` 里 `robocopy "E:\大挑项目\shared" "…\ets\model" /MIR`，并在文档里写清"改完 shared 必须跑一次"。

> 答辩场景建议再加一层"机器校验"：后端 FastAPI 自带 `/openapi.json`（`backend/main.py:23` 未关闭），写个 30 行脚本把 OpenAPI 的字段名/类型与 `shared/model.ts` 对比，漂移就报错。**生成代码不如校验漂移**——因为自动生成的 TS 经常不符合 ArkTS 子集。

### 2.3 必须改造的语法清单（★ 直接对应你现有代码）

| # | 你现在的 TS 写法 | ArkTS 约束 | ArkTS 写法 |
|---|---|---|---|
| 1 | `onMessage: (data: any) => void`<br>`useWebSocket.ts:5` | `arkts-no-any-unknown` | 定义 `WsInbound` 具体 interface；实在要动态用 `Object` + `instanceof` |
| 2 | `type SeverityLevel = 'none'\|'mild'\|'moderate'\|'severe'`<br>`stores/dashboard.ts:16` | 不支持字面量类型 / `as const`（`arkts-no-as-const`） | `enum SeverityLevel { none='none', mild='mild', moderate='moderate', severe='severe' }` |
| 3 | `type: 'image' \| 'video'`<br>`api/index.ts:4` | 同上 | `enum MediaType { image='image', video='video' }` |
| 4 | `ReturnType<typeof setInterval>`<br>`useWebSocket.ts:17` | `arkts-no-utility-types`：**只支持 `Partial`/`Required`/`Readonly`/`Record`** | `number` |
| 5 | `Pick<X,'a'>` / `Omit<X,'a'>` / `Exclude` / `Parameters` | 同上 | 手写一个新 interface（ArkTS 没有类型体操） |
| 6 | `interface M { [k: string]: number }` | `arkts-no-indexed-signatures` | `Record<string, number>`（注意取值类型含 `undefined`） |
| 7 | `type A = B & C` | `arkts-no-intersection-types` | `interface A extends B, C {}` |
| 8 | `{...state, x: 1}` 对象展开 | `arkts-no-spread`（只支持数组展开） | 显式构造函数 / 逐字段赋值 |
| 9 | `obj[field]` 动态取属性、给对象加新字段 | `arkts-no-props-by-index` + 对象布局不可变 | `Map<string, T>`；或类里显式声明全部字段 |
| 10 | 两个同形状 interface 互相赋值 | `arkts-no-structural-typing`（**不支持结构化类型**） | 只能是**同一个** interface；别名 `type I2 = I1` 或 `extends`；class 必须 `implements` |
| 11 | `@ts-ignore` / `@ts-nocheck` | `arkts-strict-typing-required` | 不允许，改代码 |
| 12 | `let n: number = null` | 强制开启 `strictNullChecks` 等 | `number \| null` |
| 13 | `/【(.+?)】/` 正则字面量（VlmParser 会用到） | `arkts-no-regexp-literals` | `new RegExp('【([\\s\\S]*?)】', 'g')` |
| 14 | `Object.assign(a, b)` / `Object.freeze` / `hasOwnProperty` | `arkts-limited-stdlib` | 逐字段赋值（`Object.keys/entries` 仍可用） |
| 15 | 同名 `interface` 分两处声明合并 | `arkts-no-decl-merging` | 合并到一处 |
| 16 | `{ onMessage: cb }` 传给带方法/函数成员的接口 | `arkts-no-untyped-obj-literals`（不支持字面量初始化"带方法的接口/带参构造的类"） | 抽象类回调（见 1.4）或 `new` 一个类实例 |
| 17 | 泛型省略实参、只靠返回值推断 | `arkts-no-inferred-generic-params` | 显式写 `f<MyType>(...)` |

### 2.4 ★ 最深的一条坑：`as` 是编译期断言，不做运行时转换

```ts
// 后端 /api/media/list 返回的 id 是字符串，但 /api/report/{id} 里 media_id 是数字
const item = JSON.parse(text) as MediaItem;   // 编译通过
// 如果服务端实际下发的是 12（number），而 MediaItem.id 声明为 string：
//   - 编译期不报错
//   - 运行时 item.id 就是 number
//   - 于是 item.id === '12' → false，列表选中/删除全部失效（且很难查）
```

两条对策（都要做）：
1. **wire 模型按后端真实类型声明**：`ReportListItem.media_id: number`（`schemas.py:72` 是 `int`），不要"统一按 string 猜"。
2. **加一层 normalize 函数**，把接口返回值显式转换成前端统一类型：

```ts
export function normalizeMediaId(raw: number | string): string {
  return typeof raw === 'string' ? raw : raw.toString();
}
```

顺带一条：**`JSON.parse(s) as SomeClass` 拿到的对象没有方法**（没有原型），方法在运行时是 `undefined`。所以 **wire DTO 一律声明成 `interface`，不要声明成 `class`**；需要行为就另写静态函数或独立工具类。

### 2.5 共享模型文件长什么样

```ts
// shared/enums.ts —— 合法 TS，也合法 ArkTS
export enum SeverityLevel { none = 'none', mild = 'mild', moderate = 'moderate', severe = 'severe' }
export enum MediaType { image = 'image', video = 'video' }

// shared/model.ts
import { MediaType } from './enums';

export interface MediaItem {
  id: string;
  name: string;
  type: MediaType;
  thumbnail_url: string;
  url: string;
  duration?: number;
  created_at: string;
}

export interface AnalysisFrame {
  frame_id: number;
  timestamp: number;
  bdi_score: number;
  aligned_face: string;      // 裸 base64 JPEG（无 data: 前缀）
  heatmap_data: number[][];  // 16×16
  inference_time_ms: number;
  progress: number;
}

export interface ReportListItem {
  id: number;
  media_id: number;
  media_name: string;
  media_type: string;
  bdi_score: number;
  severity: string;
  detected_at: string;
  inference_time_ms: number;
}

export interface StatsData {
  total_analyses: number;
  total_media: number;
  severity_distribution: Record<string, number>;   // Record 是 ArkTS 允许的 4 个工具类型之一
  avg_inference_time_ms: number;
  bdi_trend: { date: string; avg_score: number }[]; // 匿名对象类型：TS 合法，ArkTS 建议提成命名 interface
  recent_reports: ReportListItem[];
}

/** WS 入站消息：控制消息带 type，帧消息不带（所以全部可选） */
export interface WsInbound {
  type?: string;
  message?: string;
  task_id?: string;
  content?: string;
  final_score?: number;
  frame_id?: number;
  timestamp?: number;
  bdi_score?: number;
  aligned_face?: string;
  heatmap_data?: number[][];
  inference_time_ms?: number;
  progress?: number;
}
```

> `bdi_trend` 里那个匿名对象类型在 ArkTS 里有风险（`arkts-no-noninferrable-arr-literals` 等约束），**建议提成命名 interface `BdiTrendPoint`**，两边都用——这也是"共享文件要按 ArkTS 子集写"的意义。

## 三、开工顺序建议

1. 先建 `shared/`（半天）——把 `src/api/index.ts` + `stores/dashboard.ts` 的类型搬进去，Vue 侧改成 re-export，跑通 `npm run build` 确认没破坏现有前端。
2. 建 DevEco 空工程，把 `shared/` 挂进去，写**一个** `.ets` 页面 import 这些类型并编译通过 → 顺手验证 2.3 的约束清单。
3. 最小联调闭环（1–2 天）：`POST /api/upload/image`（先用 PhotoViewPicker 选一张本地图）→ 建 WS → 收到 10 帧 → `done`。这一段跑通，M3 里程碑就落地了。
4. 再补 1.4 里的边界（重连/收尾区分/网络配置），最后才是 UI 复刻与图表自绘。

**先做第 2、3 步的"最小可行性验证"，再全面展开** —— 明文 HTTP 网络配置、CameraKit 采集、PDF 导出是三个已知高风险点。
