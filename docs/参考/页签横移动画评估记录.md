# 鸿蒙端「页签切换 · 阻尼横移」可行性评估与实测记录

> **参考状态：决策留档（2026-10-17）**。路线 ④「轨道容器」最终**未保留**在当前版本：
> 它要求两页同屏常驻，与逐卡错峰入场互斥。当前实现是“逐卡离场 → 换页 → 逐卡入场”，
> 见 [页面框架 5.3 节](../鸿蒙端页面框架与路由说明.md#53-没有两页同屏横移)。
>
> 记录时间：2026-10-17
> 目标机型/环境：鸿蒙模拟器 `127.0.0.1:5555`（1316×2832），SDK `6.1.0(23)`（API 23），DevEco Studio 6.1
> 结论一句话：**可行，而且效果可以做到"完全可控"；但用 Navigation 的路由切换实现不了，必须让两个页面同时存在于我们自己的容器里。**

---

## 一、需求拆解

原始诉求被拆成 4 条可验收的指标（后续全部按这 4 条验收）：

| # | 指标 | 说明 |
|---|---|---|
| R1 | 旧页向左滑出 | 点"往右"的页签时，当前页整体向左移出屏幕 |
| R2 | 新页从右向左滑入 | 目标页从屏幕右侧滑入并停在正中 |
| R3 | 阻尼手感 | 收尾不是硬停，有减速 + 极轻微回弹（弹簧感） |
| R4 | 慢—快—慢 | 起步柔和、中段快、末段减速，不是匀速或纯加速 |

补充结论：**R1 和 R2 必须由同一个动画量驱动**。如果两页各跑一条时间轴（比如旧页用系统默认退场、新页用我们的入场），
中途会出现"错位/一快一慢"，观感立刻崩。这一点决定了下面所有方案取舍。

## 二、可行性结论：API 层面完全够用

SDK 里这些能力都已具备（路径均在本机 `E:\HarmonyOS\DevEco Studio\sdk\default\openharmony\ets`）：

| 能力 | API | 位置 | 备注 |
|---|---|---|---|
| 弹簧/阻尼曲线 | `curves.interpolatingSpring(velocity, mass, stiffness, damping)` | `api/@ohos.curves.d.ts:840` | 也支持 `springCurve`(651)、`springMotion`(730)、`responsiveSpringMotion`(788)、`cubicBezierCurve`(578) |
| 动画时长曲线组合 | `animateTo({duration, curve, onFinish}, () => {...})` | `component/common.d.ts`（`AnimateParam`，`onFinish` 在 4088） | `curve` 类型是 `Curve \| string \| ICurve`，**可以用自定义 ICurve** |
| 曲线枚举 | `Curve.Linear/Ease/EaseIn/EaseOut/EaseInOut/FastOutSlowIn/Friction/...` | `component/enums.d.ts:1899` | `EaseInOut` ≈ 慢快慢；`Friction` ≈ 阻尼 |
| 页面级自定义转场 | `Navigation.customNavContentTransition(delegate)` | `component/navigation.d.ts:3220` | delegate 返回 `NavigationAnimatedTransition \| undefined` |
| NavDestination 级自定义转场 | `NavDestination.customTransition(delegate)` | `component/nav_destination.d.ts:1281` | `NavDestinationTransition.duration/curve/delay/event/onTransitionEnd` |
| 页面内局部横移 | `Common.translate({x: number \| string})` + `.opacity()` | 通用属性 | `x` 支持百分比（相对自身宽度），所以不用测量屏幕宽度 |
| 已有工程惯例 | `this.getUIContext().animateTo(...)` | 见于 `components/RippleCard.ets:130` | 与工程既有写法一致，不需要引入新依赖 |

**关键结论：`ICurve` 可用**，所以"阻尼 + 慢快慢"不是二选一，一条弹簧曲线可以同时满足 R3 和 R4。

### 推荐手感参数（已验证可用）

```ts
curves.interpolatingSpring(0, 1, 260, 26)
//  初速 0   → 慢起（R4 的左半段）
//  质量 1、刚度 260 → 中段速度快（R4 的中段）
//  阻尼比 ζ = 26 / (2·√260) ≈ 0.81（欠阻尼）
//           → 末段减速 + 终点一次极轻回弹（R3）
```

调参对照：

| 想要的手感 | 参数 |
|---|---|
| 纯「慢—快—慢」、完全不回弹 | `curves.cubicBezierCurve(0.4, 0, 0.2, 1)` 或 `Curve.EaseInOut` |
| 更"弹" | 阻尼降到 18 左右（ζ≈0.56，回弹明显） |
| 更"稳"、贴近临界阻尼 | 阻尼提到 30~32（ζ≈0.93~1.0，几乎不回弹） |
| 更慢/更快 | 调刚度：数值越大越快（260 ≈ 380ms 收敛） |

## 三、四条路线实测结果（这是本记录最有价值的部分）

全部在真机（模拟器）上跑过，靠 `hdc shell snapshot_display` 连拍抓中间帧验证，证据图在 `_materials/_verify/`。

### 路线 ①：`NavPathStack.replacePathByName` + 自定义转场 —— ❌ 不可用

工程原实现用 `replacePathByName` 切页签（栈深恒为 1）。给它加 `customNavContentTransition` 返回自定义转场，
期望"转场窗口内两页同时存活，然后把 `motionPos` 从头动画到尾"。

**实测结果：旧页在替换的那一帧就被销毁了。**
- 证据：`m1.jpeg`、`s1.jpeg` —— 切页瞬间画面只剩**纯白底 + 新页从右侧滑入**，旧页内容完全不渲染。
- 放大实验（把动画临时调到 2500ms 慢放，见 `s1.jpeg`）：0.2s 时旧页本该只移动 5%，
  但画面上**一点旧页内容都没有**，说明不是"移出屏幕"，而是真的被销毁。
- 结论：`replacePathByName` 的语义就是"销毁旧页"，转场里也留不住。

### 路线 ②：`pushPathByName` + `customNavContentTransition` —— ❌ 不可用

改成 push（旧页本应仍在栈里），并用自定义转场撑开窗口（`proxy.finishTransition()` 才结束）。
- 证据：`q1.jpeg`、`q2.jpeg` —— 现象与路线 ① 一模一样：只有新页从右滑入，左侧全白。
- 结论：`customNavContentTransition` **不会**让被覆盖的 NavDestination 继续绘制。

### 路线 ③：`pushPathByName` + 系统默认转场 —— ⚠️ 能看，但不可控

- 证据：`r1.jpeg` —— 系统默认转场**确实同时绘制了两页**：左侧旧页整体左移（视差），右侧新页滑入。
- 也就是说：**默认转场本身就已经接近需求（R1+R2 都有）**。
- 但不可用，因为：
  1. 曲线不可控（拿不到 R3/R4），`customNavContentTransition` 一旦接管就退化成路线 ②；
  2. **方向不可控**：不管往左还是往右切页签，系统都是"从右往左"滑；
  3. 每切一次要压栈、动画结束再 `removeByIndexes` 裁剪栈，复杂且易受打断影响。
- 附带实测：`animated: false` 时被覆盖的页面**立刻停止绘制**（连拍只有白底），
  所以"关掉系统动画、只播我们自己的动画"这条路也走不通。

### 路线 ④（✅ 采用）：一级页签不进路由栈，改用「轨道容器」自己摆位

把 5 个一级页签从 `Navigation` 的 `navDestination` 里拿出来，放进 Navigation 的**根内容**，
用一个 `Stack` + 一个可带小数的坐标 `motionPos` 自己摆位；二级页（素材选择 / 分析详情）仍走路由栈。

- 证据：`t1.jpeg` —— 中间帧里**旧页（工作台）确实整体左移**（卡片被裁掉一截），
  新页正从右侧进入，两页同屏。
- 为什么这条路一定成立：两页都是**我们自己的子组件**，渲染与否由我们决定，
  完全不依赖 Navigation 转场机制的内部行为。

## 四、路线 ④ 的完整实现（回退后按此重新应用）

### 4.1 原理：把页签想成一条横向轨道

`motionPos` 是**允许取小数的格位坐标**：0=工作台，1=素材库，2=历史报告，3=统计，4=我的。
每页只需要知道自己相对它的位移：`(自己的下标 - motionPos) × 100%`。

```
静止：motionPos = 1（停在各页签在正中），素材库位移 0，其余页位移 ±100% 在屏外
右切：motionPos 动画 1 → 2
      素材库  ：位移 0    → -100%   ← 左滑走（R1）
      历史报告：位移 +100% → 0       ← 从右滑入（R2）
```

一个量驱动两页 ⇒ 天然同步、天然同向；反向切换不需要第二套代码。
位移用**百分比**，因为 `translate` 的百分比是相对自身宽度的，换机型/折叠屏不用重新测量。

### 4.2 新增文件 `harmony/entry/src/main/ets/common/TabMotion.ets`

```ts
import { curves } from '@kit.ArkUI';

/** 一级页签横移转场 · 运动学参数与算式 */
export class TabMotion {
  /** 动画时长（上限，弹簧真实时长由曲线收敛决定） */
  public static readonly duration: number = 380;

  /** 收尾超时兜底（大于收敛时间） */
  public static readonly timeout: number = 700;

  /** 屏外页渐隐强度：每远离一屏宽，透明度减这么多 */
  public static readonly fadeDepth: number = 0.28;

  /** 屏外页缩放强度（可选增强，当前未启用） */
  public static readonly scaleDepth: number = 0.05;

  /** 阻尼曲线 · 改手感只改这一个方法 */
  public static curve(): ICurve {
    return curves.interpolatingSpring(0, 1, 260, 26);
  }

  public static distanceOf(index: number, position: number): number {
    return index - position;
  }

  public static offsetPercent(index: number, position: number): string {
    const percent: number = TabMotion.distanceOf(index, position) * 100;
    return `${percent}%`;
  }

  public static opacityOf(index: number, position: number): number {
    const distance: number = Math.abs(TabMotion.distanceOf(index, position));
    const opacity: number = 1 - TabMotion.fadeDepth * distance;
    return opacity > 0 ? opacity : 0;
  }

  /** 未启用：启用后页面四周会出现细缝（页面与父容器同为白色所以看不出来） */
  public static scaleOf(index: number, position: number): number {
    const distance: number = Math.abs(TabMotion.distanceOf(index, position));
    const scale: number = 1 - TabMotion.scaleDepth * distance;
    return scale > 0 ? scale : 0;
  }
}
```

### 4.3 `pages/PageRoutes.ets` 追加：下标即轨道格位

```ts
/**
 * 取页签在轨道上的格位（顺序即 `MAIN_TABS` 顺序）
 * ★ 必须与底部导航栏同源：调整页签顺序时动画方向自动跟着对。
 * @returns 格位下标；不是一级页签时返回 -1
 */
export function mainTabIndexOf(name: string): number {
  for (let i = 0; i < MAIN_TABS.length; i++) {
    if ((MAIN_TABS[i].tab as string) === name) {
      return i;
    }
  }
  return -1;
}
```

**① 新增状态字段**

**② `aboutToAppear` 不再入栈**

**③ `pushTab` 改为纯本地状态 + 动画（不碰路由栈）**

```ts
private pushTab(tab: MainTab): void {
  if (tab === this.selectedTab) {
    return;
  }
  const target: number = mainTabIndexOf(tab as string);
  this.buildTabParam(tab);                       // 先投影参数，新页挂载即读到正确状态

  this.leavingTabName = this.selectedTab as string;
  this.selectedTab = tab;

  this.runTabMotion(target, () => {
    this.leavingTabName = '';                    // 动画收尾再卸离场页
    this.refreshUi();
  });
}
```

**④ 动画驱动（含"只收尾一次"保护）**

```ts
private runTabMotion(target: number, finish: () => void): void {
  let done: boolean = false;
  const complete: () => void = () => {
    if (done) { return; }
    done = true;
    finish();
  };

  // 快速连点时 onFinish 不一定来，兜底保证收尾只跑一次
  setTimeout(() => { complete(); }, TabMotion.timeout);

  this.getUIContext().animateTo({
    duration: TabMotion.duration,
    curve: TabMotion.curve(),
    onFinish: () => { complete(); }
  }, () => {
    // ★ 赋值必须在闭包内，animateTo 只对闭包内的状态变化生成隐式动画
    this.motionPos = target;
  });
}
```

**⑤ 轨道层 Builder（替代原来 5 个页签 NavDestination 分支）**

```ts
@Builder

  if (name === MainTab.workbench && this.workbenchParam instanceof WorkbenchPageParam) {

  } else if (name === MainTab.media) {

@Builder
tabLayer(name: string) {
  Column() {
    this.tabPage(name)
  }
  .width('100%')
  .height('100%')
  .translate({ x: TabMotion.offsetPercent(mainTabIndexOf(name), this.motionPos) })

```

## 六、遗留问题 / 后续注意

1. **页签常驻带来的参数时效性**：路线 ④ 里当前页是常驻的（只有离场页会被卸掉），
   所以 `@Param pageParam` 按引用比对、**改字段不会让已挂载页面刷新**。
   现有 4 个页签（素材库/历史报告/统计/我的）都是占位页，影响可忽略；
   等它们实装数据后，要么把 `TabPageParam` 改成 `@ObservedV2 + @Trace`，
   要么每次切页强制重建（用 `if` 换 key）。
2. **`leavingTabName` 只记一个**：极快速连点两个页签时，上一个离场页会被提前卸掉，
   出现一帧跳变。要彻底解决需改成列表，但收益不大。
3. **工作台首帧**：`motionPos` 初值必须等于首屏页签下标，否则首帧会"从旁边滑入"一次。
4. **横向手势切页签（Swiper 式跟手）本次未做**：`motionPos` 是连续量，
   接 `PanGesture` 直接改它即可，属于低成本的后续增强。
5. **深色背景会暴露 scale 细缝**：`scaleOf` 当前未启用，启用前必须确认页面与容器背景一致。
