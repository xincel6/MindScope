## 三、基础 bug 自查发现并修掉的问题

### 3.1 编译期发现（64 → 0）

| 问题 | 现象 | 修法 |
|---|---|---|
| 静态字段与方法同名 | `Duplicate identifier 'mediaDao'` + `This expression is not callable` | 字段前缀 `daoXxx`，方法 `xxxDao()` |
| 惰性单例 `if (x === null) { x = new ... }` | `Cannot invoke an object which is possibly 'null'`（ArkTS 类型收窄不跨静态字段） | 改为**立即初始化** |
| 静态属性叫 `name` | `conflicts with built-in property 'Function.name'` | 改名 `tableName` |
| 基类泛型解码器 `decodeRow<T>(row): T` | `DiagnosisReportModel[] is not assignable to ReportListItemModel[]`（不支持结构化类型） | 泛型提到类上 `BaseDao<T>`，并让报告表统一解码为列表项形状、notes 单独投影 |
| `Record<string, Object>` 存 RDB NULL | `Type 'null' is not assignable to type 'Object'` | `DbRow = Record<string, Object \| null>` |
| Record 动态下标写入 | 头字段合并报错 | 改为显式 `if` 写已知键 |
| `@Computed` 配 `@Component` / `@State` 配 `@ComponentV2` | 装饰器约束报错 | `@ComponentV2` + `@Local` |
| `hilog` 格式串 `%{public}s` 缺实参 | 日志会打成字面量 | 统一在 `Logger` 里拼好字符串 |

### 3.2 逻辑自查（主动修正）

1. **RDB 初始化失败后本进程内永不重试** → 改为「未建好就允许重试」，保住离线能力。
2. **`AppStore.sync()` 会把「正在分析」误刷成 false** → 同步时改为从桥接器**读取**真实状态。
3. **`stopAnalysis()` 会清掉上次结果** → 停止只释放连接，**不清分数/热力图**，返回页面仍可见。
4. **重复 start 会泄漏旧连接** → 检测到 `running` 先 `stop()` 再开新连接。
5. **`/api/upload/image` 只回 4 个字段** → `Mapper.toUploadedMedia` 显式补齐，`created_at` 用**本地** `%Y-%m-%d`（不用带时区偏移的 `toISOString()`），避免东八区差一天。
6. **详情接口没有 media_name / media_type** → 拿不到时**跳过**本地镜像补写，避免把列表页写好的正确值覆盖成空。
7. **`mediaId` 字符串/数字混用会让选中与删除静默失效** → 全部出海前过 `normalizeMediaId()`；`/api/report/{id}` 的 int path 参数由 `ReportApi.listByMediaIdText` 转换。
8. **422 的 `detail` 是数组** → `normalizeDetail()` 显式判断并摊平成中文，不会弹 `[object Object]`。
9. **`ResultSet` / `executeSql` 可能抛异常** → 全部兜住（ArkTS 的 6 个 "Function may throw exceptions" 警告同步清零）。
10. **HTTP 头 `Content-Type` 只在需要时设置** → 避免 multipart 被 JSON 头覆盖。
