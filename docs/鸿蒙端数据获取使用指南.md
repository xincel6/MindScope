## 一、三十秒上手

```ts
import { AppStore } from '../store/AppStore';

@ComponentV2                       // ★ 必须 V2：@ObservedV2 的类只有在 @ComponentV2 里才会驱动刷新
struct MyPage {
  @Computed
  get app(): AppStore { return AppStore.get(); }

  build() {
    Column() {
      // 直接读字段，数据一变自动重绘
      Text(`共 ${this.app.mediaItems.length} 个素材`)
      ForEach(this.app.mediaItems, (item) => {
        Text(item.name)                            // ★ 字段是驼峰，不是 name / created_at
        Image(this.app.media().thumbnailUrl(item))
      }, (item) => item.id)                        // ★ item.id 一定是字符串
    }
  }
}
```

三条铁律：

1. **取数只找 `AppStore.get()`**（门面）或它下面的领域 store，不要自己 `http.createHttp()`。
2. **字段一律驼峰**（`createdAt` / `thumbnailUrl` / `bdiScore`），只有 `types/dto.ts` 里保留服务端的 `snake_case`。
3. **id 一律当字符串用**（`MediaItemModel.id`、`ReportListItemModel.mediaId` 都已归一化，可直接比较）。

> 页面纪律与两处已知例外（工作台 / 分析详情直接读 `AppStore`）见
> [页面框架与路由说明 3.1 节](鸿蒙端页面框架与路由说明.md#31-三条页面纪律)。

## 二、数据从哪来：启动时序

写 UI 之前不需要做任何初始化 —— 在 Ability 生命周期最开始，数据层已经自己启动：

```text
EntryAbility.onCreate
  └─ AppBootstrap.start(this.context)          ← 同步返回，不阻塞首帧
       ① StorageManager.init(context)          打开 preferences + RDB（v2），建表建索引
       ② ApiConfig.load()                      读回服务端地址与令牌
       ③ 冷启动预热                            从 RDB 把上次数据灌进内存 store（UI 立刻有内容）
       ④ AuthStore.restore()                   有令牌则调 /api/auth/me 校验
       ⑤ 并发拉取 media / reports / stats       写内存 store + 回写 RDB
       ⑥ restoreAssessment()                   恢复上次已落盘的工作台评估
       ⑦ 失败 / 无令牌 → 标记离线或未登录         UI 照常渲染，不崩、不白屏
```

UI 侧如何知道“加载好了没有”：

```ts
import { AppBootstrap } from '../common/AppBootstrap';
import { AppStore } from '../store/AppStore';
import { BootPhase } from '../types/Index';

aboutToAppear(): void {
  AppBootstrap.ready.then(() => { AppStore.get().sync(); });
}

// 或者用 bootPhase 做分支（推荐，首帧就有东西看）：
//   BootPhase.idle        未启动
//   BootPhase.preparing   正在读缓存 / 校验令牌  → 骨架屏
//   BootPhase.authenticated 已登录              → 正常渲染
//   BootPhase.anonymous   未登录                → 登录页
```

## 三、`AppStore` 门面（主入口）

`AppStore.get()` 是单例。**下面这些字段都是 `@Trace`，读了就会自动刷新。**

### 3.2 方法一览

```ts
const app = AppStore.get();

// ── 数据刷新 ──
await app.loadAll();            // 并发刷新 media + reports + stats（下拉刷新用）
await app.refreshMedia();       // 只刷媒体库
await app.refreshReports();     // 只刷报告（沿用当前筛选条件）
await app.loadAllReports();     // 历史报告：从第 1 页连续拉到 hasMore = false
await app.filterReports(severity, mediaType);   // 应用筛选 + 全量加载
await app.refreshStats();       // 只刷统计

// ── 领域 store（要调具体方法时用）──
app.auth()        // AuthStore   登录 / 注册 / 登出
app.media()       // MediaStore  素材库：上传、删除、患者筛选、重命名
app.reports()     // ReportStore 报告：翻页、筛选、详情
app.statsStore()  // StatsStore  统计
app.analysis()    // AnalysisStateHolder  WS 会话归档

// ── 便捷查询 ──
app.isBooted()                  // 引导是否结束（骨架屏判据）
app.username()                  // 用户名；未登录返回 ''
app.findMedia('12')             // 按 id 找媒体，找不到返回 null
app.mediaEmptyHint()            // 媒体库空态文案（已处理离线 / 加载中）
app.visibleMediaItems()         // 应用了类型筛选的媒体列表
app.patientOptions()            // 去重患者名（含“未命名”）
app.patientFilter()             // 当前患者筛选
app.setPatientFilter(patient)   // 设患者筛选；空串 = 全部
app.filteredMediaItems(type)    // 按「患者 + 类型」筛好的列表
app.renamePatient(mediaId, patient)  // 改患者名（后端已支持，需部署后生效，见下）
app.serverConfig()              // { host, port, baseUrl, wsBase }
await app.changeServer(host, port)   // 运行期改服务端地址（带探活）
await app.checkHealth()         // 探活 GET /health，返回 { ok, message }

// ── 分析会话 ──
app.startAnalysis(mediaId)      // 开始分析（自动开 WS）
app.cancelAnalysis()            // 请求取消（★ 视频场景基本无效）
app.stopAnalysis()              // 停止并释放连接（不清结果）
app.currentTask()               // 当前任务展示模型（null = 无任务）
app.recentMedia(1)              // 最近报告聚合（工作台 hero 无持久化评估时兜底）
app.firstFrameUrlOfMedia(id)    // 某素材的首帧图（评估恢复 / hero 用）
app.analysisSessionsOf()        // 全部会话（按 mediaId 归档）
app.analysisSessionOf(mediaId)  // 取**该素材自己的**会话（找不到返回 null）
app.analysisLiveMediaIdOf()     // 正在 live 分析的素材 id（空串 = 无）
app.analysisHeatmap()           // live 最新一帧热力图 number[][]
app.analysisFaceDataUrl()       // live 最新一帧人脸 DataURL
app.analysisProgressText()      // "42%"
app.analysisSeverityLabel()     // "轻度"

// ── 工作台评估持久化 ──
await app.persistAssessment()   // 分析 done 后由 onAnalysisFinished 自动调用
await app.restoreAssessment()   // 引导 / 登录成功后自动调用
```

### 3.3 领域 store 的公开方法

| Store | 常用方法 |
|---|---|
| `MediaStore` | `refresh` / `loadFromCache` / `warmUp` / `deleteMedia` / `uploadMedia` / `uploadMediaWithPatient` / `uploadImage` / `uploadImageWithPatient` / `renamePatient` / `visibleItems` / `filteredItems(type)` / `patientOptions` / `setPatientFilter` / `playableUrl` / `thumbnailUrl` / `findById` |
| `ReportStore` | `refresh` / `loadAllPages` / `loadMore` / `applyFilter` / `applyFilterAndLoadAll` / `resetFilter` / `loadDetail` / `loadFromCache` / `isFiltered` / `filterSummary` / `emptyHint` |
| `AuthStore` | `login` / `register` / `restore` / `loadMe` / `logout` / `onUnauthorized` / `refresh` / `displayName` / `registeredAt` |
| `AnalysisStateHolder` | `start(mediaId, mediaType)` / `cancel` / `stop` / `sessionsOf` / `sessionOf(mediaId)` / `restoreSession` / `isRunning` / `errorOf` / `progressOf` / `scoreOf` / `frameCountOf` |

> 字段变化触发刷新的前提：字段必须是 `@Trace`；整体替换数组引用（`concat` / `slice`），不要原地 `push`。

### 3.4 分析会话：按 `mediaId` 取数

每个素材的分析结果独立归档在 `AnalysisState.sessions`：

```ts
const session = app.analysisSessionOf('12');   // 只取 12 号素材自己的会话
if (session !== null) {
  session.frames;      // 逐帧（含 heatmapData / alignedFace / bdiScore）
  session.scores;      // 曲线分数序列
  session.vlmText;     // 智能解读
  session.firstFrameFace;  // 首帧对齐人脸（不随 frames 裁剪）
}
```

规则：

- **绝不跨素材兜底**。取不到就展示“本机未保留这次分析的逐帧数据”，不要拿全局最新一帧顶替（BUG-14）。
- 图片 = 1 帧，视频 = 逐帧；展示口径统一走 `AnalysisChartModel.resolveFrames()` / `displayFrameCount()`。
- 内存上限：6 条素材会话；单会话 live ≤ 90 帧、收尾裁到 30 帧；分数点 ≤ 120。
- 工作台评估持久化只在 `done` 时落盘；`running` / `failed` 不落盘。

### 3.5 患者命名

后端已支持（提交 `21b8cc3`）：上传接口接收 `patient`、列表返回 `patient`、`PUT` 更新 / 清除。
远程服务器需要部署该版本后才会生效；端上无需改接口。

```ts
// 上传时带患者名：服务端落库并回显，端上同时写入本地镜像
await app.media().uploadImageWithPatient(file, '张三');

// 重命名：先调 PUT，成功后才写本地镜像；空串表示清除
const r = await app.renamePatient('12', '李四');
if (!r.ok) { /* r.message 是接口失败文案（未部署 / 超过 64 字 / 网络） */ }
```

## 四、可直接抄的页面示例

### 4.1 工作台分析区（读 `AppStore` 会话 + 参数回调）

```ts
import { AppStore } from '../store/AppStore';
import { WorkbenchPageParam } from '../types/PageParams';
import { AnalysisSessionModel, CurrentTaskModel } from '../types/Index';

@ComponentV2
struct WorkbenchAnalysisSection {
  @Param pageParam: WorkbenchPageParam = new WorkbenchPageParam();

  @Computed get app(): AppStore { return AppStore.get(); }

  @Computed get task(): CurrentTaskModel | null {
    return this.app.currentTask();            // 已包含首帧 / 分数 / 状态 / 恢复标记
  }

  @Computed get session(): AnalysisSessionModel | null {
    const t = this.task;
    return t === null ? null : this.app.analysisSessionOf(t.mediaId);
  }

  build() {
    Column() {
      if (this.task === null) {
        Text('还没有评估记录');
      } else {
        Text(`${this.task.bdiScore.toFixed(1)} 分`)    // 首帧 / 状态 / 动作都在 task 里
        if (this.session !== null) {
          Text(`共 ${this.session.frames.length} 帧`)
        }
        Button('重新分析该素材')
          .onClick(() => this.pageParam.onReanalyze(
            this.task!.mediaId, this.task!.mediaName, this.task!.mediaType))
      }
    }
  }
}
```

要点：

- 实时数据（进度 / 帧 / 分数 / VLM）走 `@Computed` + `AppStore`，不要塞进页面参数；
- 动作仍走 `pageParam` 回调，页面不碰路由栈、不发请求；
- 首帧照片取 `task.firstFrameUrl`，没有时回落到媒体缩略图。

### 4.2 素材库列表（页面只读参数）

```ts
import { MediaLibraryPageParam } from '../types/PageParams';
import { MediaItemModel } from '../types/Index';

@ComponentV2
struct MediaGrid {
  @Param pageParam: MediaLibraryPageParam = new MediaLibraryPageParam();

  build() {

```

要点：

- 列表由窗口层按「患者 + 类型」筛好后注入，页面不再算一遍；

- 空态 / 错误 / 忙碌态分别由 `videos.length`、`errorMsg`、`busy` 驱动。

## 五、分析（WebSocket）怎么用

```ts
const app = AppStore.get();

// ① 开始：内部自动建连、拼 token、发 {"id":...}
app.startAnalysis(mediaId);

// ② 渲染：帧是突发批量到达的，不要每帧重绘图表，读 @Trace 最终值
if (app.analyzing) {
  Text(app.analysisProgressText());
  Text(app.analysisScore.toFixed(2));
  Text(app.analysisSeverityLabel());
  Image(app.analysisFaceDataUrl());
}

// ③ 结束：done 之后门面自动刷新 media / reports / stats，并持久化工作台评估

// ④ 页面 aboutToDisappear() 里：
AppStore.get().stopAnalysis();     // 工作台 / 详情页按需，停止不清结果
```

必须知道的四个坑（数据层已处理，但会影响 UI 文案）：

| 现象 | 原因 | 你该怎么做 |
|---|---|---|
| `progress` 从 0 直接跳到 1 | 服务端先把整个文件算完，再突发回推 | 进度条做过渡动画，别按帧数算比例 |
| 点“取消”没反应 | 后端 `cancel` 只在帧循环期间有效，视频早就算完了 | **不要**在 UI 上承诺“可中断” |
| 断线后收到“将重新分析” | 重连会重发媒体 id，服务端从头再跑 | 提示用户会重跑，别假装断点续传 |
| `done` 之后连接就断了 | 服务端主动 close，正常收尾 | 别弹“连接已断开” |

新增边界：

- 图片只会收到 **1 帧**；不要为了“图表好看”去凑点。
- 每个素材的会话按 `mediaId` 归档；同素材重算覆盖自己，其它素材保留。
- 会话只存内存（`done` 时随工作台评估落盘）；App 重启后历史素材只剩报告分数 + 重新分析。

## 六、`.ts` 与 `.ets` 的分工（改代码前必读）

| 后缀 | 放什么 | 文件 |
|---|---|---|
| `.ts` | 纯类型 + 纯常量，**同时是合法 TS 与合法 ArkTS**，Web 端可直接 import | `types/enums.ts` `dto.ts` `model.ts` `constant.ts` `mapper.ts` `Index.ts` |
| `.ets` | 用了 ArkTS 专有能力（装饰器、ArkUI 类型、系统 Kit） | `types/storeState.ets` 及其余全部 |

**官方约束**（`arkts-no-ts-deps`）：`.ets` 可以 import `.ts`，**反向不行**。
所以共享类型**必须**是 `.ts`；也正因如此，`types/Index.ts`（`.ts`）**不能**统一导出 `storeState.ets`：

```ts
import { AppState, MediaState } from '../types/storeState';
```

### 6.1 驼峰与 `snake_case` 的边界

```text
服务端 schemas.py（snake_case，不许改）
       ↓ types/dto.ts        字段名保持 snake_case，1:1 零漂移
       ↓ types/mapper.ts     逐字段手写转换（禁止对象展开）
       ↓ types/model.ts      全部驼峰 —— UI 层只认这一层
       ↓ store / UI
```

- **只有 `types/dto.ts` 允许出现 `snake_case`**，且仅限字段名；类型名、函数名一律驼峰。
- 服务端将来改字段 → 只改 `dto.ts` + `mapper.ts`，UI 一行不动。
- 例外：RDB 的**物理表名 / 列名**刻意沿用服务端 `snake_case`（镜像表要同构）。

### 6.2 自己加类型时

```ts
// types/model.ts
export class MyNewModel { /* 驼峰字段 */ }

// types/Index.ts —— 显式具名导出，不用 export *
export { MyNewModel } from './model';
```

## 七、三种异常状态的 UI 处理

> 本节片段需要 `import { promptAction } from '@kit.ArkUI';`；`r` 的类型是 `ActionResultModel`。

### 7.1 未登录（`bootPhase === BootPhase.anonymous`）

- 渲染登录页；**不要**弹“请先登录”的 toast；
- `globalMessage` 非空时（通常是“登录已过期，请重新登录”）弹一次，然后 `clearGlobalMessage()`。

```ts
if (this.app.globalMessage.length > 0) {
  promptAction.showToast({ message: this.app.globalMessage });
  this.app.clearGlobalMessage();
}
```

### 7.2 离线（`offline === true` 或各 store 的 `errorMsg` 非空）

- **有本地缓存就正常渲染**（media / reports / stats 都做了镜像），只在顶部加一条细提示；
- 空数据时才提示“离线且无本地缓存”（`mediaEmptyHint()` 已处理）；
- 离线时**不要**自动重试轰炸：数据层已把网络失败静默成“保留缓存”，用户下拉刷新即可。

```ts
if (this.app.offline) {
  Text('当前离线 · 展示本地缓存数据').fontSize(12).fontColor('#d97706')
}
```

### 7.3 服务端未启动 / 地址不对

```ts
const r: ActionResultModel = await AppStore.get().checkHealth();
if (!r.ok) { promptAction.showToast({ message: r.message }); }
await AppStore.get().changeServer('192.168.0.123', 8000);   // 改完自动探活并持久化
```

> 真机联调前提：后端监听 `0.0.0.0`；`module.json5` 的 INTERNET 权限与
> `network_config.json` 明文放行已配好。

### 7.4 患者命名失败

常见原因：服务器尚未部署 `21b8cc3`（`PUT` 会 404）、名称超过 64 字符（400）、网络 / 鉴权失败。
失败时本地数据保持不变，直接展示 `r.message` 即可。

```ts
const r = await AppStore.get().renamePatient(mediaId, patient);
if (!r.ok) {
  promptAction.showToast({ message: r.message });
}
```

## 八、扩展数据层时改哪里

| 需求 | 改哪个文件 |
|---|---|
| 新增一个服务端接口 | `network/XxxApi.ets` 加方法，只在 `HttpClient` 之上拼 URL |
| 服务端返回了新字段 | `types/dto.ts` 加字段 → `types/mapper.ts` 显式转换 → `types/model.ts` 加驼峰字段 |
| UI 要一个新的派生值 | 加在对应领域 store 上，**不要**写进页面里重复算 |
| 新加一类业务数据 | 新建 `persistence/XxxDao.ets`（继承 `BaseDao<T>`）+ `store/XxxStore.ets`（继承 `BaseStore`）+ `StorageManager` 挂 DAO |
| 加数据库列 | `persistence/DbSchema.ets` 改 DDL，`types/constant.ts` 的 `RDB_VERSION` **+1**，`StorageManager.migrate()` 补分支 |
| 新页面要读数据 | 优先用现成 `AppStore` 字段；确实不够再加领域 store 的 `@Trace` 字段 + 在 `AppStore.sync()` 拉平 |

### ArkTS 血泪清单（照着做能少踩 90% 的编译错）

1. `@ObservedV2` 的字段必须 `@Trace` 才会刷新 UI；普通 class 字段不刷新。
2. `@Computed` 只能写在 `@ComponentV2` 里，且 V2 里用 `@Local` 而不是 `@State`。
3. 静态属性名**不能叫 `name`**（与 `Function.name` 冲突）。
4. 静态字段不要与方法同名（`Duplicate identifier` + “not callable”）。
5. 不要写 `if (f === null) { f = new X() }` 的惰性单例 —— 类型收窄不生效；改用立即初始化。
6. 对象字面量必须有明确类型标注，且不能初始化“带参构造的类”或“带方法的接口”（回调用抽象类）。
7. 没有对象展开 `{...obj}`、没有 `any`、没有正则字面量（用 `new RegExp`）、没有 `Pick/Omit/Exclude`。
8. 泛型实参必须显式写，不能靠返回值推断。
9. 两个形状相同的 interface 不能互相赋值（不支持结构化类型）。
10. `Record<string, T>` 的取值若要允许 `null`，必须写 `Record<string, T | null>`。

**改完必做**：改的是 `.ets` 且被页面 import 到，才会真正编译。

```bash
bash harmony/scripts/build.sh
```

`CompileArkTS ... UP-TO-DATE` 说明本次没重新编译；要确认代码真编过，先 `hvigorw clean`。
