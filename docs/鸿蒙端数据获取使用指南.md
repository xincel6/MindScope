# MindScope 鸿蒙端 · 数据获取使用指南

> 适用版本：本轮交付（`harmony/entry/src/main/ets/` 下的 `types/` `common/` `network/` `persistence/` `store/`）
> 面向读者：写 UI 的合作者。**你不需要碰网络、数据库、类型转换，只需要读 `AppStore`。**

---

## 一、三十秒上手

```ts
import { AppStore } from '../store/AppStore';

@Entry
@ComponentV2                       // ★ 必须 V2：@ObservedV2 的类只有在 @ComponentV2 里才会驱动刷新
struct MyPage {
  @Computed
  get app(): AppStore { return AppStore.get(); }

  build() {
    Column() {
      // 直接读字段，数据一变自动重绘
      Text(`共 ${this.app.mediaItems.length} 个素材`)
      List() {
        ForEach(this.app.mediaItems, (item) => {      // item 已被推断为 MediaItemModel
          ListItem() {
            Text(item.name)                          // ★ 字段是驼峰，不是 name/created_at
            Image(this.app.media().thumbnailUrl(item))
          }
        }, (item) => item.id)                        // ★ item.id 一定是字符串
      }
    }
  }
}
```

三条铁律：

1. **取数只找 `AppStore.get()`**（门面）或它下面的领域 store，不要自己 `http.createHttp()`。
2. **字段一律驼峰**（`createdAt` / `thumbnailUrl` / `bdiScore`），只有 `types/dto.ts` 里保留服务端的 `snake_case`。
3. **id 一律当字符串用**（`MediaItemModel.id`、`ReportListItemModel.mediaId` 都已归一化，可直接比较）。

## 二、数据从哪来：启动时序

你写 UI 之前不用做任何初始化 —— **在 Ability 生命周期最开始，数据层已经自己启动**：

```
EntryAbility.onCreate
  └─ AppBootstrap.start(this.context)          ← 同步返回，不阻塞首帧
       ① StorageManager.init(context)          打开 preferences + RDB，建表建索引
       ② ApiConfig.load()                      读回服务端地址与令牌
       ③ 冷启动预热                            从 RDB 把上次数据灌进内存 store（UI 立刻有内容）
       ④ AuthStore.restore()                   有令牌则调 /api/auth/me 校验
       ⑤ 并发拉取 media / reports / stats       写内存 store + 回写 RDB
       ⑥ 失败/无令牌 → 标记离线或未登录           UI 照常渲染，不崩、不白屏
```

UI 侧如何知道"加载好了没有"：

```ts
import { AppBootstrap } from '../common/AppBootstrap';
import { AppStore } from '../store/AppStore';
import { BootPhase } from '../types/Index';

aboutToAppear(): void {
  // 想等数据就绪再渲染重内容，就 await 这个 Promise
  AppBootstrap.ready.then(() => { AppStore.get().sync(); });
}

// 或者用 bootPhase 自己做分支（推荐，首帧就有东西看）
//   BootPhase.idle        未启动
//   BootPhase.preparing   正在读缓存/校验令牌  → 显示骨架屏
//   BootPhase.authenticated 已登录            → 正常渲染
//   BootPhase.anonymous   未登录              → 渲染登录页
```

## 三、`AppStore` 门面（★ 主入口）

`AppStore.get()` 是单例。**下面这些字段都是 `@Trace`，读了就会自动刷新。**

### 3.1 字段一览

| 字段 | 类型 | 说明 |
|---|---|---|
| `bootPhase` | `BootPhase` | 启动阶段（见上） |
| `offline` | `boolean` | 是否处于离线兜底 |
| `globalMessage` | `string` | 全局提示（如"登录已过期"），弹完调 `clearGlobalMessage()` |
| `serverHost` / `serverPort` | `string` / `number` | 当前服务端地址 |
| `signedIn` | `boolean` | 是否已登录 |
| `currentUser` | `UserModel \| null` | 当前用户（可能为 null） |
| `mediaItems` | `MediaItemModel[]` | **媒体库列表** |
| `mediaLoading` / `mediaError` | `boolean` / `string` | 媒体加载态/错误 |
| `reportItems` | `ReportListItemModel[]` | **报告列表（当前页）** |
| `reportTotal` | `number` | 报告总条数（服务端 total） |
| `reportHasMore` | `boolean` | 是否还有下一页 |
| `reportLoading` / `reportLoadingMore` | `boolean` | 首屏加载 / 加载更多 |
| `reportError` | `string` | 报告错误文案 |
| `statsSummary` | `StatsModel \| null` | **统计数据**（null = 还没有数据） |
| `statsBuckets` | `SeverityBucketModel[]` | 严重度分布（已摊平成数组，可直接 `ForEach`） |
| `statsLoading` | `boolean` | 统计加载态 |
| `analyzing` | `boolean` | 是否正在分析 |
| `analysisProgress` | `number` | 进度 0–1 |
| `analysisScore` | `number` | 当前 BDI 分数 |
| `analysisFrameCount` | `number` | 已收到帧数 |
| `analysisLastFrame` | `AnalysisFrameModel \| null` | 最新一帧（含热力图） |
| `analysisVlmText` | `string` | VLM 文本解读 |
| `analysisError` | `string` | 分析错误 |
| `socketState` | `SocketState` | WS 连接状态 |

### 3.2 方法一览

```ts
const app = AppStore.get();

// ── 数据刷新 ──
await app.loadAll();          // 并发刷新 media + reports + stats（下拉刷新用）
await app.refreshMedia();     // 只刷媒体库
await app.refreshReports();   // 只刷报告（沿用当前筛选条件）
await app.refreshStats();     // 只刷统计

// ── 领域 store（要调具体方法时用）──
app.auth()      // AuthStore  登录/注册/登出
app.media()     // MediaStore 媒体库：删除、上传、筛选、按 id 查
app.reports()   // ReportStore 报告：翻页、筛选、拉详情
app.statsStore()// StatsStore 统计

// ── 便捷查询 ──
app.isBooted()               // 引导是否结束（骨架屏判据）
app.username()               // 用户名；未登录返回 ''
app.findMedia('12')          // 按 id 找媒体，找不到返回 null
app.mediaEmptyHint()         // 媒体库空态文案（已处理离线/加载中）
app.visibleMediaItems()      // 应用了类型筛选的媒体列表
app.setMediaTypeFilter(MediaType.video)   // 设筛选；传 null = 全部
app.serverConfig()           // 当前地址快照 { host, port, baseUrl, wsBase }
await app.changeServer(ip, 8000)          // 运行期改服务端地址（带探活）
await app.checkHealth()      // 探活 GET /health，返回 { ok, message }

// ── 分析会话 ──
app.startAnalysis(mediaId)   // 开始分析（自动开 WS）
app.cancelAnalysis()         // 请求取消（★ 视频场景基本无效）
app.stopAnalysis()           // 页面消失时**必须**调用，否则连接泄漏
app.analysisHeatmap()        // 最新一帧热力图 number[][] (16×16)
app.analysisFaceDataUrl()    // 最新一帧人脸图 DataURL，可直接喂 Image
app.analysisProgressText()   // "42%"
app.analysisSeverityLabel()  // "轻度"
```

## 四、四个可直接抄的页面示例

### 4.1 列表页（媒体库）

```ts
import { AppStore } from '../store/AppStore';
import { MediaItemModel, MediaType } from '../types/Index';
import { UiConstant } from '../types/Index';

@Entry
@ComponentV2
struct MediaListPage {
  @Computed get app(): AppStore { return AppStore.get(); }

  build() {
    Column() {
      // 顶部筛选
      Row({ space: 8 }) {
        this.filterChip('全部', MediaType.image, true)
        this.filterChip('图片', MediaType.image, false)
        this.filterChip('视频', MediaType.video, false)
      }

      if (this.app.mediaLoading && this.app.mediaItems.length === 0) {
        LoadingProgress()                       // 首次加载：骨架/转圈
      } else if (this.app.mediaItems.length === 0) {
        Text(this.app.mediaEmptyHint())         // 空态文案已经处理了离线的情况
      } else {
        List() {
          ForEach(this.app.visibleMediaItems(), (item: MediaItemModel) => {
            ListItem() {
              Row({ space: 12 }) {
                Image(this.app.media().thumbnailUrl(item))   // ★ 自动补服务端前缀
                  .width(56).height(56).borderRadius(8)
                Column() {
                  Text(item.name).fontSize(16)
                  Text(`${UiConstant.mediaTypeLabelOf(item.type)} · ${item.createdAt}`)
                    .fontSize(12).fontColor(UiConstant.textSecondaryColor)
                }.alignItems(HorizontalAlign.Start).layoutWeight(1)
                Button('分析').onClick(() => {
                  const r = this.app.startAnalysis(item.id);   // ★ item.id 是字符串
                  if (!r.ok) { /* r.message 是失败原因 */ }
                })
              }
            }
          }, (item: MediaItemModel) => item.id)               // key 用 id 字符串
        }
        // 下拉刷新：用 Refresh 容器包住本 List，onRefreshing 里调 refreshMedia()
        // 媒体接口没有分页参数，一次全量返回，所以不需要"加载更多"
      }
    }
    .onAppear(() => { AppStore.get().refreshMedia(); })
  }

  @Builder
  filterChip(label: string, type: MediaType, isAll: boolean) {
    Text(label)
      .onClick(() => AppStore.get().setMediaTypeFilter(isAll ? null : type))
  }
}
```

### 4.2 详情页（某媒体的报告明细）

```ts
import { AppStore } from '../store/AppStore';
import { DiagnosisReportModel } from '../types/Index';
import { UiConstant } from '../types/Index';

@Entry
@ComponentV2
struct MediaDetailPage {
  @Computed get app(): AppStore { return AppStore.get(); }
  /** 上一页把 id、name、type 传进来 */
  private mediaId: string = '';
  private mediaName: string = '';
  private mediaType: string = '';

  aboutToAppear(): void {
    // ★ 详情接口的 path 参数是 int，内部已做转换；后两个参数只用于补写本地镜像，可传空串
    AppStore.get().reports().loadDetail(this.mediaId, this.mediaName, this.mediaType)

    Column() {

        Column({ space: 4 }) {
          Row() {
            // ★ 严重度标签与颜色都从 UiConstant 取，别自己写死中文
            Text(UiConstant.severityLabel(r.severity as string))
              .fontColor(UiConstant.severityColor(r.severity as string))
            Text(`BDI ${r.bdiScore.toFixed(2)}`).layoutWeight(1)
          }
          Text(r.detectedAt).fontSize(12)                     // "2026-06-17 21:03:44"
          Text(`推理耗时 ${r.inferenceTimeMs.toFixed(0)} ms`).fontSize(12)
          if (r.notes.length > 0) { Text(r.notes).fontSize(12) }
        }
      }, (r: DiagnosisReportModel) => `${r.id}`)
    }
  }
}
```

### 4.4 登录页

```ts
import { AppStore } from '../store/AppStore';
import { AuthRule } from '../network/AuthApi';
import { ActionResultModel } from '../types/Index';

@Entry
@ComponentV2
struct LoginPage {
  @Local isRegister: boolean = false;
  @Local username: string = '';
  @Local password: string = '';
  @Local email: string = '';
  @Local errorMsg: string = '';
  @Computed get app(): AppStore { return AppStore.get(); }

  async submit(): Promise<void> {
    // ★ 本地校验规则与后端 auth.py 完全一致，先拦一次省掉无谓往返
    const nameErr: string = AuthRule.checkUsername(this.username);
    if (nameErr.length > 0) { this.errorMsg = nameErr; return; }
    const pwdErr: string = AuthRule.checkPassword(this.password);
    if (pwdErr.length > 0) { this.errorMsg = pwdErr; return; }

    const store = AppStore.get().auth();
    this.errorMsg = '';
    const result: ActionResultModel = this.isRegister
      ? await store.register(this.username, this.password, this.email)   // 注册即登录
      : await store.login(this.username, this.password);

    if (!result.ok) {
      // ★ result.message 就是后端 detail 文案，直接展示即可（422 的数组也已摊平成中文）
      this.errorMsg = result.message;
      return;
    }
    // ★ 登录成功后要自己把数据拉起来（门面不会自动做）
    await AppStore.get().loadAll();
    this.getUIContext().getRouter().replaceUrl({ url: 'pages/Index' });
  }

  build() {
    Column({ space: 16 }) {
      TextInput({ placeholder: '用户名' }).onChange((v: string) => { this.username = v; }).maxLength(32)
      TextInput({ placeholder: '密码' }).type(InputType.Password)
        .onChange((v: string) => { this.password = v; })
      if (this.isRegister) {
        TextInput({ placeholder: '邮箱（可选）' }).onChange((v: string) => { this.email = v; })
      }
      if (this.errorMsg.length > 0) { Text(this.errorMsg).fontColor('#dc2626').fontSize(13) }

      Button(this.app.auth().loading ? '请稍候…' : (this.isRegister ? '注册' : '登录'))
        .enabled(!this.app.auth().loading)
        .onClick(() => { this.submit(); })

      Text(this.isRegister ? '已有账号？去登录' : '没有账号？去注册')
        .fontColor('#0284c7')
        .onClick(() => { this.isRegister = !this.isRegister; this.errorMsg = ''; })
    }.padding(24)
  }
}
```

登出（**后端没有 logout 接口**，登出 = 客户端删令牌 + 清缓存）：

```ts
await AppStore.get().auth().logout('');   // 传文案则会在 globalMessage 里显示
```

## 五、分析（WebSocket）怎么用

```ts
const app = AppStore.get();

// ① 开始：内部自动建连、拼 token、发 {"id":...}
app.startAnalysis(mediaId);

// ② 渲染：帧是**突发批量**到达的，不要每帧重绘图表，攒批或用 @Trace 的最终值
if (app.analyzing) {
  Text(app.analysisProgressText())                       // 进度
  Text(`${app.analysisScore.toFixed(2)}`)                // 当前分数
  Text(app.analysisSeverityLabel())                      // 严重度中文
  Image(app.analysisFaceDataUrl())                       // 人脸图（DataURL 可直接用）
}
if (app.analysisVlmText.length > 0) { Text(app.analysisVlmText) }
if (app.analysisError.length > 0) { Text(app.analysisError).fontColor('#dc2626') }

// ③ 结束：done 之后门面自动刷新 media/reports/stats，报告列表里立刻能看到新结果

// ④ 页面 aboutToDisappear() 里务必：
AppStore.get().stopAnalysis();
```

必须知道的四个坑（已由数据层处理，但会影响你怎么写 UI）：

| 现象 | 原因 | 你该怎么做 |
|---|---|---|
| `progress` 从 0 直接跳到 1 | 服务端先把整个文件算完，再突发回推 | 进度条做过渡动画，别按帧数算比例 |
| 点"取消"没反应 | 后端 `cancel` 只在帧循环期间有效，视频早就算完了 | **不要**在 UI 上承诺"可中断" |
| 断线后收到"将重新分析" | 重连会重发媒体 id，服务端从头再跑 | 提示用户会重跑，别假装是断点续传 |
| `done` 之后连接就断了 | 服务端主动 close，这是**正常收尾** | 别弹"连接已断开" |

## 六、`.ts` 与 `.ets` 的分工（改代码前必读）

| 后缀 | 放什么 | 本轮文件 |
|---|---|---|
| `.ts` | 纯类型 + 纯常量，**同时是合法 TS 与合法 ArkTS**，Web 端可直接 `import` | `types/enums.ts` `dto.ts` `model.ts` `constant.ts` `mapper.ts` `Index.ts` |
| `.ets` | 用了 ArkTS 专有能力（装饰器、ArkUI 类型、系统 Kit） | `types/storeState.ets` 及其余全部 |

**官方约束**（`arkts-no-ts-deps`）：`.ets` 可以 import `.ts`，**反向不行**。
所以共享类型**必须**是 `.ts`；也正因如此，`types/Index.ts`（`.ts`）**不能**统一导出 `storeState.ets`，
渲染层要用响应式状态类型时直接：

```ts
import { AppState, MediaState } from '../types/storeState';
```

### 驼峰与 snake_case 的边界

```
服务端 schemas.py（snake_case，不许改）
       ↓  types/dto.ts        字段名保持 snake_case，1:1 零漂移
       ↓  types/mapper.ts     逐字段手写转换（禁止对象展开）
       ↓  types/model.ts      全部驼峰 —— UI 层只认这一层
       ↓  store / UI
```

- **只有 `types/dto.ts` 允许出现 snake_case**，且仅限字段名；类型名、函数名一律驼峰。
- 服务端将来改字段 → 只改 `dto.ts` + `mapper.ts`，UI 一行不动。
- 例外：RDB 的**物理表名/列名**刻意沿用服务端 snake_case（镜像表要同构），见 `persistence/DbSchema.ets`。

### 自己加类型时

需要新类型就往 `types/model.ts` 加，然后**在 `types/Index.ts` 里显式具名导出**（不用 `export *`）：

```ts
// types/Index.ts
export { MyNewModel } from './model';
```

## 七、三种异常状态的 UI 处理建议

> 本节片段需要 `import { promptAction } from '@kit.ArkUI';`，`r` 的类型是 `ActionResultModel`。

### 7.1 未登录（`bootPhase === BootPhase.anonymous`）

- 渲染登录页；**不要**弹"请先登录"的 toast，那是骚扰。
- `globalMessage` 非空时（通常是"登录已过期，请重新登录"）弹一次，然后 `clearGlobalMessage()`。

```ts
if (this.app.globalMessage.length > 0) {
  promptAction.showToast({ message: this.app.globalMessage });
  this.app.clearGlobalMessage();
  this.getUIContext().getRouter().replaceUrl({ url: 'pages/LoginPage' });
}
```

### 7.2 离线（`offline === true` 或各 store 的 `errorMsg` 非空）

- **有本地缓存就正常渲染**（媒体/报告/统计三张表都做了镜像），只在顶部加一条细提示：
  ```ts
  if (this.app.offline) {
    Text('当前离线 · 展示本地缓存数据').fontSize(12).fontColor('#d97706')
  }
  ```
- 空数据时才提示"离线且无本地缓存"（`mediaEmptyHint()` 已经处理好了）。
- 离线时**不要**自动重试轰炸：数据层已把网络失败静默成"保留缓存"，用户下拉刷新即可重试。

### 7.3 服务端未启动

表现是所有请求都失败，最常见的原因是**地址不对**或**后端只监听 127.0.0.1**。给一个排障入口：

```ts
// 探活 + 一键改地址（放在设置页，答辩现场非常有用）
const r: ActionResultModel = await AppStore.get().checkHealth();
if (!r.ok) {
  promptAction.showToast({ message: r.message });   // 文案已含排查提示
}
await AppStore.get().changeServer('192.168.1.100', 8000);   // 改完自动探活，且持久化
```

> 真机联调前提：后端必须用局域网 IP 监听 0.0.0.0（`serve_all.py` 默认 `127.0.0.1` 手机连不上）；
> `module.json5` 的 INTERNET 权限与 `network_config.json` 明文放行本轮已配好。

## 八、我需要扩展数据层时改哪里

| 我的需求 | 改哪个文件 |
|---|---|
| 新增一个服务端接口 | `network/XxxApi.ets` 加方法（照着 `ReportApi.ets` 写），只在 `HttpClient` 之上做拼 URL |
| 服务端返回了新字段 | `types/dto.ts` 加字段 → `types/mapper.ts` 显式转换 → `types/model.ts` 加驼峰字段 |
| UI 要一个新的派生值（如"总时长"） | 加在对应领域 store 上（`MediaStore` 等），**不要**写进页面里重复算 |
| 新加一类业务数据 | 新建 `persistence/XxxDao.ets`（继承 `BaseDao<XxxModel>`）+ `store/XxxStore.ets`（继承 `BaseStore`）+ 在 `StorageManager` 里挂一个 `daoXxx` 字段与 `xxxDao()` 方法 |
| 加数据库列 | `persistence/DbSchema.ets` 改 DDL，`types/constant.ts` 的 `RDB_VERSION` **+1**，并在 `StorageManager.migrate()` 里补迁移分支 |
| 新页面要读数据 | 优先用现成的 `AppStore` 字段；确实不够再加领域 store 的 `@Trace` 字段 + 在 `AppStore.sync()` 里拉平 |

### ArkTS 血泪清单（照着做能少踩 90% 的编译错）

1. `@ObservedV2` 的字段必须 `@Trace` 才会刷新 UI；**普通 class 字段不刷新**。
2. `@Computed` 只能写在 `@ComponentV2` 里，且 V2 里用 `@Local` 而不是 `@State`。
3. 静态属性名**不能叫 `name`**（与 `Function.name` 冲突）。
4. **静态字段不要与方法同名**（报 `Duplicate identifier` + `This expression is not callable`）。
5. 不要写「`if (f === null) { f = new X() }`」的惰性单例 —— 类型收窄不生效，会报 `possibly 'null'`。改用**立即初始化**。
6. 对象字面量**必须有明确的类型标注**，且不能用来初始化"带参构造的类"或"带方法的接口"（回调请用抽象类）。
7. 没有对象展开 `{...obj}`、没有 `any`、没有正则字面量（用 `new RegExp`）、没有 `Pick/Omit/Exclude`。
8. 泛型实参**必须显式写**，不能靠返回值推断。
9. 两个形状相同的 interface **不能互相赋值**（不支持结构化类型）—— 要么共用同一个 interface，要么显式转换。
10. `Record<string, T>` 的取值类型若要允许 `null`，必须写成 `Record<string, T | null>`。
