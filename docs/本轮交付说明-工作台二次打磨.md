### 2.3 为什么首帧照片要单独存一份字段（`firstFrameFace`）

`AnalysisSessionModel.frames` 会为省内存被**从头部裁剪**（live 上限 90 帧，收尾后裁到 30 帧）。
视频跑完一次后 `frames[0]` 早已不是真正的第一帧，而工作台卡片要展示的恰恰是"这次分析的第一帧"。
所以首帧图单独存、**永不裁剪**（一张 128×128 JPEG 约 5–15KB）。

取值顺序（全在 `AppStore.currentTask()` 里决定，组件不做判断）：

```
① 会话首帧对齐人脸（data URL）   图片 = 那唯一一帧；视频 = 采样出的第一帧
② 图片的媒体缩略图                首帧还没到时先顶上（后端会为图片生成缩略图）
③ 空串                            视频刚上传、还没收到帧 → 组件画「视」占位块
```

## 3. 交互口径（为什么这样设计）

### 3.1 离线横幅什么时候出现

```ts
showOfflineBanner = healthChecked && !serverOnline
```

- `healthChecked`：**至少完成过一次探活**。`serverOnline` 默认 `false`，只看它会让每次冷启动
  先闪一条"连不上"的假告警；加上这个位就只有"真的探活过且失败"才提示。
- 探活**进行中不隐藏**横幅，只把按钮文字变成「重连中…」并禁用。
  否则用户点「重试」会看到横幅消失又出现，像页面在抽搐。
- 保留「重试」按钮：它是离线态下用户唯一的主动重连入口，与右上角刷新指向同一个回调。

### 3.2 一根进度条只表达一件事

旧卡片在「分析中」时用进度条表示**分析进度**，跑完再换成大分数。
本轮用户要的是"进度条填充表示 BDI"，所以：

- **进度条 = BDI 档位**（条长 `BDI/63`、颜色四档色），任何状态下含义不变；
- **分析进度降级成文字**，写在状态标签里（「分析中 42%」）。

一根条同时表示"跑了多少"和"病得多重"，会让人没法判断它到底在说什么。

### 3.3 没有分数时不显示「正常」

`score <= 0` 时 `severityLabel` 给空串、`severityColor` 给中性灰、`scoreRatio` 给 0
（分数文案给 `--`）。这样"还没算出来"不会被读成"结果正常"。

## 4. 已知边界（本轮不做）

1. **当前任务仍然只在内存里**：杀进程/重装后消失（本工程既有决策 D9，本轮未改）。
2. **视频的唯一图像来源是首帧对齐人脸**：后端不给视频缩略图，所以视频"还没收到第一帧"时
   卡片只有一个「视」字占位块。要更好看需要后端提供视频封面帧。
3. **首帧照片是"对齐后人脸"**（128×128 的裁剪图），不是原视频原图。理由是 WS 帧里只有这张图；
   若想显示原图，需要额外下载 `media.url` 再解码，本轮不做。
4. 离线横幅没有"重新探活成功后的成功提示"：连上后它直接消失（符合"只在离线时提示"的要求）。

## 6. 给下一位接手者

- 改工作台卡片时先看 `BUG清单.md` **BUG-19**：`@Builder` 接业务参数 = 值不更新，
  这个坑**编译一定能过**，只有装机截图（或对色检查）能发现。
- 想加"服务在线"这类常驻状态元素前请先确认：用户明确要求**只提示异常**，正常状态不占界面。
- BDI 相关的一切比例/颜色都走 `BdiThreshold` + `UiConstant.severityMeta()`
  （分母 `BDI_MAX_SCORE = 63`），不要再写第二套色板或除数。
