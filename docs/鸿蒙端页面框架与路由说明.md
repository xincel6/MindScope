# MindScope 鸿蒙端 · 页面框架与路由说明

> 本轮交付：**Navigation 路由骨架 + 登录/注册页 + 五个一级页面占位**
> 适用对象：继续写 UI 的开发者、接入真实数据的开发者、code review 者。
> 配套文档：`docs/鸿蒙端数据获取使用指南.md`（数据怎么取）、`docs/本轮交付说明-页面框架.md`（本轮验收）。

## 一、三十秒上手

```
应用入口：pages/Index.ets（唯一 @Entry）
  ├─ 引导中（骨架屏）
  ├─ 未登录 → 登录流 Navigation：Login ⇄ Register
  └─ 已登录 → 主界面 Navigation：工作台 / 素材库 / 历史报告 / 统计 / 我的
```

写一个新页面的完整流程（三步，全部不用碰既有页面）：

```ts
// ① pages/ 下新建一个文件：XxxPage.ets（界面）
// ② types/PageParams.ets 里加一个参数类，声明这个页面需要什么、能做什么
// ③ pages/PageRoutes.ets 加路由名 → 在窗口层（Index.ets 或 MainPage.ets）的分发器里加一个分支
```

## 二、目录结构（**所有页面统一放在一个 `pages` 目录里**，不再层层套文件夹）

```
harmony/entry/src/main/ets/
├── pages/                             ★ 全部页面代码只在这一个目录
│   ├── Index.ets                      Ability 入口页 / 应用外壳（阶段分支），main_pages.json 注册的就是它
│   ├── LoginPage.ets                  登录界面（纯展示）
│   ├── RegisterPage.ets               注册界面（纯展示，与登录页相互独立）
│   ├── MainPage.ets                   ★ Navigation 容器 + 底部五个按钮
│   ├── WorkbenchPage.ets              工作台（占位）
│   ├── MediaLibraryPage.ets           素材库（占位）
│   ├── ReportsPage.ets                历史报告（占位）
│   ├── StatsPage.ets                  统计（占位）
│   ├── ProfilePage.ets                我的（占位）
│   └── PageRoutes.ets                 ★ 全部路由名 + 页签元数据（顺序/中文名/字形）
├── types/
│   └── PageParams.ets                 ★ 全部页面参数契约（每个页面需要什么、能做什么）
├── components/                        6 个复用组件（不是页面，不进页面注册表）
│   ├── AppCard.ets                    卡片容器（白底 / 8vp 圆角 / 投影）
│   ├── PageHeader.ets                 页头（22vp 标题 + 可选返回）
│   ├── LogoPlaceholder.ets            ★ 品牌图标占位（后期换真图标只改这里）
│   ├── SkeletonView.ets               骨架屏（SkeletonBlock / AuthSkeleton / MainSkeleton）
│   ├── PlaceholderView.ets            一级页面统一占位骨架（含"下一步操作"）
│   └── ErrorRetryView.ets             错误 + 重试按钮
└── common/
    └── UiTheme.ets                    ★ 全工程唯一视觉常量来源（颜色/字号/间距/圆角）
```

**为什么分散成三处**（而不是全部塞进 `pages/`）：

| 放哪 | 放什么 | 理由 |
|---|---|---|
| `pages/` | 页面组件 + `PageRoutes.ets` | "页面"与"页面之间怎么走"同域，新增页面只动这个目录 |
| `types/PageParams.ets` | 全部页面参数类 | 参数是**数据类型**，按工程既有规矩（`types/` 是所有数据类型的唯一目录）归位；集中一份便于"看接口不用翻页面源码" |
| `components/` | 复用 UI 组件 | 它们不是页面、不进页面注册表，多个页面 import 使用 |
| `common/UiTheme.ets` | 视觉令牌 | 与数据类型的改动理由不同，单独一处便于统一调色 |

> 文件命名即页面名（`LoginPage` / `MainPage` / `WorkbenchPage` …），
> 一个页面一个文件；要新增页面就在 `pages/` 加两个文件（页面 + 在 `PageParams.ets` 加参数类）。

## 三、页面参数契约（★ 核心约定）

### 3.1 三条页面纪律

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | 页面一律 `@ComponentV2`，只读 `@Param`，**不 import 任何 store** | 页面只负责"拿到什么画什么"，数据来源可替换 |
| 2 | 页面要展示的一切都来自参数对象（文案 / 忙碌态 / 错误 / 回调） | 直接传参即可展示，便于预览与单测 |
| 3 | 页面要产生的动作都通过参数里的回调交回窗口层 | 页面不认识网络、路由、登录态 |

> **窗口层**＝唯一允许触碰 store 与路由栈的 UI 文件：`pages/Index.ets`（登录流）与
> `pages/MainPage.ets`（主界面）。它们是"页面参数的唯一构造方"。

> 每个页面的参数类都写在**同一个文件** `types/PageParams.ets` 里，并按页面用注释分区，
> 因此"这个页面要传什么参数"看这一份就够，不用逐个翻页面源码。

### 3.2 逐步契约表（全部定义在 `types/PageParams.ets`）

| 页面 | 参数类 | 字段 |
|---|---|---|
| 登录页 | `LoginPageParam extends PageParam` | `onLogin: AuthAction`、`onRegister: AuthAction`、`onRetry: () => Promise<string>`、`authBusy: boolean`、`authError: string`、`retryMessage: string`、`retrying: boolean` |
| 注册页 | `RegisterPageParam extends PageParam` | `onRegister: AuthAction`、`onBackToLogin: () => void`、`authBusy`、`authError`、`presetUsername`、`presetPassword` || 主界面 | `MainPageParam extends PageParam` | `signedIn: boolean`、`userName: string`、`serverLabel: string` |
| 工作台 / 素材库 / 历史报告 / 统计 | `TabPageParam extends PageParam` | `activeTab: MainTab`、`busy: boolean`、`errorMsg: string`、`pathStack: NavPathStack \| null` |
| 我的 | `ProfilePageParam extends TabPageParam` | 上面四个 + `userName`、`serverLabel`、`onLogout: () => void`（本轮不赋值） |

公共类型：

```ts
/** 五个一级页签 · 枚举值即路由名 */
export enum MainTab { workbench='workbench', media='media', reports='reports', stats='stats', profile='profile' }

/** 鉴权动作 · 返回 true 表示成功 */
export type AuthAction = (username: string, password: string, email: string) => Promise<boolean>;
```

### 3.3 错误文案的显示规则

登录页与注册页对 `authError` 的显示有一条**由页面自己实现**的规则（不需要窗口层配合）：

- 本地校验提示（`AuthRule` 拦下的）**优先**于服务端返回的错误；
- 用户一旦重新输入，上一次已展示过的服务端错误就**收起**（否则看起来像"我的修改没生效"）；
  实现方式是页面本地存一个"已展示错误快照"，**不回头去清 `AuthStore.errorMsg`** ——
  页面不回写 store 是本工程的纪律；
- 重新点提交时快照清零，服务端若再报同样的错，会重新显示。

窗口层不需要为此做任何事，`authError` 照常填 `AuthStore.errorMsg` 即可。

### 3.4 最小示例：把页面单独跑起来

```ts
const param = new LoginPageParam();
param.onLogin = async (u, p, e) => { /* 任意实现，返回 boolean */ return true; };
param.authBusy = false;
param.authError = '';
// 直接放进任意容器即可渲染，不需要 store、不需要网络、不需要路由
LoginPage({ pageParam: param })
```

## 四、路由设计

### 4.1 两条互相独立的导航栈

| 分支 | 栈 | 起始路由 | 页面 |
|---|---|---|---|
| 登录流 | `Index.loginStack` | `login` | 登录页 → 注册页 |
| 主界面 | `MainPage.navStack` | `workbench` | 五个页签（+ 下一轮的二级页面） |

**为什么分两个栈**：分支切换时旧栈整体销毁，所以"登录成功后返回键回到登录页"这种情况
从结构上就不可能出现，不需要 `replaceUrl`、也不需要额外的清栈动作。

### 4.2 登录态切换是"数据驱动"的

```
AuthStore.login/register 成功 → AuthStore.signedIn=true
        ↓ AppStore.sync()
AppStore.signedIn（@Trace）
        ↓ Index.@Computed phase
界面自动从"登录流"换成"主界面"（无需任何显式跳转指令）
```

同理，**登出**（下一轮做）只要调 `AuthStore.logout()`，界面会自动回到登录页。

### 4.3 页签切换

```ts
// MainPage.pushTab()
this.navStack.replacePathByName(tab as string, param);   // 栈深恒定为 1
```

- 底部五个按钮来回点**不会堆积历史**（二级页面才用 `pushPathByName`）。
- 当前页签高亮由 `MainPage.selectedTab` 驱动，按钮点击时更新。
- 想改成"保留页签栈"（每个页签各自记住浏览位置）就把 `replacePathByName` 换成
  `pushPathByName(..., { launchMode: LaunchMode.MOVE_TO_TOP_SINGLETON })`。

### 4.4 路由分发的写法（ArkTS 约束下的标准模式）

```ts
@Builder
loginDestination(name: string, param: ESObject) {
  if (name === LOGIN_ROUTE && param instanceof LoginPageParam) {
    NavDestination() {
      LoginPage({ pageParam: param as LoginPageParam })
    }.hideTitleBar(true).backgroundColor(UiTheme.pageBackground)
  } else if (...) { ... }
}
```

三条必须遵守的细节：

1. **参数类型写 `ESObject`**：官方签名是 `param: unknown`，而 ArkTS 禁止 `unknown`/`any`
   （`arkts-no-any-unknown`），`ESObject` 是 ArkTS 给"动态类型"的合法出口。
2. **先 `instanceof` 再 `as`**：硬 `as` 会掩盖"路由名与参数类型不匹配"的 bug。
3. **一个 `NavDestination` 一个页面**，`.hideTitleBar(true)` 后标题由页面的 `PageHeader` 自绘，
   以保证 22vp / `#1E3A5F` 完全符合设计规范。

| `primary` | `#0D9488` | 主按钮 / 选中态 / 主强调 |

## 六、给"接真实数据"的开发者

五个占位页的 `TabPageParam` 已经预留了 `busy`（骨架屏）与 `errorMsg`（错误 + 重试）两个字段。
接入数据时只需要在窗口层填值、在页面里加分支：

```ts
// 窗口层（MainPage）：把 store 状态投影到参数
param.busy = AppStore.get().mediaLoading;
param.errorMsg = AppStore.get().mediaError;

// 页面（MediaLibraryPage）：三分支
if (this.pageParam.busy) {
  MainSkeleton()
} else if (this.pageParam.errorMsg.length > 0) {
  ErrorRetryView({ message: this.pageParam.errorMsg, onRetry: () => { /* 回窗口层 */ } })
} else if (items.length === 0) {
  PlaceholderView({ ... })          // 空数据 → 下一步操作
} else {
  // 真实列表
}
```

各页面对应的数据源见 `docs/鸿蒙端数据获取使用指南.md` 第三节；每个占位页的注释里也写了
"下一轮接哪个字段"。

## 七、ArkTS 踩坑记录（本轮新增，照着做能省一次编译）

| # | 坑 | 现象 | 正确写法 |
|---|---|---|---|
| 1 | `@Param` 字段名与系统属性同名 | `Property 'padding' in type 'AppCard' is not assignable to the same property in base type 'CustomComponent'` | 入参名加 `_` 前缀：`_padding` / `_size` / `_background` |
| 2 | `navDestination` 回调的 `param` | `Use explicit types instead of "any", "unknown" (arkts-no-any-unknown)` | 形参写 `ESObject` |
| 3 | `@Builder` 方法体内调普通方法 | `'this.xxx()' does not meet UI component syntax` | 只能在状态收敛点（await 之后）调普通方法 |
| 4 | `@Param` 传对象 | 每次 `build()` 都 `new` 一个新对象 → 入参被整体重置、子树冗余重建 | 参数对象**构造一次**并缓存，之后只改字段 |
| 5 | `NavPathStack` 的 import | `@kit.ArkUI` 并未导出它 | 它是**全局声明类型**，直接用类型名，不要 import |
| 6 | `@Styles` / `@Extend` 跨文件 | 全局声明在 V2 组件里能否生效没有把握 | 本轮改用 `AppCard` / `PageHeader` 等组件替代，零风险 |
| 7 | `@BuilderParam` | 不传尾随闭包时编译失败 | 必须给默认实现（见 `AppCard.emptyContent`） |
