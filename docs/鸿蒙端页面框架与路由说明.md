## 一、三十秒上手

```text
应用入口：pages/Index.ets（唯一 @Entry，应用外壳 / 窗口层）
  ├─ 开屏页 SplashView（覆盖层，引导完成后淡出）
  ├─ 引导中（bootPhase = idle / preparing）→ 骨架屏
  ├─ 未登录 → 登录流 Navigation(loginStack)：Login ⇄ Register
  └─ 已登录 → 主界面 Navigation(mainStack)：MainPage
        ├─ 五个一级页签：工作台 / 素材库 / 历史报告 / 统计 / 我的
        ├─ mediaPicker（二级页，push）
        └─ analysisDetail（二级页，push，仅历史报告进入）
```

新增一个页面的完整流程：

```text
① pages/ 下新建 XxxPage.ets（界面，@ComponentV2，只读 @Param）
② types/PageParams.ets 里加 XxxPageParam，逐字段注释
③ pages/PageRoutes.ets 加路由名 → 在窗口层（Index.ets 或 MainPage.ets）的分发器里加分支
```

> 页面代码全部在 `pages/` **单层目录**；参数契约全部在 `types/PageParams.ets`；
> 视觉令牌全部在 `common/UiTheme.ets`。新增页面只动这三处 + 窗口层的分发器。

**为什么这样分：**

| 放哪 | 放什么 | 理由 |
|---|---|---|
| `pages/` | 页面 + 路由元数据 | “页面”与“页面之间怎么走”同域，新增页面只动这个目录 |
| `types/PageParams.ets` | 全部页面参数类 | 参数是数据类型，集中一份便于“看接口不用翻页面源码” |
| `components/` | 复用 UI 组件 | 不是页面、不进页面注册表 |
| `common/UiTheme.ets` | 视觉令牌 | 与数据类型的改动理由不同，单独一处便于统一调色 |

## 三、页面参数契约（核心约定）

### 3.1 三条页面纪律

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | 页面一律 `@ComponentV2`，只读 `@Param`，**不 import 任何 store** | 页面只负责“拿到什么画什么”，数据来源可替换 |
| 2 | 页面展示的一切都来自参数对象（文案 / 忙碌态 / 错误 / 回调） | 直接传参即可展示，便于预览与单测 |
| 3 | 页面产生的动作都通过参数回调交回窗口层 | 页面不认识网络、路由、登录态 |

**窗口层**＝唯一允许触碰 store 与路由栈的 UI 文件：`pages/Index.ets` 与 `pages/MainPage.ets`。

> **两处已记录的例外**（不是回归，新页面不要照抄）：
> 1. `WorkbenchPage` 直接读 `AppStore` 的实时会话（探活 / WS 逐帧 / 进度 / 分数是异步到达的，经 `navDestination` 改参数字段不会刷新已挂载页面）；
> 2. `AnalysisDetailPage` 按 `mediaId` 读 `AppStore` 会话，**只读**、不写，动作仍走回调。
>
> 两处的共同判据：**这段数据在页面挂载之后还会变吗？** 会 → 必须走 `@Trace`，不能只走参数。

### 3.2 参数类一览（全部在 `types/PageParams.ets`）

| 页面 | 参数类 | 主要字段 |
|---|---|---|
| 登录 | `LoginPageParam`（`@ObservedV2`） | `onLogin` / `onRegister` / `onRetry`、`authBusy`、`authError`、`authErrorTitle`、`authErrorHint`、`retryMessage`、`retrying`、`serverLabel`（`@Trace`） |
| 注册 | `RegisterPageParam`（`@ObservedV2`） | `onRegister` / `onBackToLogin`、`authBusy`、`authError`、`authErrorTitle`、`authErrorHint`、`presetUsername`、`presetPassword` |
| 主界面 | `MainPageParam` | `signedIn`、`userName`、`serverLabel`、`onLogout` |
| 页签公共 | `TabPageParam` | `activeTab`、`busy`、`errorMsg`、`pathStack` |
| 素材库 | `MediaLibraryPageParam`（`@ObservedV2`） | `videos`、`images`、`patients`、`selectedPatient`、`selectedMediaId`、`analyzing`；`onUpload` / `onOpenMedia` / `onDelete` / `onRetry` / `onSelectPatient` / `onRename` |
| 我的 | `ProfilePageParam` | `userName`、`email`、`accountId`、`registeredAt`、`serverLabel`、`appVersion`、`onLogout` |
| 工作台 | `WorkbenchPageParam`（`@ObservedV2`） | `onRefresh` / `onSelectMedia` / `onReanalyze` / `onCancelAnalysis`；`scrollTopTick`、`refreshing`（`@Trace`） |
| 素材选择 | `MediaPickerPageParam`（`@ObservedV2`） | `title`、`onPickRequest` / `onUpload` / `onBack`；`hasPicked`、`pickedName`、`pickedIsVideo`、`pickedUri`、`uploading`、`errorMsg`（`@Trace`） |
| 历史报告 | `ReportsPageParam` | `onRefresh`、`onFilter`、`onOpenReport` |
| 分析详情 | `AnalysisDetailPageParam` | `mediaId`、`mediaName`、`mediaType`、`reportScore`、`reportTime`；`onBack` / `onCancelAnalysis` / `onReanalyze` |

公共类型：

```ts
/** 五个一级页签 · 枚举值即路由名 */
export enum MainTab { workbench = 'workbench', media = 'media', reports = 'reports', stats = 'stats', profile = 'profile' }

/** 鉴权动作 · 返回 true 表示成功 */
export type AuthAction = (username: string, password: string, email: string) => Promise<boolean>;
```

### 3.3 参数类要不要 `@ObservedV2`：只有一条判据

> **给字段赋值的那一行，是在页面 `NavDestination` 挂载之后执行的吗？**

| 答案 | 处理 | 例子 |
|---|---|---|
| 是（异步返回 / 用户操作后才回填） | 类必须 `@ObservedV2`，该字段必须 `@Trace` | `LoginPageParam`、`RegisterPageParam`、`MediaLibraryPageParam`、`WorkbenchPageParam`、`MediaPickerPageParam` |
| 否（push 之前写一次、之后不变） | 保持普通 class，**不要**顺手加装饰器 | `ProfilePageParam`、`TabPageParam`、`ReportsPageParam`、`AnalysisDetailPageParam` |

> 这条判据来自 BUG-10 / BUG-11；BUG-21 是“整类打包下结论”导致的复发。
> 登录页参数确实在冷启动时入栈一次，但它的字段是**之后每一次点登录**才回填的。
> 逐字段核对，不要按“哪一类页面”判断。

### 3.4 错误文案的显示规则

登录页与注册页对 `authError` 的显示由页面自己实现（不需要窗口层配合）：

- 本地校验提示（`AuthRule` 拦下的）**优先**于服务端错误；
- 用户一旦重新输入，上一次已展示过的服务端错误就**收起**（否则看起来像“我的修改没生效”）；
- 实现方式是页面本地存一个“已展示错误快照”，**不回头去清 `AuthStore.errorMsg`** —— 页面不回写 store 是本工程纪律；
- 重新点提交时快照清零，服务端若再报同样的错，会重新显示。

### 3.5 最小示例：把页面单独跑起来

```ts
const param = new LoginPageParam();
param.onLogin = async (u, p, e) => { /* 任意实现，返回 boolean */ return true; };
param.authBusy = false;
param.authError = '';
// 直接放进任意容器即可渲染，不需要 store、不需要网络、不需要路由
LoginPage({ pageParam: param })
```

## 四、路由与导航

### 4.1 两条互相独立的导航栈

| 分支 | 栈 | 起始路由 | 页面 |
|---|---|---|---|
| 登录流 | `Index.loginStack` | `login` | 登录页 → 注册页 |
| 主界面 | `MainPage.navStack` | `workbench` | 五个页签 + `mediaPicker` + `analysisDetail` |

**为什么分两个栈**：分支切换时旧栈整体销毁，“登录成功后返回键回到登录页”从结构上不可能出现，不需要 `replaceUrl` / 清栈动作。

### 4.2 登录态切换是“数据驱动”的

```text
AuthStore.login / register 成功 → signedIn = true
        ↓ AppStore.sync()
AppStore.signedIn（@Trace）
        ↓ Index.@Computed phase
界面自动从“登录流”换成“主界面”（无需显式跳转）

登出 → AuthStore.logout() → signedIn = false → 自动回登录流
```

登录失败弹窗 / 开屏页 / 退出登录的完整链路见 [交付记录](交付记录.md) 2026-10-17 条目。

### 4.3 页签切换

```ts
// MainPage.pushTab() 的核心顺序
transit.exitClock += 1;                    // ① 各卡按 order 开始离场
setTimeout(() => {
  this.selectedTab = tab;
  this.navStack.replacePathByName(tab as string, this.buildTabParam(tab));  // ② 动画播完才换页
}, CardTransit.sequenceMs(this.cardCountOf(this.selectedTab)));
```

- 栈深恒定为 1，底部五个按钮来回点**不会堆积历史**。
- 二级页面用 `pushPathByName`，系统返回键即可回到当前页签。
- 换页**必须等离场动画播完**：`replacePathByName` 在换页那一帧就销毁旧页，`customNavContentTransition` 也留不住它（实测证据见 [参考/页签横移动画评估记录](参考/页签横移动画评估记录.md)）。

### 4.4 分析详情页为什么还在

工作台重构原本删除了独立详情页；历史报告需要一个“按任意报告查看”的入口，而工作台的 `focus` 只服务“当前任务 / 最新一条报告”，无法按任意报告取数。因此：

- **工作台**：分析内容内联在主页面；
- **分析详情页**：只从历史报告卡进入，展示该素材的报告快照；本机有会话则展示逐帧结果，否则提示“逐帧数据未保留”并给「重新分析」。

### 4.5 路由分发的写法（ArkTS 约束下的标准模式）

```ts
@Builder
destination(name: string, param: ESObject) {
  if (name === MEDIA_PICKER_ROUTE && param instanceof MediaPickerPageParam) {
    NavDestination() {
      MediaPickerPage({ pageParam: param as MediaPickerPageParam })
    }.hideTitleBar(true).backgroundColor(UiTheme.pageBackground)
  } else if (name === ANALYSIS_DETAIL_ROUTE && param instanceof AnalysisDetailPageParam) {
    // ...
  }
}
```

三条必须遵守的细节：

1. **参数类型写 `ESObject`**：官方签名是 `param: unknown`，ArkTS 禁止 `unknown` / `any`，`ESObject` 是合法出口。
2. **先 `instanceof` 再 `as`**：硬 `as` 会掩盖“路由名与参数类型不匹配”的 bug。
3. **一个 `NavDestination` 一个页面**：`.hideTitleBar(true)` 后标题由 `PageHeader` 自绘，保证字号 / 颜色符合规范。

## 五、转场与交互

### 5.1 错峰入场 / 离场

| 组件 | 职责 |
|---|---|
| `common/CardTransit.ets` | 只发信号与节拍：`exitClock`、`dir`、`cardMs`、`stepMs`、`exitTravel`、`sequenceMs()`、`CARDS_*` |
| `components/RevealCard.ets` | 每个块自己持有位移 / 透明度 / 缩放；`onAppear` 播入场，`@Monitor(exitClock)` 播离场 |
| `pages/*Page.ets` | 把顶层块依次包进 `RevealCard({ order })`，`order` 从 0 连续 |

**计数契约**（`CardTransit.CARDS_*` 的语义是“参与离场的组件数”，不是页面里 `RevealCard` 的总个数）：

| 页面 | 值 | 组成 |
|---|---|---|
| 工作台 | 7 | 页头 / hero / 开始评估 / 热力图 / 曲线 / 分布 / 解读 |
| 统计 | 7 | 页头 / 核心卡 / 三小卡 / 环形图 / 折线 |
| 历史报告 | 3 | 页头 / 筛选栏 / 列表区整块（每张卡只播入场，不计入） |
| 我的 | 3 | 页头 / 账户卡 / 退出区 |
| 素材库 | 2（仅等待值） | 页面当前**未挂** `RevealCard`；`cardCountOf()` 走 `CARDS_PLACEHOLDER = 2`，切页只等这段时间，没有逐块动画 |

节拍：`cardMs = 240ms`、`stepMs = 110ms`；入场曲线 `easeOutExpo`，离场 `ease-in`，透明度单独收尾；离场距离统一 `420vp`（大于屏宽，保证“滑出屏幕之后才淡没”）。

### 5.2 按压反馈

- `RippleCard` 使用 ArkUI 原生 `clickEffect` + 按下底色 `cardPressTint` + 可选 `_pressScale(0.98)`；
- 手绘涟漪方案已撤回（BUG-01：装饰元素影响布局测量，导致卡片变长）；
- 统计页 4 张卡也套 `RippleCard`，但 `_enabled: false`，只表达“被按到”，不承担跳转。

### 5.3 没有“两页同屏横移”

仓库里评估过“轨道容器”横移方案（旧页左移、新页右滑入），它与逐卡错峰入场**互斥**：页面常驻后 `RevealCard` 的入场动画不会重播。当前版本选择保留错峰入场，离场做成“整页同速滑出、滑出后换页”。

## 六、视觉规范（改 UI 只改 `common/UiTheme.ets`）

### 6.1 颜色

| 令牌 | 值 | 用途 |
|---|---|---|
| `pageBackground` | `#F2F3F7` | 页面背景（白卡要浮起来，页底不能也是白的） |
| `cardBackground` | `#FFFFFF` | 卡片背景 |
| `primary` | `#0D9488` | 主按钮 / 选中态 / 主强调 |
| `accent` | `#0284C7` | 次要按钮 / 文字链接 / 信息强调 |
| `textPrimary` | `#1D2129` | 正文 |
| `textSecondary` | `#4E5969` | 次要文字 / 未选中态 |
| `danger` | `#DC2626` | **仅错误提示**，不做装饰 |
| `dangerSoft` | `#FEF2F2` | 失败弹窗浅红底 |
| `divider` | `#E5E6EB` | 分隔线 |
| `fillSoft` | `#E9EDF3` | 输入框底 / 缩略图底 / 进度条轨道 |
| `skeletonFill` | `#DCE3EC` | 骨架块 / 空态图标底（必须比 `fillSoft` 深一档） |
| `cardPressTint` | `#F2F8F7` | 卡片按下底色 |

**两套“红”必须分清：**

1. `danger`（`#DC2626`）—— 错误危险色，只用于失败提示；
2. 严重度色阶（`#16a34a / #0284c7 / #d97706 / #dc2626`）—— **数据表达色**，定义在 `types/constant.ts` 的 `UiConstant.severityMeta()`，可以大面积出现在进度条、图例、图表上。

两者语义不同：一个是“出错了”，一个是“病情到这个档位了”，数值相同也不得互换引用。

| 令牌 | 值 | 用途 |
|---|---|---|
| `cardRadius` | `16` | 卡片圆角 |

| `logoRadius` | `20` | 品牌图标占位 |
| `cardShadowEnabled` | `true` | 投影总开关 |
| `cardShadowRadius` / `OffsetY` | `14` / `3` | 极淡投影 |
| `cardShadowColor` | `#141D2129` | 8 位 ARGB，alpha ≈ 8%；**不要**再塞 `opacity` 字段（`ShadowOptions` 没有该字段） |
| `fontSizeTitle` | `22` | 页面标题 |
| `fontSizeSection` | `16` | 卡片 / 区块标题 |
| `fontSizeBody` | `14` | 正文（规范下限） |
| `fontSizeCaption` | `12` | 仅字段级辅助说明 |

| `fontSizeCardMetric` | `24` | 卡片内关键数值 |

### 6.3 层次的三件套

**浅灰页底 + 纯白卡片 + 极淡投影**。投影负责让白卡从灰底上浮起来；卡片内部“再嵌一层”的元素（输入框、缩略图底、进度条轨道）没有投影可用，一律用 `fillSoft` / `divider` 描边或填底。

> 全工程只有 `UiTheme.ets` 允许出现十六进制色值（数据表达色在 `types/constant.ts`）。
> 自查：`grep -r "#[0-9A-Fa-f]\{6\}" --include=*.ets`，其余命中应只在注释里。

### 6.4 品牌图标占位

`components/LogoPlaceholder.ets` 渲染“主色圆角方块 + 心字”。换真图标**只改这一个文件**：

## 七、ArkTS 踩坑记录（改 UI 前照着避）

| # | 坑 | 现象 | 正确写法 |
|---|---|---|---|
| 1 | `@Param` 字段名与系统属性同名 | `Property 'padding' ... is not assignable to the same property in base type 'CustomComponent'` | 入参名加 `_` 前缀：`_padding` / `_size` / `_background` |
| 2 | `navDestination` 回调的 `param` | `arkts-no-any-unknown` | 形参写 `ESObject` |
| 3 | `build()` / `@Builder` 体内声明局部变量 | 报 `Unexpected token` / “只能有一个根节点”等误导性错误 | 取值放进 `@Computed` getter，或在调用处 `as` 收窄 |
| 4 | `@Param` 传对象 | 每次 `build()` 都 `new` 一个新对象 → 入参被整体重置、子树冗余重建 | 参数对象**构造一次**并缓存，之后只改字段 |
| 5 | `NavPathStack` 的 import | `@kit.ArkUI` 未导出 | 它是**全局声明类型**，直接用类型名，不要 import |
| 6 | `@Builder` 按值传业务参数 | 卡片“一半新一半旧”，编译必过、只有装机可见（BUG-19） | `@Builder` 一律无参，取值走 `@Computed` |
| 7 | 装饰元素影响布局 | 点一下卡片变长 / 整片空白（BUG-01 / BUG-07） | 动画只动 `translate / scale / opacity`；装饰层不参与测量 |
| 8 | `@Computed` 依赖未建立 | 数据到了但界面不刷新（BUG-23） | 即使无数据也要先读一次 `@Trace` 源，不能提前 return |
| 9 | `@Monitor` 里同步调 `animateTo` | 离场动画“一帧跳到终态” | 推迟一帧（`setTimeout(..., 16)`）再启动 |
| 10 | `layoutWeight` 被包装层吞掉 | 三卡不再等宽 / 布局跳动 | 权重挂在 `RevealCard._weight`，卡内用 `.width('100%')` |
| 11 | `CustomDialogController` 由 `@CustomDialog` 内部持有 | V2 页面里取不到注入值，点确定崩溃（BUG-24） | **页面持有 controller**，确认 / 取消回调到页面统一关闭 |
| 12 | 8 位 ARGB 色值 | 旧结论“会让卡片不渲染”已被证伪；真正原因是共享 `AttributeModifier` | 8 位 ARGB 可用；不要给 `ShadowOptions` 塞 `opacity` |
| 13 | `@ObservedV2` 字段漏 `@Trace` | 挂载后改字段 UI 不刷新（BUG-10/11/21） | 按 3.3 节判据逐字段核对 |
| 14 | 返回键把根页面弹掉 | 登录页整屏纯白（BUG-22） | 根页面 `NavDestination.onBackPressed(() => true)` + 根内容自愈入栈 |
