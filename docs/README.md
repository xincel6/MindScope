## 四、文档规范（新增 / 修改文档时遵守）

### 4.1 统一结构

```markdown
# MindScope 鸿蒙端 · <主题>

> 文档状态：现行 / 参考 / 历史 / 归档 ｜ 更新时间：YYYY-MM-DD ｜ 对应提交：<hash>
> 用途：一句话说明读者能用它做什么。
> 关联：<相关文档链接>

---

## 一、<一级标题>
### 1.1 <二级标题>
```

- **标题**：`# MindScope 鸿蒙端 · 主题`；交付记录用 `# 交付记录 · 主题`。不用“本轮”“最新”等会过期的词。
- **元信息**：统一用引用块，至少写状态、更新时间、对应提交 / 范围。
- **章节编号**：一级 `## 一、`，二级 `### 1.1`；表格用于字段、路由、参数、验证项。
- **代码块**：必须标语言（```ts / ```bash / ```text）。
- **状态词**：只使用 **现行 / 参考 / 历史 / 归档** 四个词，含义见 4.2。
- **结尾**：现行文档应有“验证”或“已知边界”；交付记录固定以“遗留”收尾。
- **例外**：`参考/` 与 `归档/` 保留原文结构与编号（它们记录的是当时的写法），不强制重排。

### 4.2 状态词含义

| 状态 | 含义 | 代码变更时 |
|---|---|---|
| ✅ 现行 | 描述当前代码的真实行为 | **必须同步更新** |
| 📚 参考 | 专题分析、方案评估、实现指南 | 可不更新，但要标注适用范围 |
| 🗂 历史 | 当时的交接 / 决策记录 | 不更新，加“历史基线”提示 |
| 📦 归档 | 原始长文，只读留档 | 不更新 |

### 4.3 更新流程

1. 改完代码先跑构建与契约测试（命令见《开发进度》第八节）。
2. 更新《开发进度》的功能矩阵 / 已知边界 / 验证状态。
3. 涉及页面、参数、路由、视觉令牌 → 更新《页面框架与路由说明》。
4. 涉及 store 字段 / 方法、持久化、异常态 → 更新《数据获取使用指南》。
5. 涉及接口 → 更新《接口清单》并在文末追加带日期的“增量”。
6. 每轮交付在《交付记录》追加一条，格式固定；原始长文放 `归档/交付说明/`。
7. 缺陷写进根目录 [BUG 清单](../BUG清单.md)，同时在交付记录里引用编号。

### 4.4 链接约定

- 文档之间用**相对路径**：`docs/参考/xxx.md` 内引用同级用 `../xxx.md`。
- 代码 / 命令 / 文件名用反引号；路径含中文时直接写，不转义。
- 不链接 `_materials/`（已被 `.gitignore` 排除，只在本机存在）。
