## 1. 诉求①：登录匹配到底哪里出问题 —— 已核实

### 1.1 核实方法（关键：不经端上代码，直接打服务端）

后端 `POST /api/auth/login` 对"用户不存在"和"密码错"返回**同一个** 401：

```json
{"detail":"用户名或密码错误"}      // routers/auth.py:64，故意不区分两者
```

所以界面上永远看不出是哪一种。核实只能直接对服务端做实验：

```bash
# 实测的四组组合（默认服务端 = 与端上 ApiConfig 一致的 Tailscale 地址）
node harmony/scripts/check-login.mjs <用户名> <密码>
```

| 用户名 | 密码 | 服务端结果 | 结论 |
|---|---|---|---|
| `xincell` | `712098opa` | **200** · `/me` 返回 id=12, created_at 2026-10-16 | ✅ 正确 |
| `xincell` | `712098op` | 401 · 用户名或密码错误 | ❌ 少了末尾 `a` |
| `xincell1013` | `712098opa` | **200** · `/me` 返回 id=8, 邮箱 3160743764@qq.com | ✅ 正确 |
| `xincell1013` | `712098op` | 401 · 用户名或密码错误 | ❌ 少了末尾 `a` |

另外单独验证了"匹配逻辑本身没问题"（注册→登录闭环）：

```
POST /api/auth/register  {"username":"__login_diag__","password":"Diag123456"}  → 200 + token
POST /api/auth/login     同一对账号密码                                          → 200 + token
POST /api/auth/login     改一个字母                                              → 401 用户名或密码错误
GET  /api/auth/me        Bearer <token>                                         → 200 用户信息
```

### 1.2 结论

1. **服务器与端上的沟通没有问题**：iPhone/模拟器都能正常拿 `/health`、上传素材、拉报告，
   登录请求也确实到达了服务端（hilog 里能看到 `← 401 /api/auth/login · 21 bytes`）。
2. **服务端的密码匹配逻辑正确**（bcrypt 校验 + JWT 签发 + `/me` 全链路实测通过）。
3. **真实原因**：密码最后一位 `a` 没输进去 —— `712098op` ≠ `712098opa`。
   手机密码框是密文，少一位看不出来，所以表现为"怎么点都是密码错误"。
4. 顺带确认：账号 `xincell`(id 12) 与 `xincell1013`(id 8) **都在** `100.122.178.113:8000` 这台服务器上；
   仓库里自带的 `dashboard/backend/depression.db`（8 个用户 / 126 条报告）与服务器上的库
   （≥13 个用户 / 140 条报告）**不是同一份**。如果用本机 `启动-仅本机.bat` 起后端注册过账号，
   那个账号只存在于本机库，拿到 Tailscale 服务器上登录必然 401。

### 1.3 为此新增的排障工具与界面改动

| 改动 | 作用 |
|---|---|
| **新增 `harmony/scripts/check-login.mjs`** | 一条命令把「服务器通不通 / 账号密码对不对 / 令牌能不能用」三件事分开回答，退出码 0/1/2/3 可脚本化。用法见文件头 |
| 登录页底部**常驻服务端地址** | `服务端 100.122.178.113:8000`。账号在哪台服务器上一眼可见（401 最常见的第二种成因） |
| 失败弹窗的**第三行诊断行** | 明确写"服务端已回应 HTTP 401"（→ 账号密码问题）还是"请求没有到达服务端"（→ 网络/地址问题） |
| `AuthFailKind` 失败分类 | `invalid` / `credentials` / `disabled` / `network` / `server` / `unknown`，由 `AuthStore` 判定、窗口层选词、页面只负责画 |
| 密码框保留「显示/隐藏」 | 密文类 401 的唯一自查手段 |
| 用户名提交前 `trim()` | 与服务端 `username.strip()` 对齐，排除"输入法尾随空格"这一整类问题 |

## 2. 诉求②：登录失败的弹性警告弹窗

组件：`harmony/entry/src/main/ets/components/AuthAlert.ets`（登录页与注册页共用）

### 2.1 动画分解（"凭空出现 → 撞在左边屏幕上"）

| 段 | 时间 | 做什么 | 用什么曲线 |
|---|---|---|---|
| ① 复位 | t=0，`duration: 0` | `translateX = -480vp`（屏幕外）、`opacity = 0`、scale = 1/1 | 瞬时 |
| ② 撞上来 | t≈0 → 250ms | `translateX → 0`、`opacity → 1` | `curves.springMotion(0.36, 0.55)`（弹簧，自身过冲一次 = 弹性） |
| ③ 撞击挤压 | t≈170ms，110ms | `scaleX → 1.05`、`scaleY → 0.90`，**缩放中心钉在左边缘**（`centerX: 0`） | `Curve.Sharp` |
| ④ 落定 | t≈300ms，260ms | 形变回 1.0，贴住左边缘不动 | `Curve.Friction` |
| ⑤ 收起 | 5.2s 后或点击 | 向左淡出 220ms → 卸载 | `Curve.EaseIn` |

形态细节：整条横幅**贴死屏幕左边缘**（左圆角 0、右侧 10vp 圆角），左侧 4vp 危险色竖条（用 `border-left` 表达，不额外加节点），淡红底 `#FEF2F2`。

### 2.2 三条工程纪律（都是本项目踩过的坑）

1. **只动 `translate` / `scale` / `opacity`**，绝不让动画驱动尺寸、也不挂 `onSizeChange`（BUG-01）。
2. **重放前把所有动画属性一起复位**（BUG-04）：连续失败时页面用"卸载 → 隔一帧再挂载"重放，
   组件 `aboutToAppear` 第一件事就是 `duration: 0` 全量归位，避免"第二次弹窗看不见"。
3. **弹窗不占布局**：宿主页面把它放在 `Stack` 顶层，弹出/收起都不会推动输入框。

### 2.3 文案结构（三行 + 行内兜底）

```
[!] 登录失败                                        ✕
用户名或密码错误                                        ← 服务端 detail（danger）
服务端 100.122.178.113:8000 已回应 HTTP 401：用户名或密码不匹配
（后端不区分"账号不存在"与"密码错"）。可点密码框右侧「显示」
核对输入，并确认账号是注册在这台服务器上。                 ← 诊断行（secondary）
```

弹窗会收起，但输入框下方**同时**保留一行常驻红色文案，信息不会丢。

## 3. 诉求③：开屏页

组件：`harmony/entry/src/main/ets/components/SplashView.ets`，由 `pages/Index.ets` 作为**覆盖层**挂载。

### 3.1 两级开屏（看起来是一级）

```
① 系统启动窗口：module.json5 → startWindowIcon + startWindowBackground
                 （冷启动第一帧，ArkUI 还没起来；本轮把底色统一改成 #FFFFFF）
② 开屏页：SplashView —— 图标占位（弹性放大）+ 一行 MindScope（延时 170ms 淡入上浮）
                 ↓ 引导完成且已显示 ≥1100ms
   登录页 / 主界面（这期间下层已经构建好了，淡出后直接看到就绪界面）
```

### 3.2 时长策略

| 参数 | 值 | 为什么 |
|---|---|---|
| 最短展示 | `UiTheme.splashMinDurationMs = 1100` | 缓存命中时引导 200ms 就结束，不留下限只会"闪一下"，比不显示更难看 |
| 硬上限 | `SPLASH_MAX_MS = 5000` | 引导万一卡住，开屏页到点也必须让位，不能把用户永久关在开屏页 |
| 淡出 | `TransitionEffect.OPACITY.animation({ duration: 320 })` | 用 `if` 分支的过渡，不额外写定时器 |

内容严格按需求：**图标占位 + 一行 `MindScope`**，没有多余元素。

## 4. 诉求④：我的页面

页面：`harmony/entry/src/main/ets/pages/ProfilePage.ets`（整页重写）

### 4.1 结构

```
我的 / 账号与设置
┌ 账号信息 ─────────────────────────────┐
│ (头像首字) xincell                     │
│            未填写邮箱                   │
│ ───────────────────────────────────── │
│ 账号 ID                       12       │
│ 注册日期               2026-10-16       │
│ 服务端      100.122.178.113:8000        │
│ 应用版本          1.0.0(1000000)        │
└───────────────────────────────────────┘
[ 退出登录 ]                              ← 与全应用一致的次按钮（白底 + 浅灰描边）
退出后会清除本机的登录状态与业务缓存，需要重新登录才能继续使用。
```

* 数据全部来自 `ProfilePageParam`（窗口层 `MainPage.syncTabParam()` 投影），页面**不 import 任何 store**。
* 版本号由 `MainPage.readAppVersion()` 用 `bundleManager.getBundleInfoForSelfSync()` 读一次并缓存，取不到就显示 `—`。
* 视觉全部取 `common/UiTheme.ets`：卡片 8vp 圆角 + 浅灰描边、主/次按钮与登录页同款。

### 4.2 登出链路（三处必须一起做）

```
「退出登录」→ ConfirmSheet 二次确认（说明后果）
   ↓ 确认
Index.attachMainActions().onLogout()
   ① AppStore.auth().logout('')     删令牌 + 清业务缓存(RDB) + 清内存 + bootPhase=anonymous
   ② AppStore.clearGlobalMessage()  清"登录已过期"这类提示，否则刚退出就顶着一条红字
   ③ Index.resetLoginStack()        登录流栈清空后只留登录页
   ④ refreshUi()                    → @Computed phase 变 'auth' → 界面自动切回登录流
```

**③ 是本轮必须补的一条**：注册页是 `pushPathByName` 压进登录栈的，注册成功后界面虽然切到了主界面，
但栈里仍是 `[登录, 注册]`。不复位的话，用户点"退出登录"会直接落在**注册页**上。

## 5. 顺手修掉的三条真实缺陷（本轮装机实测发现）

| 编号 | 现象 | 根因 | 修法 |
|---|---|---|---|
| BUG-20 | 登录失败后按钮**一直停在"登录中…"**、输入框全部禁用 | `AuthStore.handleFailure()` 只写了 `errorMsg`，没有走 `endLoadErr()` → `loading` 永远为 true | 失败路径统一先 `endLoadErr()` 再记类别；本地校验失败也走同一条 |
| BUG-21 | 输入框下方的错误文案**不出现**（要切页签/重新挂载才"忽然"冒出来） | `LoginPageParam`/`RegisterPageParam` 是普通 class，窗口层在**页面已挂载之后**才回填字段 → 不可观察，等于没写（与 BUG-11 同根） | 两个参数类改 `@ObservedV2`，挂载后会变的字段标 `@Trace` |
| BUG-22 | 在登录页按系统返回键 → **整屏纯白**（应用像卡死） | 登录页是登录流的根，返回键把它弹出后栈为空，`Navigation` 只剩一个白色空根内容 | 登录页 `NavDestination.onBackPressed(() => true)` 消费返回键；根内容加"自愈" `onAppear` 兜底重新压栈 |

三条都在 `BUG清单.md` 里附了现象/根因/防复发规则。

## 8. 已知边界 / 请注意

1. **远端库多了一个测试账号**：核实登录时在服务器上注册了 `__login_diag__`（id=14，无邮箱）。
   它只用于证明"注册→登录"闭环，如需清掉请在服务器上执行：
   ```sql
   DELETE FROM users WHERE username = '__login_diag__';
   ```
2. **模拟器当前处于登出状态**（第 7 步验证把令牌清了），需要重新登录：
   用户名 `xincell`，密码 `712098opa`。
3. 「我的」页账户信息是**进页面时投影**的静态数据；切换页签会重新投影一次。
   若将来做改密码/改邮箱，需要把 `ProfilePageParam` 也挂到 `@Trace`（判据见 BUG-11）。
4. 失败弹窗 5.2s 自动收起；点击弹窗任意位置或 ✕ 立即收起。
5. `AuthAlert` 的位置固定在**页面顶部**（覆盖品牌区/输入框之上），不随键盘弹出上移 ——
   键盘弹出时页面本身会滚动，弹窗仍停在顶部，与"在输入框之上"的要求一致。
