### 2.1 工作台当前结构

```text
页头（标题 + 问候/日期 + 累计概览 + 刷新）          order 0
[离线横幅：仅探活失败时出现]
本次评估 hero（素材 / 状态 / 分数环 / 阶段 / 动作）   order 1
开始新的辅助评估                                    order 2
注意力热力图（16×16 + 逐帧列表）                     order 3
情绪曲线                                            order 4
严重度分布                                          order 5
智能解读（VLM）                                      order 6
```

- 分析内容**内联在主页面**，不再进入独立详情页；3~6 号卡只在“有查看目标”时渲染。
- 查看目标优先级：当前任务（含恢复的上一次评估）→ 最新一条报告 → 无。
- 只在分析 `done` 时落盘「当前任务 + 该素材最终会话」；`running` / `failed` 不落盘。
- 没有「最近使用的素材」列表；hero 在无持久化评估时用最新报告兜底。
- 素材库点素材 = 登记当前任务 → 起 WS → 切到工作台看内联进度。

### 2.2 历史报告 / 分析详情的分工

| 场景 | 行为 |
|---|---|
| 工作台 | 只展示**当前任务**或**恢复的上一次评估**，按 `mediaId` 取本机会话 |
| 历史报告 | 按检测时间倒序列出全部报告；同一 `mediaId` 聚合为一张卡（次数 / 最低–最高分） |
| 点「查看报告」 | 进入 `AnalysisDetailPage`：展示该素材的报告快照；本机有会话则展示逐帧结果，否则提示“逐帧数据未保留”并给「重新分析」 |
| 返回 | 详情页返回**不停止分析**（会话挂在 `AppStore` 上继续跑） |

## 三、应用结构

```text
EntryAbility.onCreate
  └─ AppBootstrap.start(context)
       ① StorageManager.init        打开 preferences + RDB（v2），建表建索引
       ② ApiConfig.load             读回服务端 host / port / token
       ③ 冷启动预热                 从 RDB 把上次 media / reports / stats 灌进 store
       ④ AuthStore.restore          有 token 则 GET /api/auth/me 校验
       ⑤ 并发拉取 media / reports / stats，写内存 store + 回写 RDB
       ⑥ restoreAssessment          恢复上次已落盘的工作台评估
       ⑦ 失败 / 无 token → 离线或未登录，UI 照常渲染

Index（唯一 @Entry，窗口层）
  ├─ bootPhase = idle / preparing → 骨架屏（开屏页覆盖其上）
  ├─ signedIn = false            → 登录流 Navigation(loginStack)：Login ⇄ Register
  └─ signedIn = true             → 主界面 Navigation(mainStack)：
        MainPage（五个一级页签，replacePathByName 切换）
          ├─ 工作台 / 素材库 / 历史报告 / 统计 / 我的
          ├─ mediaPicker（push，素材选择）
          └─ analysisDetail（push，仅历史报告进入）
```

**两条纪律与该有的例外：**

1. 页面默认只读 `@Param`、不 import store、不碰路由栈。
2. 例外只有两处，理由都是“异步数据在页面挂载后才到达”：
   - **工作台**读 `AppStore` 的实时会话（逐帧 / 进度 / 分数），动作仍走参数回调；
   - **分析详情页**按 `mediaId` 读 `AppStore` 会话，只读、不写。
3. 参数类是否需要 `@ObservedV2` 的唯一判据：**给字段赋值那一行，是否发生在页面挂载之后？** 是 → 必须可观察（BUG-10/11/21）。

## 四、数据层

### 4.1 分层

```text
服务端 snake_case（schemas.py，不改）
  ↓ types/dto.ts         字段名保持 snake_case，1:1
  ↓ types/mapper.ts      逐字段显式转换（禁止对象展开）
  ↓ types/model.ts       全部驼峰，UI 只认这一层
  ↓ store / 页面
```

- `.ts`：纯类型 + 纯常量（`enums / dto / model / constant / mapper / Index`），可被 Web 端直接 import。
- `.ets`：用了 ArkTS 装饰器或 ArkUI 类型（`storeState` 及其余全部）。
- 只有 `types/dto.ts` 允许出现 snake_case；RDB 物理表 / 列名沿用服务端风格。

### 4.2 持久化（RDB v2 + preferences）

| 存储 | 内容 | 说明 |
|---|---|---|
| `preferences` | token / host / port / token_saved_at | 明文 KV；token 另有内存副本供 WS 同步拼接 |
| `media_asset` | 素材镜像 | v2 新增 `patient` 列（老库自动 `ALTER TABLE`） |
| `diagnosis_report` | 报告镜像 | 冷启动 / 离线可读 |
| `stats_cache` | 统计快照 | 单行 KV |
| `workbench_assessment` | 当前评估快照 | 单行 JSON：当前任务 + 最终会话（帧 / 热度 / 曲线 / VLM / 首帧），约 0.5 MB |

- `RDB_VERSION = 2`；迁移走 `CREATE TABLE IF NOT EXISTS` + 针对 v2 的补列。
- 登出 / 换号会清空业务缓存（含评估表），避免人脸与热力图残留。
- 持久化上限：会话按素材归档，最多 6 条；单会话 live ≤ 90 帧、收尾裁到 30 帧；分数点 ≤ 120。

### 4.3 领域 store

| Store | 职责 | 关键状态 |
|---|---|---|
| `AuthStore` | 登录 / 注册 / `/me` / 登出 | `signedIn`、`user`、`loading`、`errorMsg`、`failKind`、`failStatus` |
| `MediaStore` | 素材列表 / 上传 / 删除 / 患者筛选 / 重命名 | `items`、`typeFilter`、`patientFilter`、`lastUploaded` |
| `ReportStore` | 报告分页 / 全量加载 / 筛选 / 详情 | `items`、`total`、`allLoaded`、`detailItems` |
| `StatsStore` | 统计汇总 / 分布摊平 / 趋势 | `summary`、`buckets`、`loading` |
| `AnalysisStateHolder` | WS 回调 → `@Trace` 状态的唯一接缝 | 按 `mediaId` 归档 `sessions`、live 指针 |
| `AppStore` | 面向 UI 的统一门面 | 镜像上述状态 + `currentTask` + 恢复 / 持久化 |

> UI 取数只找 `AppStore.get()` 或它的领域 store；字段一律驼峰；`mediaId` 一律当字符串用。

### 5.2 页签转场

- 机制：`CardTransit` 发 `exitClock` 信号 → 各卡按 `order` 离场 → 等 `sequenceMs` → `replacePathByName` 换页 → 新页各卡 `onAppear` 错峰入场。
- 节拍：`cardMs = 240ms`、`stepMs = 110ms`、离场位移 `exitTravel = 420vp`。
- 计数契约（只算参与**离场**的组件）：工作台 7 / 统计 7 / 历史报告 3 / 我的 3 / 素材库 2。
- 历史报告的每张卡只播入场、不计入离场；列表区整块负责离场。
- **没有实现“两页同屏横移”**：`replacePathByName` 换页那一帧就销毁旧页，与逐卡错峰入场互斥。评估记录见 [参考/页签横移动画评估记录](参考/页签横移动画评估记录.md)。

| POST | `/api/upload/image`（multipart，字段 `file`） | ✅ |

| PUT | `/api/media/{id}/patient` | ⚠ 端上已封装，**后端不存在** |

| WS | `/ws/analysis?token=` | ✅ |

| GET | `/media/{filename}`（无鉴权） | ✅ |
| POST | `/api/analyze` / `/api/analyze/face` | ⚠ 前者空壳，端上未封装 |

**后端现状（2026-10-18）：**

1. `patient` 列与 `PUT /api/media/{id}/patient` 在 `dashboard/backend` 中**不存在**。当前表现：上传成功但患者名只存端上（卸载 / 换设备后丢失）；重命名提示接口失败。
   端上 DTO / Mapper / `MediaApi` 已就绪（含 `patient` 字段与两个调用），后端补上即可生效，不需要再改端上接口层。
2. `uploader_name`：远程后端的 `ReportListItem` **已包含该字段**（2026-10-18 实测 `/openapi.json`），说明部署已跟上；旧报告的该字段为空，历史报告卡仍不展示账号 / 姓名（避免显示错误信息）。
3. 后端没有登出、改密码、删报告、媒体分页、邮箱验证；登出是客户端删 token。
4. JWT HS256、7 天、无 refresh；401 统一踢回登录页。

## 九、已知边界

1. **患者命名后端缺位**（见第六节），重命名接口失败；患者名只在端上生效。
2. **评估持久化只覆盖 `done`**；`running` 不落盘（避免幽灵任务），`failed` 不落盘（保留上次成功评估）。
3. **会话归档在内存上限内**：6 条素材 / 单会话 30 帧（收尾后）；被淘汰的素材走“报告分数 + 重新分析”。
4. **素材库没有卡片错峰入场**：页面未挂 `RevealCard`，`CARDS_PLACEHOLDER = 2` 目前只体现在换页等待时间上。
5. **工作台 / 详情页依赖 `AppStore`**：这是页面纪律的两处例外，不是回归；新页面不要照抄。
6. **视频取消基本无效**：服务端先算完再回推，UI 不承诺可中断；`done` 后断连是正常收尾。
7. **历史报告按 `mediaId` 聚合**：同一素材的多次分析只显示最新一条 + 次数 / 分数范围；没有“单素材全部分析”页。
8. **开发探针仍在仓库**：`HeatmapProbePage` / `HeatmapFeasibilityProbe` 只用于验证，不在主流程。
9. **`test-workbench-layout.mjs` 已按现行架构更新**（2026-10-18）：断言历史详情页保留、仅从历史报告进入，而不是“详情页已删除”。
