## 2. 最终页面结构（7 段错峰）

```
页头：工作台 + 问候/日期 + 累计概览 + 刷新          order 0
[离线横幅：仅探活失败时出现]
本次评估 hero：素材 / 状态 / 分数环 / 阶段 / 动作     order 1
开始新的辅助评估                                    order 2
注意力热力图（16×16 + 视频逐帧列表）                 order 3
情绪曲线                                            order 4
严重度分布                                          order 5
智能解读（VLM）                                      order 6
```

- `CardTransit.CARDS_WORKBENCH` 从 8 收敛为 **7**，与 7 个 `RevealCard({ order })` 一致。
- 3~6 号卡只在有查看目标（当前任务/恢复的评估/最新报告）时渲染。
- 无数据时：hero 空态（「还没有评估记录」）+ 开始评估卡；不会出现四张空卡片。

### 2.1 Hero（`AnalysisHeroCard`）

- 首帧照片（恢复的评估也有）、文件名、`MediaTypeBadge`、来源标签、状态胶囊。
- 分数环（`ScoreRing`，Canvas 270° 弧，120vp，值 = BDI/63，颜色 = 严重度色）。
- 严重度 / BDI / 帧数 / 推理耗时 / 一句话说明。
- 当前任务（本次运行）显示「上传 → 单次推理/逐帧推理 → 汇总评分」+ 分析进度条；
  重启恢复的评估**不画阶段轨**，显示「最近一次评估 / 上次分析 · MM-DD HH:mm」。
- 动作：重新分析该素材（无会话/失败/恢复评估时出现）、取消分析（live 运行中）。
- 来源标签：
  - 本次运行中的任务 → 「当前任务」；
  - 恢复的上一次评估 / 最新报告兜底 → 「最近一次评估」。

### 2.2 热力图卡（`AnalysisHeatmapCard`）

- 图/视频同一张卡：16×16 热力图 + 色带 + Top-3 解读。
- 视频：横向逐帧列表（最多 24 格）、可固定某一帧/回到最新；图片：不画列表。
- 无真实帧：**紧凑空态**（图标 + 原因 + 「载入演示热力图（仅验证渲染）」），
  不再画 300vp 灰块；`isSample` 只在真的载入演示帧后才为 true。
- 图片文案单独处理：「单帧图片的推理结果 · BDI x」，不再出现「左右滑动」的矛盾提示。

### 2.3 开始评估卡

- 类型胶囊：「图片 · 单次推理」「视频 · 逐帧采样」。
- 整宽主按钮「选择素材」；整卡与按钮同一个动作。

## 3. 当前评估持久化（本轮核心新能力）

### 3.1 存什么

`workbench_assessment` 单行 JSON，载荷 = **当前任务元信息 + 该素材的最终分析会话**：

```ts
interface WorkbenchAssessmentModel {
  version: 1;
  userKey: string;              // 用户 id，换号校验
  savedAt: number;
  mediaId / mediaName / mediaType;
  status / score / error;
  session: AnalysisSessionModel | null;  // 帧、热度矩阵、曲线分数、VLM、首帧
}
```

因此重启后恢复的不只是分数：**热力图、情绪曲线、严重度分布、智能解读、首帧缩略图**
全部回来；页面显示「上次分析 · 时间」，并保留「重新分析该素材」入口。

### 3.2 什么时候存

- **只在 `done` 时落盘**：`AppStore.onAnalysisFinished()` 先 `sync()` 折平当前任务状态，
  再 `persistAssessment()`，最后才刷新统计/报告/媒体。
- running 不落盘：避免重启后出现永远「分析中 42%」的幽灵任务。
- failed 不落盘：保留上一次成功评估更有用。
- 落盘失败不打断分析收尾，只写日志。

### 3.3 什么时候恢复

- `AppStore.loadAll()`（引导完成 / 登录成功）末尾调用 `restoreAssessment()`。
- 校验 `version` 与 `userKey`；不匹配直接删除，避免换号串数据。
- 把会话注入 `AnalysisStateHolder.restoreSession()`（非 live，`mediaId` 置空），
  再 `sync()` 让 `currentTask()` / `currentTaskRestored` 一致。
- 若本次已经开始了新任务（`currentTaskMediaId` 非空）则跳过，不覆盖。

### 3.4 数据层改动

- `RDB_VERSION` 1 → **2**；`DbSchema` 新增 `WorkbenchAssessmentTable`，
  `migrate()` 走既有 `createSchema()`（`CREATE TABLE IF NOT EXISTS`）。
- 新增 `AssessmentCacheDao`（沿用 `stats_cache` 的单行 KV 模式）。
- `StorageManager` 接入 `assessmentDao()`，并在 `clearBusinessCache()` 里清空评估表
  （登出/换号不残留人脸与热力图）。
- `Mapper.statsPayloadFromRow` 收敛为通用的 `Mapper.payloadFromRow`。

### 3.5 与旧逻辑的关系

- `currentTaskRestored`：`@Trace` 标记"这是恢复的上一次评估"；
  新分析 `setCurrentTask/startAnalysis` 立刻置 false。
- 「最近使用的素材」删除后，最新报告数据仍由 `AppStore.recentMedia(1)` 提供，
  仅用于首装/无持久化评估时的 hero 兜底（页面没有列表）。
- `WorkbenchPageParam` 只剩回调 + `scrollTopTick` + `refreshing`；
  focus/历史查看/「回到当前任务」chip 全部移除。

## 5. 本轮修掉的缺陷

### BUG-23 · 分析完成后热力图/帧数不刷新 ⭐⭐

- **根因**：`analysisSessionOf()` 在桥接器为 null 时提前返回，页面 `@Computed session`
  首次求值没有读到 `@Trace sessions`，后续写入不会触发重算。
- **修法**：`AppStore` 构造函数提前建桥接器（不建立连接）。
- **证据**：`task-live.jpeg`（阶段轨）→ `task-done2.jpeg`（1 帧/热力图）；
  日志 `分析完成 11.74` → `评估已持久化 会话=有 ok=true`。
- **防复发规则**：没有数据时也要读一次 @Trace 源，不能提前返回。

同轮顺手修掉：刷新按钮文字被 padding 截断、热力图空态过大/误标演示数据、
图片热力图提示矛盾、单帧曲线留白、图片阶段轨/取消提示、hero 帧数文案。
详见 `BUG清单.md`。

## 7. 已知边界

1. **只持久化 done 的评估**；running 不落盘，failed 不落盘（保留上一次成功评估）。
2. 载荷含最多 30 帧人脸 base64 + 16×16 热度矩阵，约 **0.5MB**；RDB 单行 TEXT 足够，
   但不再适合更大规模的多会话归档（当前只存"当前评估"一条）。
3. 登出会清空评估表；同一账号再登录不会恢复（这是有意的"退出即清业务数据"策略）。
4. 删除最近素材后，**没有历史列表入口**；「历史报告」页签仍是占位页。
   若后续要做历史浏览，需要重新设计入口（不能恢复成底部一条长列表）。
5. 刷新按钮当前用文字「刷新」占位，图标资源仍未选定；换图标只改 `refreshButton()`。
6. Web 端 `dashboard/` 与后端零改动；本轮所有数据来自既有 `/api/*` 与 WS。
