## 五、基础 bug 自查（发现并修掉的问题）

### 5.1 编译期发现（6 → 0）

| 问题 | 报错原文 | 修法 |
|---|---|---|
| `@Param` 叫 `padding` | `Property 'padding' in type 'AppCard' is not assignable to the same property in base type 'CustomComponent'` | 改 `_padding`（与系统属性同名的入参一律加 `_` 前缀） |
| `@Param` 叫 `size` / `background` | 同上（`LogoPlaceholder`） | 改 `_size` / `_background` |
| `navDestination` 回调形参写 `unknown` | `Use explicit types instead of "any", "unknown" (arkts-no-any-unknown)` | 形参改用 `ESObject`（ArkTS 的动态类型出口） |
| `@Builder` 体内调普通方法 | `'this.syncLoginParam()' does not meet UI component syntax` | 改为在"await 收敛点"同步参数，不在 `build` 里同步 |
| `import { NavPathStack } from '@kit.ArkUI'` | `@kit.ArkUI` 并未导出该类型 | `NavPathStack` 是**全局声明类型**，直接用类型名，删掉 import |

### 5.2 逻辑自查（主动修正）

1. **页面参数对象被反复重建** → 原先 `build()` 每次都 `new` 一个参数对象，而 `@Param` 按对象引用比对，
   会把页面入参整体重置、触发子树冗余重建。改为**构造一次 + 只改字段**，并统一在 `refreshUi()` 里收敛。
2. **"网络失败重试"与"密码错误"同时出现** → 登录失败时 `AppStore.offline` 仍可能为 true，
   导致用户输错密码时同时看到两条互相矛盾的信息。改为**仅在没有任何鉴权错误可展示时**才提示重连。
3. **服务端错误不会消失** → 用户改密码后仍看到上一次的"用户名或密码错误"，像"没生效"。
   做法：页面本地记录"已展示过的错误快照"，用户重新输入即收起；重新提交时允许再次显示。
   （页面**不回写 store**，保持"页面只消费参数"的纪律。）
4. **超长错误文案撑爆布局** → 422 的 detail 可能很长，错误行加 `maxLines(4)` + 省略号。
5. **登录页按钮连点** → `busy`（store 的 `loading` 或页面 `submitting`）期间按钮 `.enabled(false)`，
   回调入口再判一次，双保险。
6. **返回键回到登录页** → 从结构上消除：登录流与主界面各用独立 `NavPathStack`，切分支时旧栈整体销毁。
7. **首帧闪空白** → 登录页/工作台页在 `aboutToAppear` 里先入栈，`build()` 时栈非空，不会渲染根内容。
8. **启动白闪** → `startWindowBackground` 改为与页面同色的 `#F4F8FB`。
9. **`.ts` 与 `.ets` 的边界** → `types/PageParams.ets` 因为要持有 `NavPathStack`（ArkUI 类型）
   才用 `.ets`；纯数据/常量仍留在 `.ts`，维持上一轮的划分规则。

### 5.3 交付后按指示做的重构（页面目录扁平化）

首轮实现成了"每个页面一个文件夹 + 参数文件同目录"，按用户澄清（**所有 page 统一放在一个
`pages` 目录**）重构为：

| 动作 | 内容 |
|---|---|
| 页面文件上提 | `pages/{Login,Register,Main,Workbench,MediaLibrary,Reports,Stats,Profile}/*Page.ets` → `pages/*Page.ets`（单层，无子目录） |
| 参数契约合并 | 4 个零散参数文件（约 90 行）→ **一个** `types/PageParams.ets`（162 行），按页面分区并逐个字段注释 |
| 路由元数据合并 | `common/PageRoutes.ets` → `pages/PageRoutes.ets`，并把页签字形也并进 `MAIN_TABS`（原先字形散在 `MainPage` 的 `glyphOf` 里） |
| 去重 | 删掉 `MainPageParam` 里与 `PageRoutes` 重复的 `MainRoute` 枚举与顺序数组；删掉 `MainPage.labelOf` / `glyphOf`，改用 `mainTabLabel` / `mainTabGlyph` |
| 结果 | 页面相关文件从 **21 个（8 个子目录）** 收敛为 **10 个（0 个子目录）**；全量编译仍 0 error |

## 七、已知限制（如实记录）

1. **未做真机/模拟器测试**：本轮的验证只到"编译通过 + import 图核对 + 逻辑自查"，
   实际视觉比例（间距、字号、页签高度）需要下一轮在预览器/真机上微调。
   所有尺寸已集中为 `UiTheme` 常量，微调只改一处。
2. **五个页签的高亮状态与导航栈是"双份真相"**：目前用 `@Local selectedTab` 驱动高亮，
   若将来在页签内部 `pushPathByName` 跳二级页面再返回，页签名仍正确；
   但若有人绕过 `pushTab()` 直接操作栈，高亮会不同步 —— 已在 `MainPage.pushTab` 注释里标注"唯一入口"。
3. **`Navigation` 的根内容是兜底画面**：正常流程不显示（首帧即入栈），保留它是为了防"栈意外为空"时白屏。
4. **"我的"页的用户名/服务端地址在登出再登录后不会自动刷新**：因为 `MainPage` 只在挂载时读一次参数，
   而登出会卸载它。本轮不做登出，故无实际影响；下一轮做登出时顺手把 `MainPageParam` 改成按需刷新即可。
