## 二、恢复策略

### 2.1 素材库（`66fb195`）

以 `053ab44` 为源，按**方案 A** 只把素材库接回当时的旧架构：

- `MediaLibraryPage` / `PatientNameDialog` 全量取回；
- `MediaStore` / `MediaApi` / `HttpClient.put` / `MediaItemModel.patient` / `mapper` / `dto` /
  `Index` / `MainPage` 接线；
- RDB v2 增加 `media_asset.patient` 列（老库自动 `ALTER TABLE`）；
- 额外修正一：`MediaLibraryPageParam` 改为 `@ObservedV2` + `@Trace`
  —— 否则上传/删除/重命名后列表不会刷新（与 BUG-10/11 同一条判据）。
- 额外修正二：患者命名对话框按「确定」会把应用打崩（真机实测）
  —— `@CustomDialog` 组件内的 `controller` 在 V2 页面里取不到注入值，
  `this.controller.close()` 抛 `TypeError: Cannot read property close of undefined`。
  改为**由页面持有 `CustomDialogController`**、确认/取消回调到页面统一关闭；
  对话框内只保留语法要求的 `controller?: CustomDialogController` 声明，不再调用它。

### 2.2 工作台重构（`196b76e`）

以 `053ab44` 的 `harmony` 树为基线（= `93ad9eb` + 素材库），把历史报告功能作为补丁重新应用：

- `WorkbenchPage` 恢复纵向长页：页头 / 本次评估 hero / 开始评估 / 热力图 /
  情绪曲线 / 严重度分布 / 智能解读（order 0–6）；
- 恢复 `AnalysisHeroCard`、`AnalysisStageRail`、`AnalysisHeatmapCard`、`AnalysisVlmCard`、
  `ScoreRing`、`AssessmentCacheDao`，以及 `AppStore.persistAssessment/restoreAssessment`、
  `currentTaskRestored`、`firstFrameUrlOfMedia`；
- 删除 `CurrentTaskCard` / `RecentMediaSection`，`CardTransit.CARDS_WORKBENCH` 回到 7；
- 历史报告页、`ReportStore`、`ReportsPageParam`、后端 `uploader_name` 改动全部保留；
- **分析详情页保留**，但只从历史报告进入（见第三节）；
- 素材库点素材改为：登记当前任务 → 起 WS → 切到工作台看内联进度。

提交顺序：`e470f0b`（工作区既有的历史报告卡片错峰改动）→ `66fb195`（素材库）→
`196b76e`（工作台重构）。`196b76e` 已 rebase 到远端 `57c4179`（wcr 的合并），
远端那份合并相对 `66fb195` 只多了一个尚未被使用的 `CARDS_MEDIA` 常量。

## 三、当前架构（工作台重构与历史报告的折中）

| 页面 | 现状 |
|---|---|
| 工作台 | 分析内容内联在主页面；旧的独立详情页不再是主流程 |
| 素材库 | 上传（可带患者名）/ 患者筛选 / 视频图片 Tab / 2 列网格 / 删除 / 重命名 / 骨架屏 / 错误重试 |
| 历史报告 | 筛选 + 按 mediaId 聚合卡片；点「查看报告」仍进 `AnalysisDetailPage` |
| 分析详情页 | **只服务历史报告**：展示该素材的报告快照；本机有会话则展示逐帧结果，否则提示「逐帧数据未保留」并给重新分析 |

为什么保留详情页：工作台重构原本删除了它，但历史报告需要一个按任意报告查看的入口；
工作台的 `focus` 只服务「当前任务 / 最新一条报告」，无法按任意报告取数。
保留详情页是让两批功能都不回退的最小折中。
