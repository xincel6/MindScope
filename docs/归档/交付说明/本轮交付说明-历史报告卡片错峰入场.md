# 本轮交付说明 · 历史报告页「每张报告卡」错峰入场

> 承接 `docs/本轮交付说明-交互统一与离场动画.md`（上一轮：按压反馈 + 换页离场动画）。
> 本轮只做一件事：**历史报告页里具体的报告卡片也做错峰滑动**。
> 此前该页只有页头（order 0）与筛选栏（order 1）参与错峰，卡片列表是裸放的，切页签时"页头、筛选栏一个一个来，卡片却整片突然出现"。

## 1. 诉求与结论

| 诉求 | 结论 |
|---|---|
| 历史报告页的报告卡片要错峰滑动（此前未实装） | ✅ 每张卡按列表下标依次从侧向滑入；切页签进入、数据到达、筛选后新挂载的卡都会播 |
| 不能破坏已有的换页转场 | ✅ 离场仍由「页头 → 筛选栏 → 列表区整块」三块按序滑出，节拍与 `sequenceMs` 完全对齐 |
| 不能因为卡片多而卡住页签 | ✅ 卡片**不计入**离场等待；错峰延迟有上限，切换页签的等待仍是 500ms |

## 2. 为什么不能「把每张卡直接包一层 RevealCard」了事

`RevealCard` 的既有契约是**同时跟随入场与离场**（`onAppear` 播入场，`@Monitor(exitClock)` 播离场）。
把它无脑套到列表项上会同时踩三个坑：

1. **离场等待会爆炸**：第 i 张卡的离场延迟是 `i × 110ms`。全量加载可能有几十上百张卡，
   最后一张要等到十几秒后；而窗口层只等 `sequenceMs(3) = 500ms` 就 `replacePathByName`，
   绝大多数卡（包括首屏可见的）都来不及动就被销毁 —— 比不做更糟。
2. **列表容器与卡片会叠成两层动画**：列表区（骨架 / 空态 / 错误 / 卡片）必须整块参与离场，
   如果它同时也播入场，会先整体滑入一次，里面的卡再各自错峰滑入一次，
   位移与透明度相乘/相加，观感是"抖一下再变淡"。
3. **屏幕外的卡在排队**：延迟按真实下标线性增长，用户进入页面后立刻下滑，
   会看到一串还没到启动时刻的空白槽位。

所以采用「**卡片只错峰入场、列表整块负责离场**」的分工。

## 3. 实现

### 3.1 `RevealCard` 新增两个开关（默认值不变，旧页面零改动）

| 参数 | 默认 | 作用 |
|---|---|---|
| `_playEnter: boolean` | `true` | 为 `false` 时：`aboutToAppear` 直接把 `shift/shiftY/scale/alpha` 设为终态，`onAppear` 不播入场 |
| `_playExit: boolean` | `true` | 为 `false` 时：`@Monitor('transit.exitClock')` 直接 return，不跟随页面离场 |

> 与 `_weight` 同一约定：可能与系统属性重名的入参带 `_` 前缀。
> 两者都保持"默认 true = 加参数之前的行为"，因此工作台 / 统计 / 我的 / 素材库不受影响。

### 3.2 `ReportsPage` 变成 3 个离场位 + N 个入场卡

```
RevealCard({ order: 0 })                        ← 页头
RevealCard({ order: 1 })                        ← 筛选栏
RevealCard({ order: 2, _playEnter: false })     ← 列表区整块（骨架/错误/空态/卡片列表都包在这里）
  └ ForEach(reportGroups)
      RevealCard({ order: 2 + min(index, 5), _playExit: false })   ← 每张报告卡，只播入场
```

* **列表区整块**：`_playEnter: false`（入场交给卡片），但保留默认 `_playExit: true`。
  换页时它按 order 2 与页头、筛选栏一起逐块滑出；卡片在它内部，跟着整块平移，
  不会出现"页头走了、卡片还钉在原地"。
* **每张报告卡**：`order = 2 + min(index, LIST_STAGGER_LIMIT)`，`_playExit: false`。
  `order` 同时决定启动延迟（`order × 110ms`）与横向拖尾距离（`travelOf(order)`），
  与固定块用的是同一套节拍与曲线，观感统一。
* **`LIST_STAGGER_LIMIT = 5`**：一屏约放得下 4~5 张卡（单卡约 150vp、屏高约 800vp），
  前 6 张覆盖首屏；再往下用户要滚动才看得到，届时早已落位。
  延迟上限 `(2 + 5) × 110 + 240 ≈ 1.0s`（含淡入），不会出现"滑下去全是空白槽位"。

### 3.3 计数契约（最容易漏的一步）

| 位置 | 旧 | 新 |
|---|---|---|
| `CardTransit.CARDS_REPORTS` | 不存在（Reports 复用 `CARDS_PLACEHOLDER = 2`） | **3**（页头 / 筛选栏 / 列表区整块） |
| `CardTransit.CARDS_PLACEHOLDER` | 2（素材库 + 历史报告共用） | 2（**仅素材库**） |
| `MainPage.cardCountOf(MainTab.reports)` | 落到 `CARDS_PLACEHOLDER` | 返回 `CARDS_REPORTS` |

> **计数规则修正**：`CARDS_*` 现在语义是「**参与离场**的组件数」，不是页面里 `RevealCard` 的总个数。
> 列表卡片传了 `_playExit: false`，只播入场，**绝不能**计入 —— 否则等待时间会随数据量膨胀。
> `MainPage.cardCountOf()` 与 `CardTransit.CARDS_*` 的注释已同步写明。

## 4. 参数（未改动全局节拍）

## 6. 已知 / 边界

1. **刷新且数据键没变时不会重播**：`ForEach` 以 `media-${mediaId}` 为 key，同一批素材重新拉取时节点被复用，
   入场动画只在组件**首次挂载**时播（这是有意为之，避免每次刷新整页闪烁）。
   切页签进入（页面会重建）、筛选后新出现的卡、首次加载完成的卡都会正常错峰。
2. **骨架 / 空态 / 错误块本身不播入场**（与改动前一致）：它们在 `_playEnter: false` 的列表容器里，
   首帧即终态；它们仍会随列表容器一起离场。
3. 上限 5 是按"一屏 4~5 张卡"估的。若以后卡片变矮/屏变大导致一屏能放下更多，
   可把 `LIST_STAGGER_LIMIT` 调大；代价只是屏幕外的卡多等一会儿。
4. 全量列表可能有上百张卡，每张都持有 `RevealCard` 的 `@Local` 状态与 `@Monitor`；
   `_playExit: false` 时监听回调只做一次布尔判断就返回，实测切换与滚动无卡顿。
5. `MediaLibraryPage` 仍是占位页（2 个离场位），未接入列表卡片错峰。
