## 二、用户三条主诉的根因与修法

### 2.1 「图片分析出现十帧，退出再回来又变成一帧」

两处叠加：

1. **服务端伪造帧数**：`services/frame_processor.py::_process_image` 为了让网页端曲线"有点可画"，
   把同一次推理的结果重复推 10 帧（10 步循环 + 每帧 `sleep(0.2)`）。
2. **端上没有"图片 = 单帧"语义**：帧数、逐帧列表、曲线都按"收到几帧算几帧"渲染，
   而"退出再回来"走的是历史素材路径，那里**没有自己的帧**，只剩 1 帧兜底（见下一条）。

修法：
- 服务端图片路径**只推 1 帧**（`frame_id=1, progress=1.0`）；
- 端上 `AnalysisChartModel.resolveFrames()/displayFrameCount()` 按素材类型归一：**图片永远最多 1 帧**；
- 网页端 `EmotionCurve.vue` 单点数据画成水平直线并加说明。

### 2.2 「两个素材分别上传，后上传的覆盖了前面的，所有热力图变成一个人」⭐⭐ 主诉

根因是一段"善意兜底"：

```ts
// 旧 HeatmapViewModel.buildHeatmapView()（已删）
if (lastFrame !== null && hasHeat(lastFrame)) {   // ← 全局最新一帧，与所看素材无关
  return { frames: [lastFrame], ... };
}
```

配合"分析结果只有一份全局缓冲、`start()` 先 `reset()` 清空"，
历史素材页**必然**走到这条兜底并显示最近分析的那个人的结果。

修法（本轮最核心的结构改动）：**按 mediaId 归档分析会话**
（`AnalysisSessionModel`：frames / scores / 状态 / 分数 / VLM，存 `AnalysisState.sessions`）。
`start()` 只重置 live 指针与"该素材自己那一条"；同素材重算覆盖自己，其它素材保留。
**删除 `lastFrame` 兜底**，页面只按 mediaId 取，取不到就老实说"本机未保留逐帧数据"。

### 2.3 「分析跑完了，档位标签 / 智能解读不出现」（顺带发现并修掉）

档位标签与 VLM 文本原本从**页面参数**读，而写参数的 `MainPage.syncDetailParam()`
只在"切页签 / 入栈"时被调用，WS 收帧与 `done` 都不会触发它 —— 入栈那一刻分数还是 0，
之后**再没有时机**填上。

修法：删除 `syncDetailParam()` 与参数里的实时字段（含 `followLiveTask`），
页面全部从 `@Trace` 会话读；档位由分数现算（`severityMetaOf`，`BdiThreshold` + `UiConstant` 单一口径）。

## 三、两个空组件怎么填（附"饼图到底怎么用"的答案）

### 3.1 情绪曲线 → `components/charts/EmotionCurveCard.ets`

| 素材 | 形态 | 说明 |
|---|---|---|
| **视频** | 逐帧 BDI **折线** | **直接复用**已实现的 `ScoreTrendChart`（Y 轴 0–63、13/19/28 三条阈值虚线、四档图例），本卡片只补标题与说明；横轴 = 帧序号，点数超过 60 时等距抽稀（保留首尾） |
| **图片** | **水平直线** | 用户原话："如果是一张图片，折线图也无法表示随着帧数的情绪变化了，这种情况直接变成直线吧"。图片只有一个分数，**不交给图表库画孤立点**（单点在手机上几乎看不见），改用 ArkUI 原生节点画一条直线 + 分数刻度点 + 一句"分数恒定，因此是水平直线" |
| 无数据 | 占位 | "开始分析后，这里会显示评分曲线"，不画假图 |

### 3.2 严重度分布 → `components/charts/SeverityDistributionCard.ets`

用户问："我不知道怎么在一段视频或者照片中使用饼图，如果你没有思路，这个组件可以直接删除"。
**有思路，所以没删**：

| 素材 | 形态 | 为什么这样是对的 |
|---|---|---|
| **视频** | **帧级四档环形图**（环心「N 帧」） | 统计**这一段视频的所有帧**分别落在正常/轻度/中度/重度的数量与占比（例：60 帧中 5/30/20/5）。它回答的是"这段素材里情绪稳定的比例"，正是"一段视频里怎么用饼图"的正确答案。复用统计页同一套 `SeverityPieChart`（只多传一个 `centerText`，把「N 例」改成「N 帧」，统计页零影响） |
| **图片** | **档位刻度尺** | 一张图只有一次推理，饼图必然是"100% 一个颜色"的整圆，零信息量。改用 0–63 四档色带（权重 14/6/9/35）+ 当前分数指针 + 档位文字，表达"它在量表的哪个位置" |

> 如果后续仍希望图片分支整块不显示：删掉 `SeverityDistributionCard` 的 `scale` 分支即可（1 段 `if`），
> 视频分支不受影响。

### 3.3 「分不清图片和视频」的修法

| 位置 | 图片 | 视频 |
|---|---|---|
| 类型标识 | `MediaTypeBadge`：「图」实心块 + 主色描边 | 「视」实心块 + 辅助蓝描边 |
| 帧数 | 「1 帧（单次推理）」 | 「共 N 帧（逐帧采样）」 |
| 状态提示 | 「正在对这张图片做单次推理」 | 「服务端正在逐帧推理，已收到 N 帧」 |
| 热力图卡标题 | 「注意力热力图（16×16 · 单帧图片）」 | 「注意力热力图（16×16 · 逐帧）」 |
| 逐帧列表 | **不渲染**（只有 1 帧，画列表是误导） | 保留横滑列表 + 「共 N 帧」 |
| 情绪曲线 | 水平直线 | 逐帧折线 |
| 严重度 | 档位刻度尺 | 帧级环形图 |

## 五、边界与已知取舍（下一轮如果要继续，从这里开始）

1. **分析结果只在内存**（不含 RDB / 服务端持久化）。App 重启后，历史素材页只剩报告分数 +
   「重新分析该素材」。要做跨重启的逐帧热力图，需要新增端上 `FrameDao`（`RDB_VERSION` +1 并补迁移）
   或服务端 `analysis_frames` 表 —— 本轮评估后**刻意不做**，风险与收益不匹配。
2. **归档上限**：最多 6 条素材会话、单会话帧 ≤90（收尾裁到 30）、分数点 ≤120。
   超出后淘汰 `updatedAt` 最旧的**非 live** 会话；被淘汰的素材走"报告分数 + 重新分析"分支。
3. **超长视频的曲线**：分数序列只保留最近 120 点，横轴是**序列内序号**（`AnalysisFrameModel.timestamp`
   是推理时刻，不是视频时间戳，因此不能当真时间轴用）。
4. **图片素材仍会占用一条归档会话**（1 帧，内存可忽略）。
5. 网页端 `dashboard` 里另有 5 个**历史遗留** TS 报错文件（`ComparisonModal.vue`、`MediaLibrary.vue`、
   `DiagnosisReport.vue`、`HistoryPanel.vue`、`RecentReportsTable.vue`），`npm run build` 的
   `vue-tsc` 一步会因此失败。本轮未动它们（不在范围内），若要让 `npm run build` 通过需单独修一轮。

### 6.2 真机 / 模拟器清单（工程无签名，需先配签名）

1. 传**一张图片** → 徽标「图片」、**1 帧**、情绪曲线是**水平直线**、严重度是**刻度尺**；
2. 返回工作台，分别从「当前任务」和「最近使用的素材」再进入 → 同一张脸、同一热力图、仍是 1 帧；
3. 传**一段视频** → N 帧、可横滑、情绪曲线是折线、严重度是**帧级环形分布**（环心「N 帧」，
   四档计数之和 = N）；
4. 先分析 A 再分析 B，然后分别打开 A / B → **各自显示自己的人脸与热力图**（BUG-14 验证点）；
5. 打开本轮之前分析过的历史素材 → 报告分数 + 「本机未保留这次分析的逐帧数据」+
   「重新分析该素材」；点后页面**自动**开始出帧（不会跳走、不需要重新入栈）；
6. 分析完成后，档位标签与「智能解读」**自行出现**（不需要切页签，BUG-15 验证点）；
7. 断网 / 服务端没起 → 页面显示错误文案 + 可「重新分析」重试，不白屏。

## 七、给下一位接手者的三条提醒

1. **不要给"取不到数据"加"全局最新"兜底**。那正是 BUG-14 的全部原因；要兜底就兜"同一素材的更粗粒度数据"。
2. **图片就是 1 帧**。`resolveFrames()` 是唯一口径，服务端也只推 1 帧；不要再为了"图表好看"去凑点。
3. **异步数据不要走页面参数**（BUG-10/11/15 同根）。判据：这段数据在页面挂载之后还会变吗？会 → 走 `@Trace`。
