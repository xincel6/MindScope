# 参考报告：页签切换「组件错峰滑入 / 滑出」实现指南

> 适用：**HarmonyOS / ArkTS / ArkUI（API 12+，本报告在 API 23 实测通过）**
> 本文档是给「编写同类项目的 AI / 开发者」看的实现规范。照着做即可让**每一个 tab 页面**都具备
> 「组件一个一个滑出 → 换页 → 组件一个一个滑入」的错峰转场，并且**不依赖任何三方库**。
>
> 所有结论都来自真机实测（模拟器 1316×2832），文中标注的「实测」条目均附有可复现的现象描述。

---

## 0. 这份文档怎么用

| 你是 | 读哪几节 |
|---|---|
| 第一次实现 | 全套读，按 §6 的顺序执行 |
| 只想照抄代码 | §5 全文复制 → §6 接入 → §9 验收 |

| 验收别人的实现 | §9 + §10 清单 |

**硬性要求（不可裁剪）**：项目里**每一个** tab 页面都必须接入（§6.2）。
只做其中几个页面会出现"有的页面有转场、有的页面硬切"的割裂感，这比完全不做更糟。

---

## 1. 目标效果（这就是验收定义）

切换底部 tab 时：

1. **离场**：当前页的各个组件**逐个**滑出屏幕边缘并淡出；
   **前一个基本收尾，后一个才开始**（不是所有组件同时起步的"波浪式"）。
2. **换页**：所有组件都离场后，页面才真正切换。
3. **入场**：目标页的各个组件**逐个**从另一侧滑入并淡入，同样是前一个落位、后一个才动。
4. **方向**：往右侧的 tab 切换 → 组件向左离场、从右侧入场；反之相反。
5. **曲线**：入场带轻微过冲（阻尼/回弹感），离场「慢—快—慢」。

**反例（不算完成）**：
- 整页平移（页面内容作为一个整体滑动）→ ✗
- 所有卡片同时动、只是启动时间差几十毫秒（波浪式）→ ✗
- 只有入场有动画、离场是硬切 → ✗
- 只有部分 tab 页面有 → ✗

---

## 2. 一句话原理

**把转场动画收进「每个组件自己」的生命周期里，共享的只有一个"节拍器"（发信号 + 给参数）。**

```
窗口层（tab 容器）
   ├─ 点 tab → 设置方向 dir → exitClock++（发"开始离场"信号）
   ├─ 等 sequenceMs(旧页组件数) ← 让所有组件演完
   ├─ 真正换页
   └─ 再从 sequenceMs(新页组件数) 后解锁连点保护

每个组件（RevealCard 包装）
   ├─ onAppear                → 按 delay = order × stepMs 播自己的入场
   └─ @Monitor(exitClock)     → 按 delay = order × stepMs 播自己的离场
```

关键点：**动画的位移/透明度是组件自己的 `@Local` 状态**，窗口层不参与任何 UI 计算。
这样每个组件想改成缩放、改尺寸、换内容，都只改它自己，页面代码完全不动。

---

## 3. 三种常见但错误的做法（都实测失败，别再走）

### 3.1 用一个全局进度量 + 逐项重映射 —— 能做出"错峰"，但做不出"一个一个"

做法：窗口层持有 `prog: 0→1`，每张卡按 `local(i) = clamp((prog - i·s)/(1 - i·s))` 重映射。

- 现象：所有卡片**同时在动**，只是各自起点不同 → 视觉上是"波浪"，不是"一个一个"。
- 根本问题：位移是在**外面**贴到整张卡上的，组件的 UI 本身没有状态，无法个性化。

> 如果需求就是"波浪式错峰"，这个方案是成立的；但**不是本文档定义的目标效果**。

### 3.2 用 `TransitionEffect.animation({ delay })` 做错峰 —— 会被"回流"毁掉

`.transition(TransitionEffect.translate(...).combine(TransitionEffect.OPACITY).animation({ duration, delay }))`

- 现象：卡片退场时**立刻从布局里被摘掉**，兄弟组件马上往上补位（跳一格），
  与"卡片自己滑走"打架，观感很差。
- 结论：`TransitionEffect` 适合"列表项增删的补位动画"，不适合"整页组件依次离场"。

### 3.3 靠 Navigation 的路由切换动画 —— 旧页留不住

| 做法 | 实测现象 |
|---|---|
| `replacePathByName` + `customNavContentTransition` 自定义转场 | 旧页在替换那一帧就被销毁，画面只剩白底 + 新页滑入 |
| `pushPathByName` + `customNavContentTransition` | 一样，被覆盖的 NavDestination 不渲染 |
| `pushPathByName` + 系统默认转场 | 两页确实同时绘制，但**曲线和方向都改不了**，且要手动裁剪栈 |
| `pushPathByName(..., animated: false)` | 被覆盖的页面**立刻停止绘制**，只有白底 |

- 结论：**离场动画必须发生在换页之前**，不能指望路由切换帮你留住旧页。
  这正是 §2 里"先发信号 → 等演完 → 再换页"顺序的由来。

## 5. 完整代码（可直接复制）

### 5.1 `common/CardTransit.ets`

```ts
/**
 * CardTransit · 页签切换的共享节拍器（只发信号，不搬 UI）
 *
 * 每个组件在自己的生命周期里决定怎么动、什么时候动：
 *   · 入场：onAppear 里启动自己的 animateTo，延迟 = order × stepMs
 *   · 离场：监听 exitClock，信号一来各组件按自己的 order 延迟启动
 */

import { curves } from '@kit.ArkUI';

@ObservedV2                     // ★ 必须！漏了会报 10905343
export class CardTransit {
  private static shared: CardTransit | null = null;

  static get(): CardTransit {
    if (CardTransit.shared === null) {
      CardTransit.shared = new CardTransit();
    }
    return CardTransit.shared;
  }

  /**
   * 单个组件自己那段动画的时长（毫秒）
   * ★ 关键关系：总时长 = cardMs + stepMs × (组件数 - 1)
   *   所以「让单卡更从容」和「整体不变慢」能同时做到：拉长 cardMs + 让 stepMs 明显小于它。
   */
  static readonly cardMs: number = 240;

  /** 相邻组件启动间隔（毫秒）· stepMs / cardMs ≈ 0.46 ⇒ 有先后、无停顿（推荐 0.4~0.55） */
  static readonly stepMs: number = 110;

  /** 横向基准距离（vp）· 实际按序号拖尾放大，见 travelOf */
  static readonly travel: number = 96;

  /** 拖尾系数：序号每 +1 距离多这么多比例（0 = 等距，最容易显机械） */
  static readonly trail: number = 0.12;

  /** 离场缩放终值 / 入场缩放起始值（做纵深，只有 X 平移会显得很平） */
  static readonly scaleOut: number = 0.94;
  static readonly scaleIn: number = 0.96;

  /** 入场纵向上浮偏移（vp） */
  static readonly riseY: number = 12;

  /** 各页面参与转场的组件个数 · 必须与该页 RevealCard 的个数一致 */
  static readonly CARDS_WORKBENCH: number = 4;
  static readonly CARDS_STATS: number = 3;
  static readonly CARDS_PLACEHOLDER: number = 2;
  static readonly CARDS_PROFILE: number = 3;

  /** "开始离场"信号 · 每次切页签自增一次 */
  @Trace exitClock: number = 0;

  /** 方向：-1 = 向左离场（往右边的页签切），+1 = 向右离场 */
  @Trace dir: number = -1;

  /** 入场曲线：easeOutExpo，减速段长、落位稳（过冲在 200ms 级会被读成"抖一下"） */
  static curveIn(): ICurve {
    return curves.cubicBezierCurve(0.16, 1.0, 0.3, 1.0);
  }

  /** 离场曲线：ease-in（慢起、加速离开），与入场形成反向节奏 */
  static curveOut(): ICurve {
    return curves.cubicBezierCurve(0.45, 0.0, 0.8, 0.25);
  }

  /** 透明度曲线：平滑且不过冲（透明度过冲会被截断，看着像闪） */
  static curveFade(): ICurve {
    return curves.cubicBezierCurve(0.4, 0.0, 0.6, 1.0);
  }

  /** 某序号组件实际滑动距离（拖尾：越靠后甩得越远，形成流动感） */
  static travelOf(order: number): number {
    return CardTransit.travel * (1 + CardTransit.trail * order);
  }

  /** 一波转场需要等多久（从发信号到最后一个组件演完） */
  static sequenceMs(count: number): number {
    const n: number = count < 1 ? 1 : count;
    return CardTransit.cardMs + CardTransit.stepMs * (n - 1) + 40;
  }
}
```

### 5.2 `components/RevealCard.ets`

```ts
/**
 * RevealCard · 让每个组件自己按生命周期做「一个一个弹出 / 消失」
 *
 * 用法：
 *   RevealCard({ order: 0 }) {
 *     YourCard(...)
 *   }
 *
 * ★ 入场不能写在 aboutToAppear：它在首次 build 之前执行，节点没上树，动画没有可动的东西。
 * ★ 离场不能写在 aboutToDisAppear：那时节点已在销毁流程里，没有播放窗口。
 */

import { CardTransit } from '../common/CardTransit';

@ComponentV2
export struct RevealCard {
  /** 本组件在本页转场里的顺序（0 起，必须唯一且连续） */
  @Param order: number = 0;

  /**
   * ★ 必须用 @Local 持有单例：只有组件自己持有的被装饰引用上的 @Trace 字段才会被追踪。
   *   直接写 CardTransit.get().exitClock 在 @Monitor 里收不到信号。
   */
  @Local transit: CardTransit = CardTransit.get();

  /** 横向位移 · 起始在屏幕外侧 */
  @Local shift: number = 0;

  /** 纵向偏移 · 入场从略下方浮上来 */
  @Local shiftY: number = 0;

  /** 缩放 · 做纵深（入 0.96→1，离 1→0.94） */
  @Local scaleVal: number = 1;

  /** 不透明度 · 起始 0 */
  @Local alpha: number = 0;

  @BuilderParam content: () => void = this.emptyContent;

  @Builder
  emptyContent() {
    Row().width('100%').height(0)
  }

  /** 起始态（此时节点还没上树，不能在这里播动画） */
  aboutToAppear(): void {
    this.shift = -CardTransit.get().dir * CardTransit.travelOf(this.order);
    this.shiftY = CardTransit.riseY;
    this.scaleVal = CardTransit.scaleIn;
    this.alpha = 0;
  }

  /** 入场 · 两条时间轴并行：主运动 cardMs；透明度更短且略晚起步（"边滑边显"） */
  private playIn(): void {
    const delay: number = this.order * CardTransit.stepMs;

    this.getUIContext().animateTo({
      duration: CardTransit.cardMs,
      delay: delay,
      curve: CardTransit.curveIn()
    }, () => {
      this.shift = 0;
      this.shiftY = 0;
      this.scaleVal = 1;
    });

    this.getUIContext().animateTo({
      duration: CardTransit.cardMs * 0.7,
      delay: delay + CardTransit.cardMs * 0.15,
      curve: CardTransit.curveFade()
    }, () => {
      this.alpha = 1;
    });
  }

  /** 离场 · 同样两条时间轴；方向由页面给出的 dir 决定 */
  private playOut(): void {
    const delay: number = this.order * CardTransit.stepMs;
    const direction: number = this.transit.dir;

    this.getUIContext().animateTo({
      duration: CardTransit.cardMs,
      delay: delay,
      curve: CardTransit.curveOut()
    }, () => {
      this.shift = direction * CardTransit.travelOf(this.order);
      this.scaleVal = CardTransit.scaleOut;
    });

    this.getUIContext().animateTo({
      duration: CardTransit.cardMs * 0.75,
      delay: delay,
      curve: CardTransit.curveFade()
    }, () => {
      this.alpha = 0;
    });
  }

  /** 页面发来"开始离场"信号 */
  @Monitor('transit.exitClock')
  onExitSignal(): void {
    this.playOut();
  }

  build() {
    Column() {
      this.content()
    }
    .width('100%')
    .translate({ x: this.shift, y: this.shiftY })
    .scale({ x: this.scaleVal, y: this.scaleVal })
    .opacity(this.alpha)
    .onAppear(() => {
      this.playIn();
    })
  }
}
```

## 6. 接入步骤

### 6.1 主容器（窗口层）：改 `pushTab`

先用一个**同步执行**的初始入栈（首屏不需要转场），并把 `pushTab` 改成「发信号 → 等 → 换页」：

```ts
aboutToAppear(): void {
  this.attachActions();
  // ★ 首屏直接入栈，不走 pushTab（同页签会被判据挡掉，且首屏不需要转场）
  this.navStack.replacePathByName(
    MainTab.workbench as string, this.buildTabParam(MainTab.workbench)
  );
}

private pushTab(tab: MainTab): void {
  // 同一页签连点 / 上一轮还没播完 → 忽略
  if (tab === this.selectedTab || this.transitBusy) {
    return;
  }

  const fromIndex: number = mainTabIndexOf(this.selectedTab as string);
  const toIndex: number = mainTabIndexOf(tab as string);
  const transit: CardTransit = CardTransit.get();

  // 往右边的页签切（下标变大）→ 组件向左离场
  transit.dir = toIndex >= fromIndex ? -1 : 1;
  this.transitBusy = true;

  // ① 发"开始离场"信号
  transit.exitClock = transit.exitClock + 1;

  // ② 等最后一个组件演完再换页（切早了会砍断离场动画）
  const leavingWait: number = CardTransit.sequenceMs(this.cardCountOf(this.selectedTab));
  setTimeout(() => {
    this.selectedTab = tab;
    this.navStack.replacePathByName(tab as string, this.buildTabParam(tab));

    // ③ 新页组件在 onAppear 里依次入场，这里按同样节奏解锁连点保护
    setTimeout(() => {
      this.transitBusy = false;
      this.refreshUi();
    }, CardTransit.sequenceMs(this.cardCountOf(tab)));
  }, leavingWait);
}

/** 页签 → 组件数。★ 必须与页面里 RevealCard 的个数严格一致 */
private cardCountOf(tab: MainTab): number {
  if (tab === MainTab.workbench) {
    return CardTransit.CARDS_WORKBENCH;
  }
  if (tab === MainTab.stats) {
    return CardTransit.CARDS_STATS;
  }
  if (tab === MainTab.profile) {
    return CardTransit.CARDS_PROFILE;
  }
  return CardTransit.CARDS_PLACEHOLDER;
}
```

还需要一个「页签顺序下标」helper（方向判定用），必须与底部 tab 栏的展示顺序**同源**：

```ts
// pages/PageRoutes.ets
export function mainTabIndexOf(name: string): number {
  for (let i = 0; i < MAIN_TABS.length; i++) {
    if ((MAIN_TABS[i].tab as string) === name) {
      return i;
    }
  }
  return -1;
}
```

### 6.2 每个 tab 页面：把顶层块依次包进 `RevealCard`

**这是「所有 tab 页面都要有」的落地点。** 规则：

1. 页面内容顶层 `Column` / `Scroll` 里的**每个直接子块**，用 `RevealCard({ order: N })` 包住；
2. `order` 从 **0 开始、连续、不跳号**；
3. 数量与 `cardCountOf(tab)` 一致；
4. 条件块（`if (...) { ... }`）**不要**包（它出现/消失不可预测，会打乱节拍）。

```ts
// 例：工作台（4 个组件）
Column({ space: UiTheme.gapL }) {
  RevealCard({ order: 0 }) {                 // 页头
    Column() {
      this.pageHeader()
    }
    .width('100%')
    .alignItems(HorizontalAlign.Start)
  }

  if (this.showOfflineBanner) {              // ★ 条件块不包，保持节拍稳定
    this.offlineBanner()
  }

  RevealCard({ order: 1 }) {                 // 当前任务
    CurrentTaskCard({ task: this.currentTask, onOpen: () => { this.onOpenTask(); } })
  }

  RevealCard({ order: 2 }) {                 // 开始新的辅助评估
    StartAssessmentCard({ onPick: () => { this.onSelectMedia(); } })
  }

  RevealCard({ order: 3 }) {                 // 最近使用的素材
    RecentMediaSection({ items: this.recentItems /* ... */ })
  }
}
```

`CardTransit` 里登记 **4**；`cardCountOf(workbench)` 也返回 4 ✓。

**各页面的实际做法参考**（本项目）：

| 页面 | 组件数 | 包了哪些 |
|---|---|---|
| 工作台 | 4 | 页头、当前任务、开始新的辅助评估、最近使用的素材 |
| 统计 | 3 | 页头、严重等级分布卡、BDI 趋势卡（**4 张 KPI 卡不参与**，见 §8-坑 6） |
| 素材库 | 2 | 页头、占位内容块 |
| 历史报告 | **3** | 页头、筛选栏、列表区整块（列表里的每张卡只错峰入场、不计入离场，见 6.3 的 2026-10-18 注） |
| 我的 | 3 | 页头、账号信息卡、退出登录块 |

### 6.3 组件计数登记（最容易错的一步）

`cardCountOf()` 算小了 → 最后一个组件的离场动画被换页砍断（表现为"闪一下"或"没动就走了"）。
**改页面结构后必须同步两处**：`CardTransit.CARDS_*` 与页面里 `RevealCard` 的实际个数。

自检命令（数量必须一一对上）：

```bash
grep -c "RevealCard({ order:" harmony/entry/src/main/ets/pages/WorkbenchPage.ets   # 应为 4
grep -c "RevealCard({ order:" harmony/entry/src/main/ets/pages/StatsPage.ets        # 应为 3
grep -c "RevealCard({ order:" harmony/entry/src/main/ets/pages/ProfilePage.ets      # 应为 3
grep -c "RevealCard({ order:" harmony/entry/src/main/ets/pages/MediaLibraryPage.ets # 应为 2
# ReportsPage 自 2026-10-18 起含「列表卡片」层，不能再按总数自检，见下方注
```

**本项目的实测结果**（可与你的实现对照）：

```
WorkbenchPage        4     ← CARDS_WORKBENCH = 4  ✓
StatsPage            3     ← CARDS_STATS     = 3  ✓
ProfilePage          3     ← CARDS_PROFILE   = 3  ✓
MediaLibraryPage     2     ← CARDS_PLACEHOLDER = 2 ✓
ReportsPage          2     ← CARDS_PLACEHOLDER = 2 ✓（2026-10-18 前）
```

> 素材库与历史报告曾经共用 `CARDS_PLACEHOLDER`，因为两者结构相同（都是页头 + 占位块）。
> 一旦它们的结构不再相同，就必须拆成两个独立常量，否则短的那个页面会白等。

#### 2026-10-18 更新：列表卡片接入后的计数规则（重要）

历史报告页已接入「每张报告卡错峰入场」（`docs/本轮交付说明-历史报告卡片错峰入场.md`），结构变为：

```
页头(order 0) + 筛选栏(order 1) + 列表区整块(order 2, _playEnter:false)
  └ 每张卡 RevealCard({ order: 2 + min(i, 5), _playExit:false })      ← 只播入场
```

因此：

1. **`CARDS_*` 的含义收窄为「参与离场的组件数」**，等于该页里跟随 `exitClock` 的 `RevealCard` 个数；
   列表卡片传 `_playExit:false`，**不计入**。`ReportsPage` 对应新常量 `CardTransit.CARDS_REPORTS = 3`，
   `CARDS_PLACEHOLDER = 2` 现在只服务素材库。
2. `grep -c "RevealCard({ order:"` 不再适用于列表页（会把列表卡片也算进去）。
   这类页面改按「顶层离场位」人工核对：`ReportsPage` = 3。
3. 列表项**不要**跟 `exitClock` 逐张离场：几十张卡的延迟会超过窗口层的 `sequenceMs()` 等待，
   换页时绝大多数卡还没动就被销毁。离场交给列表容器整块，卡片只负责入场错峰。

## 7. 参数与速度预设

改 `CardTransit` 里两个数即可（**两个要一起改**，只降 `cardMs` 会变成波浪式）：

| `cardMs` / `stepMs` | 重叠率 | 4 个组件的单相时长 | 手感 |
|---|---|---|---|
| 170 / 170 | 0%（严格串行） | 740ms | **一顿一顿**，显僵硬（不推荐） |
| 120 / 110 | 8% | 510ms | 快，但单卡仅 120ms，像"闪一下" |
| **240 / 110** | **54%** | **570ms** | **推荐默认：单卡从容 + 无停顿** |
| 260 / 70 | 73% | 470ms | 最顺滑最快，接近"波浪"，先后感变弱 |
| 300 / 300 | 0% | 1200ms | 很慢，适合演示逐个过程 |

**核心关系**（务必先懂再调）：

```
单相总时长 = cardMs + stepMs × (组件数 - 1)
重叠率     = 1 - stepMs / cardMs
```

于是「让每个组件的动作更从容（cardMs 大）」与「整体不拖沓（总时长小）」并不冲突 ——
**拉长 cardMs 的同时把 stepMs 压小**，就能既顺滑又不慢。这就是去僵硬的主杠杆。

其他可调项：

| 参数 | 含义 | 建议 |
|---|---|---|
| `travel` | 单个组件横向位移（vp） | 100–160；太大易露白边 |
| `curveIn()` | 入场曲线 | 保持轻微过冲 `y>1` 才有阻尼感 |
| `curveOut()` | 离场曲线 | 控制点接近对称即"慢快慢" |
| `sequenceMs()` 的 `+40` | 换页余量 | 别小于 20，否则可能切在动画尾巴上 |

## 7.5 「太僵硬」的六个成因与对应手法

> 这一节是实操中最常被反馈"滑得僵硬/像机器"的原因清单。按性价比排序，
> 前两条是主因，改完立刻见效。

| # | 成因 | 症状 | 手法 |
|---|---|---|---|
| 1 | **单卡时长太短** | <150ms 的位移，人眼读成"跳变/闪一下" | `cardMs` 提到 220~300 |
| 2 | **重叠太少** | 一张张"蹦"，节奏有停顿 | `stepMs / cardMs` 压到 **0.4~0.55** |
| 3 | **动作完全同质** | 每张卡速度/距离/方向/曲线全一样，像流水线 | 用 `travelOf(order)` 做**拖尾**：越靠后甩得越远 |
| 4 | **只有 X 轴平移** | 平面感，像贴纸被推走 | 加 `scale`（入 0.96→1、离 1→0.94）+ 入场 12vp 上浮 |
| 5 | **透明度与位移同起同落** | 缺层次，像整体被"抹掉" | 透明度**单独一条时间轴**，时长 ×0.7 且略晚起步 |
| 6 | **曲线过冲过大** | 短时长里显"抖/弹" | 入场用 easeOutExpo `(0.16, 1, 0.3, 1)`，离场用 ease-in |

**验证手法**：改完之后按 §9.1 连拍，应该能拍到这样的帧 ——
**前面的组件已实色落位，后面的组件还在半透明侧移且略小**。
如果每一帧都是"所有组件同一透明度、同一进度"，说明重叠和分层没生效。

**注意取舍**：重叠率提高会削弱"一个一个来"的仪式感。
`0.4~0.55` 是兼顾两者的区间；如果项目明确要求"极强的一步一步感"，就只能在
"僵硬"和"慢"之间选一个 —— 物理上无法既严格串行又丝滑。

## 8. 硬约束与踩坑清单（症状 → 原因 → 修法）

> 全部为真机实测，照抄最容易省事。

### 坑 1：动画"一帧跳到终态"，连拍 4 帧完全一样
- **原因**：动画量读的是静态单例字段（如 `CardTransit.get().prog`），ArkUI V2 **不会**把它登记成依赖，`animateTo` 里改了也没组件重绘。
- **修法**：组件必须 `@Local transit: CardTransit = CardTransit.get();`，通过 `this.transit` 读写。

### 坑 2：`@Trace` 编译报 `10905343`
- **报错**：`The '@Trace' can decorate only member 'variables' within a 'class' decorated with '@ObservedV2'.`
- **原因**：类上漏了 `@ObservedV2`。
- **修法**：`@ObservedV2` 必须直接写在 `export class Xxx {` 上方。

### 坑 3：改了 `duration` 但动画速度不变
- **原因**：`curves.interpolatingSpring(...)` / `springCurve(...)` 的真实时长由曲线自身收敛决定，`animateTo` 的 `duration` 对它们**无效**（实测 duration 500 → 2000，速度完全一样）。
- **修法**：要精确排时间表就用显式时长的 `curves.cubicBezierCurve(...)` 或 `Curve.EaseInOut`。

### 坑 4：入场动画不播 / 节点没动
- **原因**：动画写在 `aboutToAppear` 里。它在首次 build **之前**执行，节点还没上树。
- **修法**：起始态放字段初始化，动画放 `onAppear`。

### 坑 5：离场动画不播
- **原因**：动画写在 `aboutToDisAppear` 里。那时节点已在销毁流程中，没有播放窗口。
- **修法**：页面**提前**发信号（`exitClock++`），组件在 `@Monitor` 里播，播完页面再换页。

### 坑 6：给 `Row` 里 `layoutWeight(1)` 的卡片套包装组件后布局塌了
- **原因**：`RevealCard` 的根是 `Column().width('100%')`，会吃掉 `layoutWeight` 的均分语义。
- **修法**（任选）：
  - 该排卡片**不参与**逐组件转场（本项目统计页 4 张 KPI 卡即如此）；
  - 或给包装组件加一个 `@Param weight: number = 0`，根上加 `.layoutWeight(this.weight)`。

### 坑 7：自定义组件带尾随闭包时，属性写在闭包后面编译失败
- **报错**：`Declaration or statement expected` + `Cannot find name 'translate'`
- **原因**：`AppCard(...) { ... }` 这种形态，属性必须写在**调用处**、不能写在 `}` 之后；
  无尾随闭包的组件（`CurrentTaskCard({...})`）则可以正常接 `.translate()`。
- **修法**：统一用 `RevealCard({ order: N }) { AppCard(...) { ... } }` 包一层，不要在闭包后接属性。

### 坑 8：`build()` / `@Builder` 里声明局部变量报错
- **报错**：`Unexpected token`，有时伪装成 `10905210 单根节点` 错误。
- **修法**：把计算收进 `@Computed` getter，或在调用处用 `as` 收窄；builder 体里只写 UI。

### 坑 9：换页那一帧旧页内容直接消失
- **原因**：`replacePathByName` 的语义就是"销毁旧页"。`customNavContentTransition` 也留不住它；
  `pushPathByName(..., animated:false)` 时被覆盖的页面同样立刻停止绘制。
- **修法**：**先演完离场，再换页**（§6.1 的 ①②③ 顺序）。

### 坑 10：快速连点页签导致动画叠在一起 / 卡死
- **修法**：`transitBusy` 布尔锁 + 「同页签直接 return」。释放时机放在**入场那一段之后**，不要放在换页之后。

### 坑 11：用 `uitest uiInput click` 抓不到动画中间帧
- **原因**：该命令会等到 UI 空闲才返回；而本方案用 `setTimeout` 串起整段转场，
  click 会一直阻塞到动画全部结束，之后连拍只能拍到终态。
- **修法**：把点击放到后台，再并发连拍：

```bash
hdc shell "uitest uiInput click 395 2603 > /dev/null 2>&1 &"
for i in 1 2 3 4 5 6; do hdc shell "snapshot_display -f /data/local/tmp/f$i.jpeg"; done
hdc file recv /data/local/tmp/f4.jpeg f4.jpeg
```

## 9. 验收标准与验证方法

### 9.1 逐帧验收（最硬的证据）

用 §8-坑 11 的方法连拍 6 帧，按内容量（或肉眼）应看到：

| 帧 | 期望 |
|---|---|
| 1 | 旧页完整 |
| 2–3 | 旧页组件**逐个**消失，画面逐渐变空（不是"一下子全没"） |
| 4 | 新页**只有第 0 个组件**在淡入并侧移，后续组件**完全不存在** |
| 5 | 新页前 2–3 个组件落位，最后一个仍未出现 |
| 6 | 新页完整 |

**关键判据**：帧 4 / 帧 5 里必须存在"部分组件已落位、部分组件完全不渲染"的画面。
只要有这一帧，"一个一个来"就成立；如果每帧都是"所有组件同时处于不同透明度"，那是波浪式，不合格。

### 9.2 手动验收清单

- [ ] 每个 tab 页面都有转场（逐个点过去）
- [ ] 往右切与往左切，位移方向相反
- [ ] 入场有轻微回弹，离场是减速
- [ ] 快速连点 5 次不会卡死、不会叠动画
- [ ] 从二级页返回后 tab 正常，再切 tab 动画仍正常
- [ ] 应用冷启动时首屏也会依次入场（首屏不换页，但组件挂载即播）
- [ ] 离线态（出现条件块）时转场节拍不被打乱

## 12. 跨框架映射（同一原理，换 API）

| 概念 | ArkUI（本报告） | Vue 3 | React | Flutter |
|---|---|---|---|---|
| 单组件独立排期 | `animateTo({ delay })` | `transition: ... var(--delay)` 或 GSAP `stagger` | Framer Motion `transition.delay = i * step` | `AnimationController` + `Interval(begin, end)` |
| 入场钩子 | `onAppear` | `onMounted` / `@enter` | `useEffect` | `initState` |
| 离场触发 | `@Monitor` + `exitClock` | 父组件 emit / provide 的阶段 `ref` | 父组件 phase state | 父页面 `AnimationController` 反向前 |
| 曲线 | `curves.cubicBezierCurve` | `cubic-bezier()` | `cubicBezier()` | `CurvedAnimation` |
| 顺序切换页面 | 先演完再 `replacePathByName` | 先播离场再 `router.push` | 先播离场再导航 | 先播离场再 `Navigator.push` |

**唯一不能变的两条**：
1. 动画状态属于组件自己，不放在页面外面统一算；
2. 离场动画必须在页面真正切换/卸载**之前**播完。
